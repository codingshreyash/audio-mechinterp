# Prospective Voxtral audio-to-language Jacobian lens

**Design for independent review, 18 November 2026. No result and not an executable freeze.** This document was written while the separate, frozen Voxtral development state-patch run was in progress. It uses no outcome from that run. No model weights or new audio answers were loaded for this design. A runner, independent auditor, exact source hashes, and a resource pilot must be reviewed and frozen before the first model answer on the fresh v2 corpus.

## Question, evidence, and prior art

Can a map fitted on other spoken words read the model's natural next-answer preference from an audio state, and predict how a precisely specified audio-state edit changes the language-model state on new words? The map must operate from an unpatched audio activation and frozen FIT parameters. A local derivative computed on the evaluated recipient is an oracle diagnostic, not a reusable lens.

The released [Anthropic Jacobian Lens](https://github.com/anthropics/jacobian-lens) averages source-to-final residual Jacobians for text models, then applies the final readout; its [paper](https://transformer-circuits.pub/2026/workspace/index.html) pairs readouts with interventions. [J++](https://github.com/safety-research/jpp_lens) already uses clustered expert Jacobians, learned signed weights, LRP backward rules, and vocabulary filtering. Its cluster assignments are made during fitting and its deployed lens is one fixed map. The existing [Audio Jacobian Lens](https://github.com/kennethli319/audio-jacobian-lens) includes Whisper readouts, an LFM language-stream slice, a Chatterbox speech-code pilot, and an explorer. A [Voxtral/Qwen/DeSTA causal-tracing study](https://arxiv.org/html/2603.13768) already traces audio-text fusion and a final-token bottleneck. Therefore an audio Jacobian, audio explorer, or Voxtral activation patch alone is not a novelty claim. The testable extension here is a **FIT-fitted, time-indexed audio-to-LM map** with word-disjoint readout and causal-edit prediction, measured at two distinct audio boundaries.

Local evidence sets the bar. The frozen Qwen rank-16 transport failed its one-shot development gate. On FIT, local Qwen derivatives predicted their own small edits far better than a shared map, but the basis captured only about 22% of measured terminal-change energy; a FIT-only Gaussian source router was effectively tied with the global map. These are diagnostics, not transferable Voxtral parameters. The independently audited Voxtral FIT state-patch assay restored the complete recipient answer in 16/16 and caused valid lexical loss in 15/16 at each of two audio sites. Its strict **restoration time-preference gate failed**; finite teacher-forced scores cannot relabel it. That assay uses constructed mel blanks and donor states, and no reusable Jacobian. The separate Voxtral development transfer run and its results are outside this design.

## Three boundaries, two distinct estimands

The **source sites** are fixed: (1) audio encoder block 31 post-block/pre-final-norm, nominal tensor `[1,1500,1280]`; (2) projector forward output, nominal `[375,3072]`. Fit them independently. Their effects are nested on one pathway and must not be summed. The **target** is the prompt-final position at LM block 29 post-block/pre-final-norm, width 3,072; apply the pinned LM final norm and head to read its first-answer-token distribution. Passively capture LM blocks 0, 14, and 29 at that position to describe the handoff through language layers, but do not choose a best target layer after seeing data. Confirm the tensor/tuple structure, hook invocation count, dtype, and exact token position against the pinned implementation before fitting. Audio-placeholder embedding values and projector output should agree at the handoff; that equality is a plumbing check, not an independent causal site. The 20-ms encoder and 80-ms projector row clocks are **nominal**: bidirectional attention can move information across them.

Construct six frozen half-open supports per clip and source site: a full-word support made of four equal-duration word quarters, plus a full-word-width pre and post interval. Keep nominal padding as a separate control. Use the same sample-to-mel-to-row rule as the reviewed Voxtral FIT mask builder, recomputed and hash-bound for every fresh v2 WAV. For recipient source state `H_i^s`, let `R_{i,s,b}` be the selected rows, and let `μ_{i,s,b}` be their mean vector. The paired donor supplies `δ_{i,s,b}=μ_{donor,s,b}−μ_{recipient,s,b}`. The **uniform edit** at scale `α` adds the same `αδ_b` to each recipient row in `R_b` and then casts to the frozen state dtype. A full rowwise donor replacement is a separate intervention and never an exact test of this uniform-edit derivative. Store the realized BF16 edit and norm, including zeroed edits.

For a FIT-only rank-32 orthonormal basis `U∈R^{3072×32}` and terminal state `z_i`, define

`J_{i,s,b}=∂(Uᵀz_i)/∂q_b`, where `q_b` is a vector added **uniformly to each row** in `R_{i,s,b}`. Thus one VJP's row gradients are **summed**, not averaged, over the support; the predicted edit is `Δẑ_i=U Σ_b J̄_{s,b} (αδ_{i,s,b})`. Compute the target coordinate in FP32 and accumulate saved row gradients in FP32, while recording that the underlying forward/backward model remains BF16; this is not an FP32-model Jacobian. This estimand must use the same rows, dtype conversion, and effective edit as the actual patched forward. No backward pass, local derivative, output logit, target state, expected word, donor label, category, voice label, or pair ID from an evaluated development/test item enters a fitted map. Donor activations define only the test edit and are disclosed as such.

Estimate `U` on the 16 basis pairs using their matched natural terminal-state differences for both voices and both FIT phrasings (64 difference vectors, one orientation per pair/voice/phrasing). SVD is CPU float64, with a fixed sign convention; require 32 finite nondegenerate singular directions (`σ_j/σ_1>1e−6`) or stop. Do not change rank after a failure. Record the fraction of each measured full terminal change captured by `U`; a low fraction limits any state-transport claim even if a first-token score is predicted.

The **paired-edit estimand** is measured `Uᵀ(z_patched−z_clean)` and the first-token class-contrast change. Score the two frozen initial-capital answer prefixes only if their first-token ID sets are nonempty and disjoint under the pinned Voxtral tokenizer; deduplicate alias IDs and stop if the rule fails a pair. The map's `z_clean+Δẑ` can predict a **first-token** contrast after final norm/head. It cannot predict later reply tokens, EOS, or complete-answer likelihood without an unrolled derivative. Save natural and patched complete generated suffix IDs independently.

The **source-only readout** is a separate, stronger test. With FIT-only anchor `z̄_s` and per-bin source means `μ̄_{s,b}`, form `ẑ_i=z̄_s+U Σ_b J̄_{s,b}(μ_{i,s,b}−μ̄_{s,b})` from the unpatched audio state alone. Compare its first-token class contrast/rank with the model's own natural next-token distribution and valid complete answer. Anchors and any calibration are fitted inside each pair-excluded FIT fold, then frozen for development. A successful paired-edit predictor without a successful source-only readout is **local transport**, not an Anthropic-style readout lens.

## Feasibility before fitting

The prior BF16 Voxtral generation assay peaked near 10 GiB MPS driver allocation. It says nothing about backward memory. First run a FIT-only resource pilot after corpus intelligibility review: capture the 64 basis-difference states and verify rank, then compute 32 projected-target VJPs for one preselected map context with both source hooks on one graph. Check a four-coordinate finite-difference subset independently and compare one shared backward to separate-site backwards. Measure loaded/forward/backward MPS peaks, seconds per VJP, graph retention, and zero/padded edit drift. The numerical edit grid is **α ∈ {0.025, 0.05, 0.1}** for the primary local test; α=0 and α=1 are controls/stress checks, not members of the small-edit fit. Fail the pilot if a gradient is disconnected/nonfinite, terminal/source shapes or passive suffix IDs differ, effective BF16 edit is zero or unfaithful to the intended edit, or MPS driver allocation reaches 30 GiB. Do not tune α using a development result.

Under one shared graph, 80 map contexts × 32 target cotangents means **2,560 VJPs**; two site-specific graphs mean **5,120**. Six bins come from each VJP's already selected row gradients, not six backward passes. In float32, the two site's six-bin derivative arrays together use about **3.2 MiB per context**, about **256 MiB for 80** before metadata; do not save full rowwise gradients by default. These are arithmetic estimates, not a measured runtime or memory peak. Before a full fit, multiply the measured pilot times by the exact planned captures, forwards, VJPs, patched forwards, and generations, including load/preprocessing/checkpoint overhead. Require a **six-hour cumulative local model-work cap** across all attempts, 30 GiB MPS driver cap, immutable attempt and elapsed-time receipts, and fail-closed resume after an unreceipted interruption. If local backward is too large/slow, stop the local protocol and prospectively port the *same frozen population and method* to an available cloud GPU with a new independently reviewed environment receipt; do not omit a site, bin, or context after viewing outputs.

## FIT comparisons, development gate, and claims

The prespecified **primary candidate** is the pair-balanced average of the 80 FIT local Jacobians, separately at each site. The Qwen FIT Gaussian router's failure gives no basis to elevate a new router to primary. Compare on the same rank-32 basis and fit contexts against zero change, fit-only source/target mean, equal-rank ridge trained on the same edited pairs, a six-bin-shuffled derivative map, and a **J++-inspired** fixed expert average with FIT-only clusters and signed weights. Record parameter and forward-work counts. A Gaussian source-conditioned map is exploratory, with no route to replacing the primary after viewing results. The J++ comparator is an adaptation unless its LRP graph, readout filter, and signed-weight objective are ported exactly; do not label a plain-gradient cluster average an exact J++ reproduction. The local recipient derivative is reported only on FIT as an in-sample ceiling.

For 20 pair-excluded FIT folds, hold out **both voices and both directions of the whole pair** from derivative fitting, source/target centering, ridge/expert fitting, all hyperparameter choices, and numerical calibration. The independent 16-pair basis may stay fixed. On the first FIT phrasing there are 80 contexts × three primary α values = **240 all-planned small-edit measurements per site**. Freeze ridge/expert hyperparameter grids, tie rules, first-token alias sets, and all score arithmetic in executable code before the FIT model run. Report projected-terminal L2, full-terminal L2, captured-energy fraction, predicted-versus-measured first-token score movement, sign above a FIT zero-repeat floor, and source-only readout rank/contrast. Use 10,000 pair-level bootstrap resamples seeded from the binding hash. Keep every wrong, malformed, zero-edit, or missing case in its planned denominator; an invalid primary cell fails the gate rather than shrinking it.

**Proposed advancement rule, subject to independent pre-run review:** at **both sites**, the fixed Jacobian map's projected-terminal L2 MAE and first-token contrast MAE are each ≤0.85 of both zero-change and equal-rank ridge over all 240 measurements, with pair-bootstrap 95% upper bounds below 1.00 for each ratio. At least 192/240 measured contrast changes must exceed the frozen numerical floor and ≥75% of those must have the correct predicted sign. The source-only readout must identify the model's preferred candidate on ≥60/80 FIT contexts and exceed the FIT-only mean-anchor and ridge readouts by at least 8/80 each. Natural answer validity is reported separately; require ≥60/80 clean one-word+EOS answers before interpreting a semantic word readout. If only the paired estimand passes, report the local transport finding but **do not** call it a source-only lens or open the source-only locked test under this rule. These thresholds are design choices, not achieved results.

If FIT passes, freeze the map, centering, aliases, code, and complete population before one development run. Development has **96 directions × three α values = 288 planned small-edit measurements per site** with no new VJP. Apply the same error ratios, bootstrap upper bounds, sign rule (at least 231/288 above floor), and source-only readout rule scaled to ≥72/96 preferred-candidate matches and ≥10/96 improvement over each source-only comparator; require ≥72/96 valid natural complete answers. A one-site result is a partial result, not a two-site pass. Open the fresh locked test only if both sites pass every prespecified development criterion after an independent audit. Repeat the identical analysis on locked test once with no tuning. A favorable projected score with low full-state capture is a **task-score predictor**, not a full-state lens.

Preserve a separate **complete-answer causal endpoint**: at each site/direction, record the actual generated suffix for clean, passive hook, self patch, uniform whole-word α=1, rowwise clean-donor replacement, and equal-effective-BF16-norm pre, post, padding, and random controls. Score each condition's complete answer and EOS with the strict existing answer classifier. Require exact clean/passive/self token parity. Whole-word donor or uniform-edit answer flips are observations from *actual* model interventions, never predictions inferred from `Δẑ`. Pre/post/padding are comparative controls because attention can move word information off the nominal word rows. Keep the FIT assay's failed restoration time-preference gate visible; a new time-selective label requires a separately frozen valid-complete-answer paired-control gate, not finite scores alone. A later spoken-versus-typed authorization test needs its own policy, attacker-controlled waveform, and consequential action endpoint before a security claim.

## Outcome decision tree

1. **Incomplete corpus intelligibility, broken hooks, failed rank, gradient/local-linear mismatch, or resource cap:** stop before a corpus fit; publish feasibility and exact failed checks.
2. **FIT pair-excluded gate fails:** publish the negative map/readout result; no development or locked-test efficacy inference.
3. **FIT passes, development fails:** publish all 96 development directions and the negative transfer result; locked test stays sealed.
4. **Development passes:** freeze an independently reviewed locked-test runner and auditor, then run once. Passing supports the specified *Voxtral audio-to-LM task readout and small-edit transport*, bounded by the corpus and rank. It does not explain generated speech, tool calls, accents, noise, or an attacker-reachable security violation.

This document is a design. It does not change the frozen Voxtral development patch protocol, its failed FIT restoration time gate, or the Qwen v1 negative result.
