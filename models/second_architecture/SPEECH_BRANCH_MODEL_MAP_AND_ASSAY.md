# Generated speech and action branches: source map and next assay

**Status (18 November 2026):** source review only. This memo adds the generated-speech branch to the existing [second-architecture feasibility review](FEASIBILITY.md). It reports no model output and no new security finding. The local Voxtral development run was left untouched.

## Choice

Use the already pinned **Qwen2.5-Omni-3B** as the first *generated-speech branch* instrument, then use **NVIDIA NemotronLabs VoiceChat-11B** for the more direct spoken-answer versus native tool-script question if CUDA resources and checkpoint terms permit. Qwen is the smaller, more explicit Thinker→Talker→codec path; VoiceChat has the action channel Qwen lacks. Neither substitutes for the planned LFM3 cross-architecture replication, which remains gated on the [LFM license review](FEASIBILITY.md#candidate-and-exact-source-pins).

## Exact Qwen boundary to instrument

The locally installed `transformers==5.20.2` implementation at `models/second_architecture/.venv/lib/python3.12/site-packages/transformers/models/qwen2_5_omni/modeling_qwen2_5_omni.py` (SHA-256 `2f33a2b2536b8ab584b6475ffbd37d2108001c6b1ed1ca2c23fba39a2966fa7d`) shows the full generator requesting Thinker hidden states, building `thinker_reply_part`, passing it to `talker.generate`, extracting `talker_generate_codes` from the returned codec sequence, and decoding those codes with `token2wav`. The public return is Thinker text IDs plus waveform; **codec IDs are an internal intermediate**, so capture them at this interface. `talker.forward` adds Thinker reply features to codec embeddings, applies `thinker_to_talker_proj`, runs the Talker decoder, then applies `codec_head`. Token2Wav includes a diffusion stage and vocoder; the implementation starts decoding from random noise, so fix seeds for waveform comparisons. [Upstream implementation](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen2_5_omni/modeling_qwen2_5_omni.py).

Before any intervention, pin the **exact installed source hash and package version**, log `named_modules()` paths and shapes, and require identical Thinker IDs, codec IDs, and waveform (within a documented numeric tolerance) with passive hooks versus no hooks. Do not infer Thinker/Talker alignment from one decoded sentence: log text-token indices, Talker input-text indices, codec-token indices, EOS and any chunk boundaries. Codec codes do not have one-to-one word alignment by assumption; use a measured audible interval and decode the full waveform.

## One bounded mechanistic assay

**Question:** Can the Talker path cause a spoken authorization decision to differ from the Thinker text decision while the Thinker output is held fixed?

1. Start with short, harmless English audio requests that ask for a one-word decision, `ALLOW` or `DENY`, and explicitly ask the assistant to say the same word. Use paired requests and at least two independently generated voices. Treat this as a *branch-fidelity* task, not as an attack benchmark. Keep prompt template, speaker, decoding settings, seeds, sample rates, and model revision fixed. Record original WAV hashes, Thinker text IDs, Talker codec IDs, and final WAV. Transcribe with an independent ASR and manually listen to every candidate mismatch.
2. From clean baseline examples with different decisions, swap only the **generated-response part** of `thinker_reply_part` entering the Talker, preserving Thinker output IDs and all prompt-side state. First run an identical-source sham; then a matched opposite-decision donor, an off-word donor span, and a norm-matched random direction. Patch one documented interface at a time (conditioning input, then an early and a late Talker layer). A code-level capture/patch wrapper must preserve unpatched generation exactly; otherwise the experiment is invalid.
3. The strict endpoint is a **complete decoded waveform** that an independent ASR and a human listener both classify as the opposite decision, while the logged Thinker generated IDs remain the original decision and the codec sequence/termination are valid. Report counts over all pairs, voices, and seeds, including no-change cases. A shifted codec logit, ASR-only flip, truncated utterance, or patch that silently changes Thinker IDs does not pass.

This would identify a causal interface for **white-box branch divergence**. It would **not** establish an attacker-reachable vulnerability: an internal activation swap is not an ordinary user-controlled waveform. The later security test must show that a permissible input-audio change induces a text/spoken decision mismatch in the *unmodified* model, and must separate a listening/transcription error from a model-output discrepancy. Qwen has no proven native action output, so do not describe this assay as a tool-call exploit.

For an eventual action-integrity endpoint, VoiceChat is the better next model: use an inert `list_calendar_events` / `cancel_calendar_events` tool schema and a prewritten response. In **pass 1**, log the input WAV, tool schema, text and function logits/IDs, `tokens_function_pred`, decoded raw call string, call position, and parser input/output/error. In **pass 2**, log the injected call and canned response, `tokens_function`, text and codec tokens, unspliced generated audio, and the saved WAV after the official script removes the tool-call interval. Compare text, function and speech from the same pass or label any cross-pass comparison. A possible security endpoint is an **unconfirmed `cancel_calendar_events` proposal** from the model's raw function stream while the audible response promises only to list, with a supplied date, available list tool, and no real calendar side effect. Confirm the model generated the call before attributing any mismatch to it; an offline proposed call is not an executed action. [Official offline helper](https://github.com/NVIDIA-NeMo/Speech/blob/nemotron-labs-voicechat/nemo/collections/speechlm2/inference/utils/offline_voicechat.py#L1177-L1493).

## Decision gates

- Finish the frozen Voxtral run and source/hash audit first; no concurrent model load was done for this memo.
- Review the Qwen `qwen-research` and NVIDIA OpenMDW terms for the intended organizational use. Keep LFM blocked until its separate license issue is resolved.
- Run a one-sample full-Qwen fit/identity smoke before building the patch assay; measure peak device and host memory. If the local full speech path fails, record the specific operator or memory failure and move the same pinned protocol to an available CUDA GPU.
- Treat VoiceChat as English-only until independently shown otherwise. Its released configuration **does enable a separate function head**, but text and function heads share the LLM backbone; trace raw head outputs and both offline passes before claiming that a spoken/tool discrepancy originated inside the model. [Independent source audit](VOICECHAT_SOURCE_REVIEW.md).
