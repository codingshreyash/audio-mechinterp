# Voxtral FP32: fresh-word answer-link check (V3 prospective)

**Question.** Does a **per-recipient local-oracle** audio-state Jacobian predict a change in a *complete generated answer* on new words and an independent synthetic voice? Each direction is computed from that test recipient and its matched donor; this does not test a FIT-fitted fixed map or transfer of one reusable lens. This is a small model-level corroboration, not an attacker-reachable input attack or a security finding. The separate corpus-v2 480-WAV study and corpus-v1 locked test remain sealed. ## One model boundary and predicted effect

Intervene only at the output of `model.model.multi_modal_projector`. Derive the Track B projector word rows from the frozen half-open PCM word slot using the same prospective center rule as FIT, `160*(8*r+3)` samples for row `r`. Reject an empty mask, any out-of-range or nominally padded row, or unequal recipient/donor projector shapes; **do not silently clip a bad row into range**. This center rule is only a fixed index heuristic: log-mel normalization and receptive fields can carry word information outside the nominal rows, so no time-localization claim follows. Require equal prompt and audio-token geometry within each matched pair. Do not assume the old 375-row geometry if Track B lengths differ; record and validate the actual shape before an edit. For recipient source state `H`, matched donor state `H_d`, and fixed word rows `R`, define `d = mean_R(H_d) - mean_R(H)`; add `alpha*d` to each row in `R`. Natural source states must be captured under the same prompt and FP32 path, hashed, and inspected for finite/nonzero `d` before any edit. Do not learn a direction from answer outcomes.

Before candidate inference, freeze the exact tokenizer IDs for **six complete reply aliases per word**, each with EOS: lowercase, initial-capital, and uppercase word, each with no prefix and with one leading ASCII space. Deduplicate identical token-ID sequences. A later free generation whose strict casefold class matches a word but whose exact suffix IDs are outside this alias set is **uncovered** for the score-to-answer link; it remains in the strict full-answer tally but cannot count as a predicted switch. Do not add aliases after outputs. Score each word class by `logsumexp` of the complete-sequence log probabilities of its frozen aliases (all include EOS), not just the initial-capital form. **Several words tokenize into multiple answer tokens**, and alias lengths differ: align each candidate's token and EOS rows to its own sequence length, mask padding out of the likelihood, and never score only the first token. For one class batch, let `Lmax` be the longest alias length **including EOS**. Feed exactly the prompt plus `Lmax−1` continuation-token positions (right-pad shorter aliases with attention mask zero), and request `logits_to_keep=Lmax`, **never zero**. In the pinned model, these are exactly the rows from prompt-last through the longest EOS position. For alias length `Li`, score only its own `Li` logits beginning at prompt-last, with its EOS at offset `Li−1`; assert exact input/output shape and row mapping, and exclude right padding from the likelihood. Batched aliases for one word class count as **one** score forward. On the predeclared first context (`pair_00`, Piper, banana recipient), compare each batched alias score against its standalone score within `1e-4` using at most 12 extra diagnostic forwards; stop the campaign on any failure. Define `S(alpha) = log alias-mass(donor | edit) - log alias-mass(recipient | edit)`.

On two differentiable clean score forwards, one batched alias set per word class, compute both source gradients and subtract them. The pinned Voxtral source flattens the projector output across the alias batch: assert `B` aliases, exactly `T` projector rows and matching ordered audio-placeholder count **per alias**, and a raw hook output of shape `[B*T,3072]`. Interpret that output as `[B,T,3072]` only for validation and edit construction; raw flat row `b*T+r` belongs to alias `b`, word row `r`. Require each candidate's **bitwise prepatch projector segment** to match the natural singleton state, and all segments, processor audio input hashes, prompt prefix IDs and row sets to match across the two word-class batches; candidate continuations alone may differ. Apply every edit to `b*T+r` for **every** alias `b`, then return the original flat `[B*T,3072]` shape and order. Sum source gradients over `B` so `grad_S` is the gradient for one **shared** source edit, then form `J = sum_{r in R} grad_S[r] dot d`. Any nonuniform segment, invalid flat-to-batch mapping, missing alias edit, or projector hook count other than one invalidates the context. Predict `S(+0.1)-S(0) ≈ +0.1 J` and `S(-0.1)-S(0) ≈ -0.1 J`. The prior four-coordinate random LM29 Jacobian establishes numerical feasibility only; it does **not** predict this answer margin. An alias-mass margin still does not characterize every possible free generation, as the earlier `deer`/`dear` case illustrates.

Run the following fixed complete-generation arms per context: unhooked clean, exact-zero hook, `+0.1 d`, `-0.1 d`, `+0.1 u`, `+1.0 d`, and whole-projector donor-state replacement. The seed-derived `u` is one random width-matched vector per context, drawn before inference, orthogonalized against `d`, scaled to `||d||₂`, and applied to the **same word rows**. It is an equal-norm specificity control, not a null guaranteed to preserve output. Whole-state donor replacement must reproduce the natural donor's entire generated suffix exactly; each donor's natural output is already captured as the opposite direction's clean arm. `+1.0` is a nonlinear stress arm and cannot be credited to the local derivative. Run no adaptive alpha or reroll after outputs. Measure `S` for clean, zero, ±0.1, random +0.1 and +1.0 with the same hooks under no-grad deployment; use each context's own baseline. Six score conditions × two batched word-class forwards × 16 contexts = **192 no-grad score forwards**. The two clean differentiable class scores × 16 contexts add **32 grad forwards/backwards**. The clean differentiable score and no-grad zero score must agree within `1e-4` margin units or that context is invalid for Jacobian comparison. A clean and exact-zero hook must also produce **identical complete suffix token IDs**, not just the same class. Use only ordinary single-prefill `generate(use_cache=True,max_new_tokens=32)` and teacher-forced `model(...,use_cache=False,logits_to_keep=Lmax)` as defined above; prohibit chunked prefill, supplied `past_key_values`, supplied `inputs_embeds`, or an assistant/draft decoder. Assert exactly one projector call for each generation and each score forward; any different call count is invalid.

For every edited arm, compute the **realized FP32 source difference** `D = H_post[R] - H_pre[R]` from the exact tensors consumed by the model, save its SHA-256 and L2 norm, and compare it with the requested broadcast `alpha*d`. Require finite nonzero requested and realized norms (except exact zero); require relative realized-edit error at most 5% for a local prediction, or label that comparison invalid. Save the exact FP32 norm and requested-versus-realized ratio, never infer realized strength from alpha alone. The primary local prediction remains the prespecified `alpha*J`; also report the diagnostic contraction `sum grad_S*D` to reveal FP32 realization error. No row outside `R` may differ in the ±0.1/random arms.

## Endpoints, controls and decision

The **primary endpoint** is the complete, freely generated suffix: exact token IDs, decoded text, and terminal EOS. Classify it with the frozen strict FIT classifier as `recipient`, `opposite`, `other`, `missing_eos`, `malformed_special`, or `malformed_surface`. Also record whether the exact suffix IDs fall in the frozen scored alias set. A raw donor switch requires clean and zero both `recipient`, the edited suffix `opposite`, and terminal EOS; all other outcomes remain in the denominator. A predicted donor switch has the stricter gate below. Record full donor baseline and whole-state replacement exact-ID parity, zero-hook **bitwise source and complete-token-ID** parity, hook count, source shape and hashes, realized edit norm, all token log probabilities, runtime, and MPS peak. Any zero or full-donor parity failure holds that context for causal interpretation and is reported, not dropped. One prompt hook is expected per generation; extra or missing calls are invalid.

Report **all 16 contexts**, grouped by word pair and voice. For every context report `S(0)`, `J`, predicted and measured signed ±0.1 margin changes, random-control change, complete-answer class and alias coverage in every arm, and the +1 stress outcome. A local score prediction passes that context only if `|0.1 J| ≥ 0.02`, both signed measured deltas have predicted signs, and each error is at most `max(0.05, 0.25*|0.1 J|)` log-probability units; a smaller prediction is **unresolved**. A **predicted complete-answer switch** at signed local alpha requires all of: clean and zero are strict valid recipient answers whose exact suffixes are in the recipient alias set; `S(0)<0`; `S(0)+alpha*J>0`; the measured `S(alpha)>0`; and that same free generation is a strict donor answer with EOS whose exact suffix is in the donor alias set. Accuracy of `ΔS` plus an observed flip **without the predicted zero crossing** does not count. Report each failed clause separately. If a predicted alias-mass crossing occurs but the generated answer does not switch, that falsifies the sufficiency of this margin for generation in that context; a raw switch without a predicted crossing does not validate this Jacobian explanation. If no local alpha predicts a zero crossing, the answer-link outcome is **inconclusive**, even if score transport is accurate. A +1-only switch is nonlinear evidence. Compare donor-direction and random-direction answer effects over the complete planned 16; a comparable random effect defeats direction-specific interpretation.

**Advance only to a separately specified wider study** if at least 12/16 valid contexts (including at least one pair in each lexical category and both voices) pass the local score criterion, at least four valid contexts across at least two pairs satisfy **every predicted-switch clause above** at `|alpha|≤0.1`, and raw donor switches outnumber random-control switches by at least four contexts. These are engineering gates, not significance tests; the two directions of a pair are correlated. If the score gate fails, inspect the score graph and hook parity; if it passes without enough predicted boundary crossings, report a score-level result and an inconclusive answer link. No result here licenses a held-out or security claim.

## Implementation path and cap

No model inference or implementation occurs under this document. Adapt the FP32 differentiable leaf and exact-zero assertions in `voxtral_fp32_nonbeaver_linearity_runner_v1.py`, the complete-generation hook/classifier in `voxtral_fit_v2_causal_first_record.py`, and EOS-inclusive scoring in `voxtral_fit_pilot_capability_v1.py`. The current FP32 `trace_forward` is **not** a generation hook; the BF16 generation hook requires an FP32 adaptation and parity test. The existing `score_sequence` runs under `inference_mode` and converts scores to Python floats, so it **cannot** provide the required gradients; its EOS indexing may be reused only in a new differentiable scorer. Freeze and independently review source, masks, prompt/processor hashes, alias token IDs, random seeds, expected arm and call counts, QA receipt and a no-weight resource preflight before inference. No inference authorization is inferred from the technical WAV fixture or QA source review alone.

Maximum Track B **core** workload: 16 contexts × 7 generation arms = **112 complete generations/projector calls**; six fixed score conditions × two word-class batches × 16 contexts = **192 no-grad score forwards/projector calls**; two clean word-class batches × 16 contexts = **32 grad score forwards/backwards/projector calls**, or **336 core projector calls** total. Add at most 12 first-context alias batching diagnostics, at most 16 unique natural source captures (one per selected WAV; 32 logical recipient/donor references), and at most two old-FIT plumbing generations. The reversed directions reuse clean generations as donor baselines, not extra donor generations. Every alias batch size and realized number of candidate sequences must be recorded separately from forward-call count. MPS backward memory with alias batches is unmeasured: the no-weight preflight must bound the batch and fail closed if it cannot fit under 30 GiB; the live worker must sample MPS driver allocation before and after each backward and stop on the cap. No adaptive retries. Stop a context after 240 seconds of model work or 30 GiB MPS driver allocation; stop the campaign after 3,840 seconds of model work, 2 GiB new output, or below 12 GiB free disk. Preserve partial records with failure reasons and count missing contexts as incomplete, not negative or successful.

Each local launch requires AC power, open lid, and a ten-minute `pmset -g log` interval free of Sleep, DarkWake, or thermal transitions; archive the bounded raw log and hash it. Record UTC and monotonic start/finish pairs and require their elapsed-time disagreement to be at most **5 seconds** after the run. Also record power/lid state and system-transition log over the run; a transition, disconnection, closed lid, or >5-second clock gap marks the attempt environmentally invalid. Stop safely on a detected transition, preserve the partial attempt, and **do not retry or replace it under V2**. These admission rules address the prior FP32 host-interruption evidence; they do not improve the model-level evidence by themselves.
