# Voxtral old-FIT numerical follow-up: BF16 load amendment v2

**Prospective correction, 18 November 2026.** This amendment changes only the parameter dtype acceptance check and its receipts in the [v1 numerical protocol](VOXTRAL_V1_FIT_BACKWARD_NUMERICAL_FOLLOWUP_PROTOCOL_V1.md). The v1 signed alpha grid, old-FIT case, source states, model revision, hook sites, four target coordinates, controls, analysis, caps, and claim limits remain fixed. It does not authorize a retry from the original frozen launcher. A separate v2 source review and external freeze are required before any new BF16 attempt.

The first frozen BF16 attempt, preserved at `runs/voxtral_v1_fit_backward_numerical_launch_v1/bf16/20261118T120738563890Z/`, failed **before generation or intervention**. Its strict assertion required every parameter to be BF16. A separate bounded load found that the pinned Transformers implementation intentionally leaves exactly `model.audio_tower.embed_positions.weight` as FP32 on MPS, while the other 761 named parameters are BF16 on MPS. See [diagnosis](VOXTRAL_NUMERICAL_BF16_LOAD_FAILURE_DIAGNOSIS.md). This failed attempt is not a numerical measurement and is not overwritten.

The v2 runner must load the checkpoint with the same `dtype=torch.bfloat16`, `low_cpu_mem_usage=True`, `device_map="mps"`, and SDPA arguments. It must not cast or fine-tune a parameter after loading. For the BF16 arm, require **exactly one** exception by full name: `model.audio_tower.embed_positions.weight` must be FP32 on MPS, and every other named parameter must be BF16 on MPS. For the FP32 arm, require every named parameter FP32 on MPS and no exception. Reject any parameter on another device, any additional FP32 parameter in BF16, any BF16 parameter in FP32, or missing expected positional embedding. Save parameter name/dtype/device/shape counts and the exception name in the attempt metadata and result receipt. The ordinary hook source/target states and VJPs must still satisfy the v1 arm dtype rules.

The amended runner must bind the installed `transformers/modeling_utils.py` SHA-256 `553412f58334f65abba617f3b344828698dbf63615e109159fd03dafd3422d38` before model loading, in addition to the v1 source and old-FIT pins. It must hash this amendment in the start and metadata receipts. Use a new exclusive v2 output directory and separate review, auditor, and launcher binding. The already launched v1 FP32 arm remains on its original source and receipt; its result, if valid, is a separately frozen measurement. Do not silently substitute it into a v2 dual-arm receipt.

This is a source-level correction for the library's documented dtype policy. It does not change or rescue the old pilot's numerical prediction, does not make one sample generalize, and does not establish a security finding.
