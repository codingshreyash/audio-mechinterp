# Voxtral Track B V6 pilot worker: source-only handoff

**HOLD for any real weight load.** The [pilot source](voxtral_track_b_v6_pilot_worker_source_v1.py) has no CLI or checkpoint loader. Its public `run_pilot()` always rejects before it can invoke the supplied loader. This is a reviewable schedule/ledger slice, not a measured V6 resource result or an executable pilot GO. It follows the [V6 resource amendment](VOXTRAL_FP32_TRACK_B_ANSWER_LINK_PROSPECTIVE_V6_RESOURCE_PILOT_AMENDMENT.md) and [independent design GO](VOXTRAL_FP32_TRACK_B_ANSWER_LINK_PROSPECTIVE_V6_INDEPENDENT_REVIEW_GO.md). The actual 32/32 human QA receipt, frozen external pre-pilot admission, measured pilot, and post-pilot independent GO are not supplied by this source.

The private, fake-tested schedule makes exactly **two old-FIT natural clean/zero generations, two synthetic maximum-geometry clean/zero forced 32-token generations, 72 singleton no-grad scores and 12 singleton differentiable scores**. The first clean generation captures its projector state in the same call; there is no extra capture forward. Forced generations pass `min_new_tokens=max_new_tokens=32`, require 32 suffix tokens and exact clean/zero suffix/source hash parity. All scoring uses the frozen longest EOS-inclusive alias and the reviewed core's `B=1`, `logits_to_keep=Li` path. It stores only suffix/score/gradient hashes, finite/parity indicators, per-call elapsed times and observed post-call allocation; token IDs, decoded text, numeric score values and gradient tensors are not written. The timing projection computes V6's `1.2W≤240` and `1.2(P+16W)≤3840` using the two forced-generation, 72 score and 12 backward call maxima.

`calls.jsonl` is append-only and fsynced: every call has a **started** row before model invocation and a **completed** or **failed** row afterward. Thus an interrupted call remains an attempt. The admission contract binds a `campaign_attempt_id` and an absolute `campaign_claim_path` in a stable registry outside per-attempt output directories. The private schedule exclusively creates the claim before its output directory; a second attempt with a different output directory but the same bound claim path fails. The registry parent must already exist. A successful fake schedule writes an exclusive `pilot_measurement.json` with schema `voxtral_track_b_v6_pilot_measurement_v1`, planned/attempted/completed/missing counts, call-log SHA, bound QA/preflight/worker/study-runner fields, synthetic geometry and alias, host raw-log hashes, clock gap and V6 timing projection. A future study runner should require an independent post-pilot GO bound to the **exact SHA-256 of this measurement and call log**, then rehash all dependencies. The measurement's current success status is deliberately `schedule_complete_resource_unverified`, never `complete_feasible`.

## Blocking work before a real pilot

1. Create and independently review the external pre-pilot admission object and a **separate launcher**. The launcher, rather than this immutable worker, must pin the exact admission SHA-256 and worker SHA-256 and call `verify_admission(files, expected_admission_sha, expected_worker_sha)` before any later reviewed execution entry. This avoids a worker/admission hash cycle. The admission must bind the real audited **32/32 QA receipt and independent QA review**, a separately frozen no-weight preflight, V3–V6+V6-GO bytes, pilot/study/auditor source hashes, checkpoint and installed Transformers hashes, selected/synthetic processor hashes, longest alias, fresh host evidence, and the one campaign attempt identity and stable registry claim path. The existing preflight V1 is intentionally HOLD-only and cannot self-issue `pilot_go`. The launcher, claim registry and any private schedule invocation need separate source review; this source provides no live entry.
2. Replace the injected host-probe callback with a reviewed, source-hash-bound adapter that independently verifies AC, open lid, ten-minute clean raw `pmset` coverage and no transition during the run. The slice currently checks required booleans/raw-byte presence and hashes the raw log, but does **not** independently parse its timestamps or power events.
3. Add a process-level hard watchdog for model load and each forward, plus an actual **MPS driver high-water sampler** or equivalent peak measurement. The slice checks elapsed time and current driver allocation **after** each completed call, so it cannot bound a hung call or a transient allocation peak. Its receipt explicitly says `hard_per_call_watchdog_present=false` and `measured_mps_high_water_present=false`. These are source HOLDs even if fake tests pass.
4. Make the frozen admission path verify the loaded model's revision, every FP32 parameter, eval/no-autocast state, MPS device and generation settings before the first call; bind old-FIT and synthetic batch tensor hashes to the reviewed preflight and validate all input/placeholder geometry. A separate saved-data auditor must independently recompute the 88-call ledger and V6 projection. Only then may a later worker emit a claim-bearing measured receipt and request post-pilot review.

Verification: [`test_voxtral_track_b_v6_pilot_worker_source_v1.py`](test_voxtral_track_b_v6_pilot_worker_source_v1.py) ran five fake CPU tests. They cover external admission/worker SHA validation, public HOLD before loader, the full 88-call schedule and 176 started/completed ledger rows, forced 32-token parity, hash-only outputs, no retry across alternate output directories, host rejection before loader, and a failed model call retained as attempted. No real model, candidate WAV or GPU was used.
