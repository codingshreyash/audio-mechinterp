# Prospective FP32 non-beaver local-linearity pilot — V5 exact-zero identity amendment

18 November 2026. **Source-only amendment; no model run or executable freeze.** The independently reviewed [V2 protocol](VOXTRAL_FP32_NONBEAVER_LOCAL_LINEARITY_PROSPECTIVE_V2.md), [V3 output-budget amendment](VOXTRAL_FP32_NONBEAVER_LOCAL_LINEARITY_PROSPECTIVE_V3.md), and [V4 passive-recipient amendment](VOXTRAL_FP32_NONBEAVER_LOCAL_LINEARITY_PROSPECTIVE_V4.md) remain immutable. V5 specifies the exact alpha-zero hook operation. It requires independent conceptual GO, updated implementation/source review, regenerated CPU preflight and byte-budget receipts, and a new external freeze before any checkpoint weight load.

## Failure demonstrated before live model work

The V4 design makes each clean reference and its paired zeros use the same final signed donor-minus-recipient direction. That removes the avoidable clean-versus-zero disagreement from using different direction tensors. A second CPU-only counterexample shows that the draft arithmetic zero edit can still change a negative-zero source element: `-0.0 + (0.0 * positive_direction)` may return `+0.0`. The borrowed edit helper tests zero equality with `torch.equal`, which treats `-0.0` and `+0.0` as equal. The V2 required **bitwise** source pre/post and clean-to-zero parity would correctly reject this arithmetic identity. No live V4 result exists. This amendment fixes the zero operation prospectively rather than discarding failed cells after a model run.

## Exact alpha-zero hook

For every site-specific N0 and G1 clean reference **and every paired zero**, the source hook first creates the same detached FP32 source leaf as before, with `requires_grad=True` in G1 and `False` in N0. It keeps the final signed `δ_s` in the condition descriptor and hook configuration, but performs **no addition, multiplication, or conversion of source values** at alpha zero. The hook clones the leaf, clones the selected source rows bitwise, writes those cloned rows back to the same fixed positions through the ordinary site replacement operation, and returns the result. The returned source must be bitwise equal to the full prepatch source, including signed zeros. The alpha-zero effective edit is an explicitly allocated FP32 all-zero selected-row tensor. Its recorded effective norm, fidelity ratio, row nonuniformity ratio, and unchanged fraction are exactly `0, 0, 0, 1`, respectively. A G1 zero retains a differentiable path from the returned source to the source leaf; N0 retains no gradient path. Save and assert the actual grad flags and full pre/post raw-byte parity.

This branch is identical for a site's clean reference and all its paired zeros in the same mode: same final signed direction in configuration, row list, detached leaf construction, clone-and-replace operation, hook registration order, batch, grad context, and logits settings. At nonzero signed alpha, keep the previously specified FP32 `source + alpha*δ_s` edit arithmetic and save its realized FP32 difference and fidelity metrics. Do not modify the frozen borrowed edit helper; the runner handles alpha zero as a separate identity case and calls that helper only for nonzero edits. The fixed four-probe VJP remains the derivative of the G1 alpha-zero hook graph, and every G1 edited forward remains grad-enabled with a differentiable source leaf. The CPU fake-model test must include negative-zero source elements and demonstrate exact alpha-zero pre/post byte identity, clean-to-paired-zero bitwise parity, and a connected nonzero G1 VJP. The saved-data auditor independently checks these same zero identities and marks any failure invalid without substitution.
