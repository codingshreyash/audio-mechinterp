## Resource-resume issue found in earlier drafts

The first draft initialized resume time from the last completed checkpoint only, omitting failed-attempt work. A later revision accounted for exception receipts but could still miss a hard kill during model load, before an attempt file existed. The final runner writes cumulative elapsed debt in immutable error receipts, carries the largest validated checkpoint/error budget forward, requires every partial attempt to have a receipt, and fails closed on an invocation memory log with no error or completed-checkpoint stamp. It checks the cumulative 45-minute bound before resuming or CPU-only finalization. An uninterruptible model call and the narrow interval after a checkpoint remain operation-boundary limits, not a hard real-time timer.
