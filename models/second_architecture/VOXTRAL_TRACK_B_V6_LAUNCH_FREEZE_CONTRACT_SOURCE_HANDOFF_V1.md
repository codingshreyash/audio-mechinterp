# V6 pilot launcher freeze: source-only handoff

**HOLD for model load.** The [launch freeze contract](voxtral_track_b_v6_launch_freeze_contract_source_v1.py) does not issue an admission or run a pilot. Its public `launch_v6_pilot()` always rejects. It specifies the acyclic order: immutable worker **W**; external pre-pilot admission **A** binding W and all reviewed inputs/sources; independent review **R** binding A; then a later, independently reviewed launcher **L** pinning exact W/A/R and composition bytes. No A, R or executable L exists in this source.

`verify_launch_freeze` checks the currently reviewed W, bound audio batch adapter, pinned FP32 loader and MPS runtime source SHA-256 values against their actual files and A. It additionally requires a future L pin for the exact composition source SHA, also present in A. A must explicitly bind `old_fit_source_choice="color_05/piper/fit_chosen/silver"`, the frozen Piper WAV SHA, three raw FIT tensor hashes, and the FIT and Track B prompts. The adapter's read-only frozen WAV resolver is rerun. This prevents A/R from being re-pinned to a different engine or modified adapter while retaining the same source-only policy. It is a source check, not a model result.

`prepare_bound_inputs_for_child` checks the source freeze, invokes the reviewed batch adapter, and passes its results through `checked_transfer`. That helper compares dtype/shape-aware old-FIT and synthetic batch hashes with A before and after tensor `.to(device)`, and checks tensor dtype, shape and destination. The fake tests use CPU; a later live child must pass `device="mps"` and must not permit a CPU fallback. This path does not load weights. `audit_composition_sidecars` checks the composition sidecar, post-host raw bytes, worker measurement hash, strict post-after-pre host timestamp, W/A/R and campaign identity, completed parent watchdog result, and the combined size of the worker directory, outside sidecars and both claims/results against the 2-GiB output cap and 12-GiB free-disk gate. It returns **source-only, not pilot GO**. The saved worker auditor and an independent raw host-log review must also run.

## Executable freeze still required

1. Obtain audited 32/32 human QA and create externally reviewed A and R. A must bind the adapter/Piper fields above, batch hashes and the exact composition source. A/R are absent now; fake fixtures do not substitute.
2. Review a new top-level, spawn-pickleable child operation and launcher L. Parent L must recheck A/R/source hashes and actual QA, create the exclusive watchdog claim, and start the 240-second deadline **before** child process startup. The child must import torch/MPS locally, set the 30-GiB PyTorch allocator cap, rerun fresh QA/preflight/host evidence, build exact CPU batches with the reviewed adapter, transfer and rehash them on MPS, and call the pinned FP32 loader **inside the worker's timed `load_model` callback** so pilot P includes model load. It must then run the worker's exact 2+2+72+12 schedule and capture fresh post-host evidence. The current composition child stops before the batch adapter and model loader; this contract does not remove that HOLD.
3. Bind parent result, sampled MPS driver high-water **lower bound**, allocator fraction ceiling, worker ledger, external sidecars and raw host logs into a saved-data auditor. The worker receipt still says `measured_mps_high_water_present=false` and `hard_per_call_watchdog_present=false`; these cannot be silently relabeled. Determine whether the allocator cap certifies the V6 30-GiB requirement, verify no power/sleep/thermal event across the attempt, enforce all output bytes and no retry, then obtain a separate independent post-pilot GO. The sample maximum is never an exact transient peak.
