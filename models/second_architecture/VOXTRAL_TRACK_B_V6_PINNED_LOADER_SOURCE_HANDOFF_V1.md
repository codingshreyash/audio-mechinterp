# Voxtral Track B V6 pinned FP32 loader: source-only handoff

**HOLD for real model load.** The [separate loader source](voxtral_track_b_v6_pinned_loader_source_v1.py) has a public `load_v6_pilot_model()` that always raises. Its private child-local path first calls the [pre-pilot launcher verifier](voxtral_track_b_v6_pre_pilot_launcher_source_v1.py), which checks externally pinned W/A/R hashes, the actual 32/32 human QA gate, frozen and fresh no-weight checkpoint/source/processor/selected-WAV fingerprints, and fresh host evidence. A failed proof returns before processor or model construction. The private path checks that the proof repeats exact W/A/R pins, verifies MPS availability, and sets the 30-GiB PyTorch MPS allocator fraction before loading any model weights.

The production-only private wrapper derives the snapshot from the existing pinned `voxtral_fit_pilot_capability_v1.SNAPSHOT`. The private helper rejects a supplied path unless its resolved directory equals that pinned path, before either factory. It calls the existing `validate_snapshot()` immediately before the processor factory and after model construction; that function rehashes the pinned tree, config, index, both weight shards, processor config, tokenizer asset and generation config against their fixed digests and sizes. Both full returned manifests must equal the frozen preflight snapshot, and each tree SHA must equal the admission binding. It also recomputes the installed Transformers source map before and after factories and compares it with the frozen preflight. These checks narrow, but cannot eliminate, a concurrent change-and-restore race during a factory read.

The helper uses `AutoProcessor.from_pretrained(..., local_files_only=True)` and checks processor/tokenizer types and audio/EOS IDs against the frozen preflight. It then requests `VoxtralForConditionalGeneration.from_pretrained` with local files, `dtype=torch.float32`, `device_map='mps'`, and SDPA, sets eval and disables parameter gradients, and checks every parameter is FP32 on MPS plus EOS/pad configuration. It synchronizes and checks current driver allocation against the cap. The dependency-injected private helper exists to fake-test order and state validation; an arbitrary snapshot or factory is not an admitted live path.

This source is not composed with a real `spawn` operation, processor-produced old-FIT/synthetic batches, worker schedule, host post-run audit, or saved-data auditor. The public [runtime adapter](voxtral_track_b_v6_mps_runtime_adapter_source_v1.py) and public admission launcher remain hard HOLD. The runtime's sampled driver high-water is a lower bound and its configured allocator fraction is a PyTorch allocation ceiling; neither provides an exact device peak. Future executable composition needs independent source review and externally reviewed QA/admission pins. No post-pilot GO can be inferred from a successful fake loader test.

Verification: [seven fake tests](test_voxtral_track_b_v6_pinned_loader_source_v1.py) use fake AutoProcessor/AutoModel and the earlier fake pinned admission chain. They check exact FP32/MPS factory arguments and eval state, bad QA blocking factories, bad model dtype rejection, alternate snapshot rejection before factories, pre-factory and in-factory snapshot mutations, and public HOLD. No real model, candidate audio or GPU was used.
