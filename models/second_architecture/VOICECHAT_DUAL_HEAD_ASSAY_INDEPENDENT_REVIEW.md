# Independent review of the VoiceChat dual-head assay protocol

**18 November 2026.** Reviewed [`VOICECHAT_DUAL_HEAD_ASSAY_PROTOCOL.md`](VOICECHAT_DUAL_HEAD_ASSAY_PROTOCOL.md) at commit `6ac8265` against the pinned NVIDIA NeMo source `097dfe9e2f55baf653b83035868bdc89849f1b47` and VoiceChat checkpoint configuration `443794ea956ef0065f001967ffd00e77f519cb39`. This is a source review only. I ran no model, ASR, remote instance, or active Voxtral development output.

## Decision

The proposed neural hook sites are reachable, and the plan correctly separates model tokens, parsing, replay, audio, and a stubbed dispatcher. I found three pre-run blockers in commit `6ac8265`; the protocol revision in commit `95a2e22` addresses all three. They are recorded here so implementation can preserve the fixes:

1. **Authorization gate is model-controlled.** Requiring `confirmed=true` in `cancel_calendar_events(date, event_ids, confirmed)` does not enforce confirmation if the model can emit that argument itself. The stub dispatcher must check a separate, fixture-controlled confirmation state bound to the exact date and event IDs. Under list-only and “ask first” requests, this state is false regardless of the model's JSON. Validate IDs against the seeded calendar and require the intended list/selection state where the fixture calls for it. Log the proposed call and the independent rejection reason. The model's `confirmed` field can be retained as an observation, never as proof of authorization.
2. **A single canned response can corrupt pass 2.** The [official helper](https://github.com/NVIDIA-NeMo/Speech/blob/097dfe9e2f55baf653b83035868bdc89849f1b47/nemo/collections/speechlm2/inference/utils/offline_voicechat.py#L171-L289) parses the first extracted call, then retokenizes that call and injects the supplied `api_response`; it does not dispatch by parsed tool name. A seeded *list* response after a proposed *cancel* call creates an inconsistent replay. Select a stub response from the validated parsed call: list data for list, rejection for unauthorized cancel, appropriate result for authorized cancel. With no complete/parseable call, inject no response and record no executed tool. Keep pass-1 and pass-2 claims separate. NVIDIA explicitly describes offline function calling as using a [prewritten response rather than a live tool](https://huggingface.co/nvidia/NVIDIA-NemotronLabs-VoiceChat-11B#offline-inference).
3. **Codec-token identity check is not available from the returned object.** In the pinned [`NemotronVoiceChat.offline_inference`](https://github.com/NVIDIA-NeMo/Speech/blob/097dfe9e2f55baf653b83035868bdc89849f1b47/nemo/collections/speechlm2/models/nemotron_voicechat.py#L678-L788), `gen_codes` is built and trimmed locally, but the returned `_post_inference` result retains `tokens_audio: None`; this contradicts the method's docstring. The protocol's codec-token identity gate requires a minimal local capture of the trimmed `gen_codes` and valid lengths. Pin and test that instrumentation before the 18-WAV fixture. If it changes results, stop.

**Revision check, `95a2e22`:** The protocol now requires independent confirmation state tied to event/date, chooses a call-specific inert response or no injection, captures local `gen_codes`, and treats `src_text` as optional. These corrections remove the three setup blockers above.

**Final protocol check, `711a23a`, SHA-256 `603c875f9c60a22488db3d1a63204b5d5edccc7c2217a6efd59b1ed058da06ca`:** The evidence gate now compares pass-1 text with pass-1 predicted function tokens without an audio claim, and separately compares pass-2 text/heard unspliced audio with pass-2 predicted function tokens after excluding injected spans. The readout defines the first action-discriminating token only when candidate scripts share the preceding function-token prefix, and otherwise reports separate divergence points. **No remaining source-review blocker to environment preparation.** The passive-hook identity pilot, local `gen_codes` capture, and independent confirmation/response dispatch remain required before fixture interpretation.

## Hook and inference details to preserve

- The exact modules exist: `stt_model.llm`, `stt_model.lm_head`, and `stt_model.function_head`; the latter two consume the same `out['last_hidden_state']` in [`DuplexSTTModel.forward`](https://github.com/NVIDIA-NeMo/Speech/blob/097dfe9e2f55baf653b83035868bdc89849f1b47/nemo/collections/speechlm2/models/duplex_stt_model.py#L466-L535). The released [config](https://huggingface.co/nvidia/NVIDIA-NemotronLabs-VoiceChat-11B/blob/443794ea956ef0065f001967ffd00e77f519cb39/config.json) enables the function head. `_step_zero` and `_step_inference` call this forward path; generation then samples text and takes `argmax` of function logits. A `function_head` output hook can affect that `argmax`. For a shared-state patch, insert immediately after `self.llm(...)` returns and before either head, or verify that a hook replacing the LLM's structured return really changes the local `last_hidden_state`.
- At a generation frame, a predicted function token is **discarded** when the position belongs to the prompt or a call/response token is already injected. The source's `should_predict = ~is_prompt_position & ~already_injected` gate matters for intervention placement. Assert that the targeted frame is actually selected, and log pre-head logits, returned logits, chosen IDs, and the gate. The forward path may boost text special-token logits after `lm_head`, so pre-head and sampled text logits should not be conflated. [Generation loop](https://github.com/NVIDIA-NeMo/Speech/blob/097dfe9e2f55baf653b83035868bdc89849f1b47/nemo/collections/speechlm2/models/duplex_stt_model.py#L3934-L4040).
- “First cancel decision” needs an operational token definition. `list_calendar_events` and `cancel_calendar_events` are multi-token serialized strings, often sharing `<TOOLCALL>` and JSON prefix tokens. A single-frame no-call/list/cancel *logit margin* is undefined until the relevant token sequences and common prefix are specified. Identify the earliest divergent function token after matched history; use complete parsed actions as the outcome. An opposite-decision donor with different prior tokens cannot be called a same-state intervention without checking history and alignment.
- The model's `src_text` is optional evidence, not a ground-truth transcript: `_post_inference` sets it from the user-text head only if enabled or from RNNT output if present, and the released config has `predict_user_text=false`. Use independent listening/ASR for the input wording and record whether any internal user-text path actually ran. [Post-processing](https://github.com/NVIDIA-NeMo/Speech/blob/097dfe9e2f55baf653b83035868bdc89849f1b47/nemo/collections/speechlm2/models/duplex_stt_model.py#L4405-L4455).

## Remaining gates

The fixed UTC date, literal-date controls, seed event IDs, no-tool control, multiple voices, and pass-labeled traces address major date and parser confounds. Keep the separate text checkpoint as a task-difficulty comparator, not a same-model typed-user baseline. A passive-hook identity pilot should precede the 18-WAV matrix; record GPU memory, disk use, and per-pass runtime before estimating the larger run. The [model card](https://huggingface.co/nvidia/NVIDIA-NemotronLabs-VoiceChat-11B#offline-inference) requires a Linux/NVIDIA GPU reference environment and lists H100 test hardware, but does not establish that a particular available GPU or batch size will work with these hooks. Full-logit capture must remain bounded.

The protocol's evidence hierarchy is sound if these fixes are made: a raw unmodified model call, a correctly parsed action, and an independent dispatcher decision are separate observations. An activation patch can establish local causality; a security claim additionally needs an input-reachable behavior and an accurately stated harness consequence.
