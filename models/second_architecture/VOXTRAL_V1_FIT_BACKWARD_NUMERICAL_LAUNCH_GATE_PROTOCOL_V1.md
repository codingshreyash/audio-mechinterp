# Old-FIT numerical follow-up external launch gate, v1

**Prospective source/launch control, 18 November 2026. No live arm has been launched by this protocol.** The [numerical protocol](VOXTRAL_V1_FIT_BACKWARD_NUMERICAL_FOLLOWUP_PROTOCOL_V1.md) fixes the old v1 FIT WAVs, two arithmetic arms, six signed alphas, three repeats and 30-GiB/15- or 20-minute runner limits. The [auditor review](VOXTRAL_V1_FIT_BACKWARD_NUMERICAL_AUDIT_INDEPENDENT_REVIEW.md) accepts its CPU auditor for arithmetic and receipt consistency. This gate may start **one arm per new Python process** only after a separate, committed external freeze receipt exists. It does not create that receipt or authorize itself.

The external receipt path is `VOXTRAL_V1_FIT_BACKWARD_NUMERICAL_EXTERNAL_FREEZE_RECEIPT_V1.json`, committed in the repository after independent launch-source review. It must carry status `frozen_old_fit_numerical_launch_v1`, exactly the permitted arms `bf16` and `fp32`, a full SHA-256 for the runner, runner tests, numerical protocol, runner review, auditor, auditor tests, auditor review, launcher, launcher tests, this launch protocol and the independent launcher review; the review commit must contain those launcher files at the same bytes. The audit scope string must be `paired_edit_numerical_consistency_only; donor_and_no_grad_report_only`. The launcher pins reviewed pre-existing hashes itself and compares every receipt hash to both the working file and its committed `HEAD` blob. It rejects a missing/uncommitted receipt, a dirty or substituted bound file, a malformed or unreviewed receipt, or a launch-review commit that does not contain the same launcher source/tests/protocol/review. The gate performs this check before starting the model subprocess and rechecks the same sources after it returns. The receipt is produced externally; no self-freeze or auto-accept path exists.

The launcher reserves a fresh exclusive attempt directory and writes `launch_start.json` before spawning the pinned runner with `--run --arm <bf16|fp32> --output-dir <attempt>/runner`. It uses the same pinned virtual environment and offline Hugging Face settings, with no shell interpolation. The runner creates its own exclusive child directory, starts its internal clock before preflight, and retains its 15-minute BF16 or 20-minute FP32 and 30-GiB MPS driver caps. The launcher adds a 120-second process grace to the arm wall cap, terminates a hung subprocess on timeout, and records that condition as a failed launch. It never retries, changes dtype, starts the other arm, or reads fresh v2 data. The launcher writes `launch_finish.json` once with subprocess exit status, elapsed time, post-run source verification and SHA-256 hashes of any runner result/error receipt.

If the runner created a completed or failed receipt, launch the frozen CPU auditor after the runner exits and capture its JSON stdout as immutable `audit.json` in the attempt parent. Auditor failure is a failed launch outcome and its stderr is captured in `audit_error.txt`. The auditor's `audited_failed_attempt_receipt_only` status remains a failed attempt, not a completed result. An `audited_completed_numerical_consistency_only` status verifies arithmetic and receipt consistency; it does not attest model execution, source loading at every instant, or donor/no-grad terminal content. The donor and three no-grad terminal vectors are **report-only**: the auditor checks shape, FP32 dtype and finiteness but has no independently bound source tensors or per-vector result hashes for them. Likewise, the independent auditor checks clean/donor source-hash fields only as strings. The launch gate binds files at pre-load and post-run checks, but it must not claim an attestation of intermediate process state or the model's actual forwards.

The expected source freeze and each attempt's launch receipts are separate from the numerical runner output. A successful gate/audit remains a diagnostic on one old-FIT case. It does not establish a reusable audio Jacobian lens, held-out v2 transfer, generated-speech behavior, a tool-call failure or a security vulnerability.
