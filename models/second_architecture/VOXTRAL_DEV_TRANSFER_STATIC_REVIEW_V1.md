## Blocking issues

1. **An invalid self patch can evade the parity gate.** In `run_record`, any invalid `prepare_dev_edit` result, including `name == "self"`, becomes an `invalid_condition` row and execution continues. `summarize` counts invalid conditions only for whole/pre/post/padding/random, so both effect and time gates can pass even if a required self row is invalid and no self suffix parity was measured. The prospective protocol requires **96/96 self parity per arm and site**. Abort immediately on an invalid self edit, and make the summary or independent auditor verify that every passive/self slot is a generation with exact suffix-ID parity against its clean or blank baseline. Add a synthetic regression with an invalid self slot and another with a mismatched passive/self suffix.
2. **A behavior-critical imported helper is not pinned.** The runner verifies the FIT full-runner SHA but imports `voxtral_fit_v2_causal_first_record.py` for feature construction, hook placement, edit scaling, score generation, and answer classification without checking that file's hash. Its reviewed SHA-256 is `64d799bbb40b58b128b049877d18bde7774c2dc16717af97e692aa4531e907b5`. Pin and verify this helper before model load and record it in run metadata. The independent frontend helper `voxtral_preprocessing_decomposition.py` (SHA-256 `026445da1ac2c4c2f4b8f45ab2f8d7a1f4679924774714951b16d5cd29de0788`) should also be pinned or at least recorded, because it supplies the second frontend check.

The initial runner is **not cleared for development inference** at SHA `4e89f783...`. The prospective protocol also requires an independently frozen CPU result auditor before `--run`; this review is source inspection, not a result audit or a claim about transfer.
