19 November 2026. **HOLD for the amended design at commit `d7a5980`; no candidate inference was run.** This rereview checks [V2](WHISPER_PADDING_CHANNEL_PROSPECTIVE_V2.md) against the [first independent HOLD](WHISPER_PADDING_CHANNEL_INDEPENDENT_DESIGN_REVIEW_V1.md), the amended [planner](padding_channel_plan_v1.py), and its no-weight tests. The five planner tests pass; the printed schedule has **436** calls, core evidence estimate **1,375,203,488 bytes**, and SHA-256 `1dbbbc07183bd6b93b94feffeaaf90c9c28ebadb2699f8e5ff361b2399097951`. The tests do not load weights or run the candidate model.

## Corrected points

V2 adds paired true no-hook and read-only capture calls for each of the two same-duration silence donors. It specifies both phase-specific tensor captures at both intervention sites, immutable sidecars, and complete-output/first-vector parity with the no-hook donor. It makes each recipient `RR` a true no-hook call and makes `read_only` the source of recipient-native tensors. The all-18, two-site, 12-arm factorial is intact. The source hashes remain pinned, and the prior implementation facts remain correctly stated: the Whisper encoder ignores its supplied audio mask, decoder cross-attention is unmasked, and the log-mel floor depends on the input's global maximum. Nominal padding is therefore not an information-free control.

V2 also specifies 1,800-second wall, 4-GiB sampled process-tree RSS, and 2-GiB evidence ceilings with a 128-MiB reserve and a 256-MiB auxiliary allowance. The amended estimate plus allowance and reserve is **1,777,856,672 bytes**, below the 2-GiB cap. The host-power/thermal gate, complete prefix/text/EOS and length-censor accounting, full `DD` donor raw-logit parity, and separation between white-box state swaps and a later waveform-level test are appropriate design constraints. A future worker and independent executable review must still implement and verify them.

## Remaining blocking order dependency

For every recipient and site, `schedule()` emits `CELLS + CONTROLS + PHASE_SPLITS`, so its first arms are **`RR`, `RD`, `DR`, `DD`, then `read_only`**. Yet V2 says `read_only` captures the recipient-native tensors used by `RD`, `DR`, `DD`, and the random and phase-split arms; `RR` explicitly has zero hooks. At the first case/site, the three swap calls therefore occur before their required recipient tensors exist in this run. The protocol requires one run per arm in frozen order and disallows an implicit preliminary pass, so this is an executable dependency error, not merely a missing test.

Move recipient `read_only` immediately after `RR` for each case/site and before every edit, while retaining all 12 arms. For example, freeze `RR`, `read_only`, `RD`, `DR`, `DD`, `self`, the four random arms, and the two phase-split arms. Keep the two donor no-hook/read-only pairs first. Update the planner, test the per-case order and capture-before-edit invariant, and replace the canonical schedule hash in V2. Preserve the duplicate capture hash check across sites. Then a design-only GO can be considered. A worker, fake-model hook tests, admission receipt, independent executable GO, and passing host gate remain separate requirements before candidate inference.
