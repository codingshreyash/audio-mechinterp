# Independent review: prospective Whisper padding-channel assay

19 November 2026. **HOLD for the design as written; no candidate inference was run.** I reviewed `WHISPER_PADDING_CHANNEL_PROSPECTIVE_V1.md`, `padding_channel_plan_v1.py`, `test_padding_channel_plan_v1.py`, commits `3c8a2b1` and `ca008d1`, the prior independent saved-result audit, and the pinned installed Transformers source. The no-weight planner prints 434 calls and canonical schedule SHA-256 `b6ae293a9a28ae13338a6ef17fae42ad8c62feae7c63afd73a5c991bf7eeccc1`; its four unit tests pass. This is a decision about the prospective protocol, not an observation about model behavior.

## What is sound

The plan retains all 18 non-silence cases in two nine-case duration strata and includes both `log_mel` and `pre_block0` sites. Each case/site has the complete `RR`, `RD`, `DR`, `DD` active-by-padding factorial; read-only and self controls; two seeded, same-support L2-matched random active controls and two random padding controls; and detection-only and transcription-only padding swaps. The schedule count is correctly `2 + 18 × 2 × 12 = 434`. The donor is the same-duration silence file, and the planner rehashes the manifest and all WAVs.

The proposed geometry is source-consistent: 2/8-second masks mark 200/800 of 3,000 mel frames and 100/400 of 1,500 pre-block-0 rows. The two kernel-3 convolutions have strides 1 and 2, giving early row *j* a local mel receptive field from `2j-3` through `2j+3`; the first row at active limit plus two is beyond the active mel interval. This local calculation does not remove the global log-mel-floor dependence. The installed `feature_extraction_whisper.py` SHA-256 is `dcce2e7820be059e657a9e12a60e8a55cfd37b1a82ee202ca15fc7d0934374cb` and applies the global maximum floor. The installed `modeling_whisper.py` SHA-256 is `bf4f022d37ed523d09a472dae267b86007aaae0cd39d2ce37927de44bfc5b9e6`; its encoder ignores the supplied audio attention mask and its decoder layers receive `encoder_attention_mask=None`. Thus nominal padding is an exposed, potentially informative representation, not a no-information control.

The endpoint is appropriately a complete generated sequence including language prefix, text, EOS, and step count. The plan retains length-censored outcomes, requires no-op and full-donor parity, distinguishes detection from transcription effects, and separates white-box state swaps from a later waveform-level attacker-control test. A changed activation or score alone is explicitly insufficient for a behavioral or security claim. The prior audit already showed why this restraint matters: only four beep cases had a donor/recipient output contrast, and three of the four transfers were capitalization changes.

## Blocking design correction

The frozen schedule has **only two `no_hook` silence donor calls**. A no-hook call can provide the donor output, but it does not capture the donor's phase-specific log-mel and pre-block-0 tensors. `RD`, `DR`, and `DD` require those tensors for both detection and transcription. The current document says to use immutable native captures but does not say how donor captures enter this new run or bind them to the schedule. The 434-call plan is therefore not a self-contained executable experiment.

The cleanest repair is to add one `read_only` capture call for each silence donor, immediately after its no-hook call, and require exact complete-output and first-raw-logit parity between each pair. That changes the frozen count to **436**, so update the planner, tests, schedule hash, and evidence calculation before execution. An alternative is to use the independently audited donor sidecars from `runs/causal_whisper_v1/attempt_002/worker_output/native/`; then the design must explicitly name that dependency, pin every sidecar hash and provenance, independently rehash it at admission, verify model/source/processor/generation equivalence, and retain current-run no-hook donor parity. The prior sidecars currently exist locally, but merely existing is not a prospective source binding.

Also say explicitly that `RR` is a true no-hook recipient call at each site. The separate `read_only` call then captures the recipient state and must match `RR`; `self` must match both. This makes the stated comparison to a no-hook recipient result an in-matrix control rather than an implicit dependence on an earlier run.

## Gates before executable GO

1. Freeze a worker and fake-model hook tests before loading weights. The current tests verify only the schedule and hard-coded geometry. They do not prove the first-convolution and pre-block-0 hook axes, exactly one detection and one transcription edit, immutable donor/recipient captures, unchanged support outside each edit, or no-op controls. Bind the worker and tests by source hash and independently review them.
2. Measure the processor masks and actual tensor shapes at runtime, require exact recipient/donor mask equality within each pair, and rehash every saved tensor sidecar. A boundary sensitivity analysis must remain separate from the full-pad primary factorial and cannot be substituted for full-donor parity.
3. Set numeric wall-time, RSS, and evidence caps plus a pre-run AC/lid/thermal gate. The prose requests these gates but the new planner defines none. A conservative **core-only** float32 estimate for the present 434 rows is 1,176,573,320 bytes: 434 first raw vocab vectors, 36 `DD` calls at 128 full raw vocab vectors, and both native sites/phases for 20 files. With the prior 256-MiB metadata allowance and 128-MiB reserve, this is about 1.47 GiB, below the prior 2-GiB evidence cap. That estimate excludes additional processed-score, decoder-state, hook, and audit artifacts; recompute it for the repaired schedule and enforce a live hard cap. The current battery/thermal-unstable host is not ready for long candidate inference.
4. Make every arm's full prefix/generated IDs, EOS/censor flag, selected language, and first raw logit vector mandatory. Keep `DD` all-step raw-logit parity against the donor and no-op first-step parity at the stated `1e-5` maximum absolute difference. Define exactly which processed-score and decoder-state arrays are saved and compared; “where the prior audit format supports them” is not a deterministic acceptance rule. A failed parity or missing call makes that local causal comparison uninterpretable.

After these corrections, the assay is a reasonable within-checkpoint test of whether the exposed nominal padding interface affects complete Whisper outputs. It cannot by itself establish a waveform-reachable exploit, a general audio circuit, or a security finding in a speech-to-speech system. A later, separately frozen waveform experiment is necessary for those claims.
