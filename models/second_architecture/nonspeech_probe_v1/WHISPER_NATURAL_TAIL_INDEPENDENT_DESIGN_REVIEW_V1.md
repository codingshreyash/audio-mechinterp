## Required protocol correction before runner implementation

The prospective sentence that specifies `task="transcribe", language=None` as the existing Whisper generation path reads as applying to both checkpoints. That call **fails** for the pinned `openai/whisper-tiny.en` under Transformers 5.20.2: the installed `_set_language_and_task` rejects a non-None task or language for the English-only generation config. This failure was already isolated and fixed in [the English V2 source review](INDEPENDENT_WHISPER_ENGLISH_REPAIR_REVIEW_V2.md). Amend the prospective to state two explicit call signatures:

1. Multilingual `openai/whisper-tiny`: pass `task="transcribe", language=None`; require the automatic language-detection pass and capture its candidate logits, chosen language token, and resolved generation prefix.
2. English-only `openai/whisper-tiny.en`: **omit both `task` and `language` keywords entirely**; require its native English prefix and exactly one transcription encoder pass, with no language-detection pass.

Keep the common pinned processor, FP32 CPU/eval, greedy generation, 128-token cap, no timestamps, no previous-token conditioning, and complete output/first-step vector evidence. Add a no-weight test that checks both actual keyword dictionaries against the pinned installed generation configuration. Do not work around the English failure by silently dropping that checkpoint or counting failed calls as negative results.

## Conditions for the later executable review

Freeze a 320-row plan before inference, with case, checkpoint, condition, and replay identity; make the second WAV/PCM auditor independent of the constructor. Compare processor tensors before model answers. For every zero-tail pair, require explicit 30-second padded-PCM identity and report mel and attention-mask parity separately; a zero-tail answer change needs a mask/preprocessing/runner explanation. For noise pairs, report original-source, appended-tail, boundary, and nominal-padding mel differences, global maximum/floor, and complete EOS-qualified token outcomes. A changed padded feature alone cannot establish that padded information mediated an output change, because the noise tail also changes active audio. The prior 436-call white-box result is a lead, not a substitute for that test.

Save full first-step **raw** decoder logits and post-processor scores, complete prefix/generated IDs, selected scores, EOS versus 128-token censor, and the multilingual detection evidence. The previously audited descriptive V2 outputs may be compared with new `base` calls as a diagnostic only when the exact pins and generation arguments match; they cannot replace any of the new 320 scheduled calls or the within-run base replays. The English-only prior output was stable on all 20 engineered WAVs, and the multilingual prior had four output-informative beeps; neither observation licenses selecting only those beeps now. Silence plus a noise tail is a noise-only source control, not a no-treatment negative control.

The proposed 1,800-second and 4-GiB process-tree RSS limits per checkpoint, 1-GiB evidence ceiling, AC/open-lid/thermal gates, immutable failed-attempt handling, and independent post-run audit are sensible but **not yet implemented or validated** for this runner. Clarify in the executable whether 1 GiB applies to each checkpoint attempt or their combined evidence and enforce the chosen scope. Preserve the fixed checkpoint and package/source hashes from `descriptive_pins_v1.json` and pin the new runner, plan, auditor, and rendered manifest before inference.

This experiment tests whether an ordinary modified waveform can move a Whisper output in this engineered non-speech set. Even a replicated complete-output change would not by itself be a tool, authorization, covert-audio, or general security finding.
