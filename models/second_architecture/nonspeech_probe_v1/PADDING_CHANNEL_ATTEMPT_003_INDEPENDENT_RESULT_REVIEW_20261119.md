# Independent result review: Whisper nominal padding channel, attempt 003

19 November 2026. **Bounded causal finding; no security finding.** I reviewed the immutable 436-call `runs/padding_channel_v1/attempt_003` against the predeclared [V1 question](WHISPER_PADDING_CHANNEL_PROSPECTIVE_V1.md), [V3 call order](WHISPER_PADDING_CHANNEL_PROSPECTIVE_V3.md), [V4 evidence amendment](WHISPER_PADDING_CHANNEL_PROSPECTIVE_V4.md), [V5 processor evidence amendment](WHISPER_PADDING_CHANNEL_PROSPECTIVE_V5.md), [V6 terminal amendment](WHISPER_PADDING_CHANNEL_PROSPECTIVE_V6.md), and executable [GO](PADDING_CHANNEL_INDEPENDENT_EXECUTABLE_REVIEW_V3.md). This was a deterministic, CPU FP32, white-box test on the pinned multilingual Whisper Tiny checkpoint, using 18 engineered non-speech recipients and two same-duration silence donors. It did not send a modified waveform to the model.

## Integrity and audit provenance

The parent completed all **436/436 scheduled forwards** in about **115.3 seconds**, with a terminal receipt after the completion write. The pre/post host checks passed the recorded AC, lid, and thermal gates. The sampled peak process-tree RSS was **1,136,623,616 bytes**, below the 4-GiB limit; the attempt contained **357,571,184 bytes**, below the 2-GiB evidence cap. The post-run audit reconstructed **20 processor input tensors**, **80 native tensors**, all hooks and inputs, and **1,920/1,920 binary sidecars**. It reported **zero parity failures** and **14 length-censored generated outputs**. The audit status is named `censored_or_parity_failed` because the 14 censors exist; it does not signify a parity failure.

I separately parsed the 436 saved forward records and verified SHA-256, byte size and shape for all 1,920 referenced `.npy` sidecars, with no missing or unreferenced `.npy` files. An independent NumPy comparison found **128/128 applicable first-step/complete-token parity comparisons** and **36/36 full-step raw-logit DD-to-donor comparisons** within the frozen `1e-5` tolerance. The DD outputs also matched the complete donor token paths. The saved audit independently recomputed each of the 20 input feature tensors from the pinned PCM and processor, compared all 436 call bindings and masks, and reconstructed each scheduled edit from native tensors.

The original, preregistered `padding_channel_audit_v3.py` failed at DD call 9 due to an **auditor key-order bug**: the worker inserted `donor_no_hook` before `donor_full_raw`, but sorted-key JSON stored `donor_full_raw` first; the auditor used `next(iter(item["parity"].values()))` as though order were preserved. The saved records had correct parity values. The separately named [posthoc auditor](padding_channel_audit_v3_posthoc.py) changes only this first-parity key lookup to the explicit expected key and passed against the unchanged attempt and original source admission/GO. The original auditor remains unchanged; the posthoc audit is not a new run or a repair to candidate outputs. The exact auditor diff is the module docstring and three-line explicit key selection.

## Complete-output result

For each site, only **4/18** native recipients had a different complete output from their matched silence donor. The other **14/18** remain in the full denominator but cannot show a donor-output transfer. The 2×2 and phase results were identical at the `log_mel` and `pre_block0` sites for the four informative cases:

| Recipient | RR native | RD: recipient active, donor pad | DR: donor active, recipient pad | DD: donor active and pad |
| --- | --- | --- | --- | --- |
| 2-s high beep | ` Fuck` + EOS | ` Fuck.` + EOS | ` you` + EOS | ` you` + EOS |
| 2-s low beep | ` You` + EOS | ` You` + EOS | ` you` + EOS | ` you` + EOS |
| 8-s high beep | ` You` + EOS | repeated ` Fuck.`; **no EOS at 128 tokens** | ` you` + EOS | ` you` + EOS |
| 8-s low beep | ` You` + EOS | ` You` + EOS | ` you` + EOS | ` you` + EOS |

Thus, **RD never produced the donor's EOS-complete answer in the four informative cases**. It produced one complete punctuation change, two exact native matches, and one length-censored repeated output at each site. RD exactly preserved the complete native output for all 14 output-uninformative recipients at each site. DR and DD produced the complete donor output in **4/4 informative cases per site**; their matches in the 14 uninformative cases provide no output-flip evidence. All four informative cases and all donor swaps retained the English language prefix.

`padding_detect_only` retained RR's complete sequence in **18/18 cases at both sites**. `padding_transcribe_only` had exactly the RD outcome categories: 16 native matches, one complete punctuation change, and one length-censored repetition per site. This localizes the observed complete-output differences to the transcription pass under these edits, rather than an altered selected language prefix. It does not isolate a unique direction, neuron, or waveform time.

At both sites, RD changed the **first-step raw decoder logits in all 18/18 recipients** by more than `1e-5` (log-mel maximum-absolute difference range `0.08704`–`1.95125`; pre-block-0 range `0.14907`–`3.87074`). Detection-only changed no first-step raw decoder vector. This is strong evidence that the nominal padding interval can influence decoder scores through the transcription pathway in this pinned implementation, even when greedy generation returns the same complete answer. It is **not** evidence that all 18 answers changed.

The equal-norm random controls are disruptive, especially at the log-mel interface. The two random-padding arms produced **16/36 EOS-complete changes plus four censors** at log-mel and **4/36 EOS-complete changes plus two censors** at pre-block-0; the two random-active arms produced **26/36 complete changes plus one censor** at log-mel and **17/36 complete changes plus three censors** at pre-block-0. These controls prevent describing the donor-pad result as uniquely tied to a silence feature or as a robust, general answer flip. Some random arms changed the language prefix, whereas the donor-pad arms did not. Random arrays and internal splices are not attacker-supplied audio.

## Interpretation and next decision

The nominally padded input is an available causal channel in this implementation: its splice changes raw decoder scores in every recipient and, in the two high-beep cases, changes generation (punctuation in one and an EOS-censored repetition in the other). The unmodified active region dominates the native-versus-silence complete answer in the four informative cases: DR alone reproduces the silence answer. The replicated two-site pattern strengthens the within-checkpoint observation but does not make the edited states natural. The processor's global log-mel floor and Whisper's unmasked encoder make nominal padding available to attention; the splice itself can create inconsistent active/padded combinations that an ordinary waveform may not produce.

The next causal test should use **frozen, attacker-reachable WAV edits** with equal-duration zero-tail controls, preregistered noise levels, complete-answer and language-prefix outcomes, and direct measurement of active/padded feature changes. The [prospective V1 plan](WHISPER_PADDING_CHANNEL_PROSPECTIVE_V1.md#separate-attacker-reachable-waveform-test) already specifies this distinction. If those WAV edits produce a meaningful replicated complete-output effect, test it on an audio-language or speech-to-speech action model with a real authorization boundary. The current experiment establishes a narrow Whisper mechanism lead, not an exploit or a security vulnerability.
