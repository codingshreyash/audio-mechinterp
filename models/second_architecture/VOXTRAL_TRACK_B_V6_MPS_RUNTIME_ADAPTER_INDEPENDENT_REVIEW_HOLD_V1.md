# Independent source review: V6 Mac MPS runtime adapter

18 November 2026. Reviewed only runtime adapter commit `8594d10` against V6 and the held pilot worker. **HOLD for freezing this runtime boundary, and HOLD for any real model load or pilot.** No model, candidate WAV or GPU was used.

All **6/6 fake-process CPU tests passed** and Python compilation passed. Actual `spawn` tests use top-level fake operation functions and a top-level `_child_entry`; production `torch.mps` is imported in the child when no fake MPS object is passed, so it need not be pickled. A closure or lambda would fail at spawn and is unsuitable for a live launcher. The allocator computes `30 GiB / recommended_max_memory`, rejects less than 30 GiB recommended memory, and configures the PyTorch per-process fraction before calling the operation. Its 20-ms driver-allocation samples are explicitly a **lower bound** on transient usage; the configured PyTorch allocator limit is the separate ceiling and does not certify non-PyTorch use. The sampler ignores only an incomplete final JSONL row and tracks the active call ordinal from completed lines. Public `launch_v6_pilot()` always raises before a loader. The parent writes an exclusive `.watchdog` claim before spawn, includes child startup in its 240-second deadline, and retains fake OOM/timeout outcomes without retrying the same claim.

**Termination-confirmation gap:** On timeout the parent calls terminate/join and then kill/join if needed, but does not check `process.is_alive()` after the final join. It can write `timeout_no_retry` as though the child stopped even if termination remains unconfirmed. A retained outcome must state `termination_unconfirmed` with the child PID/status and remain HOLD if the process is still alive.

**Early-failure receipt gap:** The parent creates the exclusive claim, then constructs the multiprocessing queue and process **outside** its exception handler. I reproduced a fake queue-allocation `OSError`: the `.watchdog` claim remains but no adjacent `.result.json` exists. Queue/process setup and spawn errors must be covered by the retained failure receipt path without clearing the claim.

The present adapter is not composed with the reviewed pre-pilot admission, FP32 model loader, worker schedule, host audit or saved-data auditor. The worker's own `measured_mps_high_water_present=false` and `hard_per_call_watchdog_present=false` cannot be relabeled by this source. A future live launcher and evidence chain require separate review even after these two source gaps are fixed.
