## Residual corrections

1. **Correct the WAV identity table.** I independently SHA-256 hashed all 16 selected file bytes, compared each to its Track B manifest output, and checked mono/16-kHz/PCM16/frame-count metadata. Fifteen V2 table hashes match. The `pair_01` Piper **cookie** table hash is only 62 hex characters: `79fed2f865bbf91b68cb2c68c6afbfeb65f1d44f33ba7bb4d275d1d97e64ba`. The manifest and actual WAV both give the 64-character `79fed2f865bbf91b68cb2c68c6afbfeb65f1d44f33ba7bb4d275d1d1d97e64ba`. The V2 manifest, technical-binding and independent-inventory file hashes themselves match their files. Correct the table and make the no-weight preflight compare all 16 exact hashes to both the reviewed manifest and the corrected protocol.
2. **Bound teacher-forced logits to answer positions.** V2 specifies `model(..., logits_to_keep=0)`. In the pinned local `transformers/models/voxtral/modeling_voxtral.py`, `slice_indices = slice(-logits_to_keep, None)` followed by `lm_head(hidden_states[:, slice_indices, :])`; zero means `slice(0,None)` and materializes logits for **every prompt and reply position** for each batched alias. This is unnecessary and can materially increase FP32 backward memory. For a class batch with longest alias length `Lmax` including EOS, feed prompt plus `Lmax-1` continuation tokens and set `logits_to_keep=Lmax`. This yields score rows from prompt-last through the longest EOS position. Index each alias using its own length and mask continuation padding. Freeze these exact shapes/index rules, run the predeclared batched-versus-standalone score parity, and account for the reduced but still unmeasured peak under the 30-GiB cap.
3. **Specify the batched projector hook layout.** The pinned `VoxtralModel.get_audio_features` reshapes the encoder output with `reshape(-1, intermediate_size)` before `multi_modal_projector`; the projector hook's batch output is therefore flat `[B*T,3072]`, not `[B,T,3072]`. V2 says to sum gradients over an alias batch dimension but does not say how to recover it. The implementation freeze must assert the actual `B`, per-clip `T`, ordered audio-placeholder count and flat shape; reshape as `[B,T,3072]` only for per-alias state parity, edit at `b*T+r` for **every** alias `b` and selected word row `r`, sum gradients over alias dimension for the shared edit, then return the original flat tensor shape and ordering. A single unoffset `R` edit would affect only alias zero. Keep V2's stringent prepatch singleton/batch state parity; if batching changes those bits, stop and amend prospectively rather than silently relaxing the comparison.

No pair-excluded pooled Jacobian is needed for this **local-oracle answer-link** pilot. It cannot support a reusable-lens or time-localization claim, and the fixed ±0.1 schedule may yield no predicted crossings; V2 correctly treats that as inconclusive for a categorical answer link. After these three corrections, a separate source/runner review, no-weight preflight and the real 32/32 listening receipt remain required before weights load.
