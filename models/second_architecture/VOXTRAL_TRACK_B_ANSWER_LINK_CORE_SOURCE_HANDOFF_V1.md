# Voxtral Track B answer-link core: source handoff

This source-only handoff follows the independently reviewed [V3 protocol](VOXTRAL_FP32_TRACK_B_ANSWER_LINK_PROSPECTIVE_V3.md), [V4 erratum](VOXTRAL_FP32_TRACK_B_ANSWER_LINK_PROSPECTIVE_V4_ERRATUM.md), [V5 sequential-alias amendment](VOXTRAL_FP32_TRACK_B_ANSWER_LINK_PROSPECTIVE_V5_SEQUENTIAL_ALIAS_AMENDMENT.md), and [V6 resource-pilot design GO](VOXTRAL_FP32_TRACK_B_ANSWER_LINK_PROSPECTIVE_V6_INDEPENDENT_REVIEW_GO.md). The [first core source review](VOXTRAL_TRACK_B_ANSWER_LINK_CORE_INDEPENDENT_SOURCE_REVIEW_HOLD_V1.md) found four defects; the present source revision addresses them for rereview. The V6 GO is for design only. Neither the core nor this handoff authorizes loading weights.

## Implemented in source

- [`voxtral_track_b_answer_link_core_v1.py`](voxtral_track_b_answer_link_core_v1.py) has no CLI, checkpoint loader, corpus reader or model construction. It accepts an externally supplied FP32 model, one checked processor batch, exact projector states, frozen rows and frozen aliases.
- It derives nominal projector rows from the PCM word slot, **requires an externally reviewed unpadded projector row count**, and rejects any selected row beyond that count. The core cannot infer the active count from the word mask; if no reviewed count exists, the caller must stop. It checks nonempty/in-range rows, fixed 3,072-wide finite matched FP32 states and donor mean direction, and produces a seed-derived equal-norm random direction. The row rule is an index heuristic, not a time-localization result.
- Its hook and passive capture both require Voxtral's fixed 3,072-wide FP32 projector output. The hook validates flat `[B*T,3072]` output against the singleton source, edits raw `b*T+r` for every alias `b`, and returns the original flat order. It asserts one hook call, exact-zero bit parity, no outside-row changes, finite realized FP32 edit norm and at most 5% relative realization error. Full donor replacement is separate.
- The production class scorer runs **one B=1 model forward per alias**, with prompt plus `Li−1` answer tokens and `logits_to_keep=Li`, where `Li` includes EOS. It stores each complete alias's token likelihoods and log probability; class mass is `logsumexp` of those log probabilities. For gradients, it takes one source gradient per alias, exposes a CPU FP32 **selected-row gradient tensor per alias** for lossless sidecar storage, and records selected/full norms, finite flags, selected SHA-256, float64 alias-weight dtype and FP32 accumulation dtype. It softmax-weights the gradients to obtain the class-mass gradient. Donor minus recipient yields `S0` and the directional Jacobian `J`.
- It validates contextual alias tokenization through a caller-supplied encoder of the **actual chat prompt plus assistant surface**. The frozen inventory keeps V5's surface order (lowercase, initial-capital, uppercase; no space then one space) and retains the first occurrence of each token-ID sequence, including its surface provenance. A standalone word encoding is rejected unless it matches that continuation. Generation captures the full greedy suffix, EOS, strict six-way class, alias coverage and hook evidence. Separate helpers enforce grad/no-grad per-token score parity, exact clean/zero and natural/full-donor suffix parity, and every V3 predicted-switch clause.
- [`test_voxtral_track_b_answer_link_core_v1.py`](test_voxtral_track_b_answer_link_core_v1.py) uses only fake CPU models/tokenizers. It covers contextual boundary rejection, first-occurrence alias order/deduplication, active-row rejection, fixed 3,072 width, flat `B*T` indexing, one-hook rejection, zero/full controls, variable-length EOS scoring and answer-logit slice, sequential class mass, lossless per-alias gradient reconstruction, grad/no-grad parity, a finite-difference check of a multi-alias answer Jacobian, and exact switch clauses. Run with `python -m unittest models.second_architecture.test_voxtral_track_b_answer_link_core_v1 -v` in a Python environment with PyTorch. No real model or audio is used.

## Required integration before any candidate inference

1. Follow the V5/V6 schedule and separately review executable source. Maximum planned Track B core calls with six aliases per word: **112 generations, 1,152 no-grad score forwards, 192 grad score forwards/backwards**. V6 adds its specified synthetic maximum-geometry resource pilot and call ledger; the runner **must capture natural source states inside clean generations**. If that cannot be implemented, stop and obtain a new prospective protocol amendment and independent review before any separate capture call. Deduplicated aliases reduce actual calls; an execution ledger must record them. The V3 336-call batch estimate no longer describes this source path.
2. Obtain the actual independently audited **32/32 blinded human QA GO** and independent evidence review; bind its SHA-256 and all 16 selected WAV hashes to both the frozen Track B manifest and V3 table. The technical WAV fixture's `candidate_model_inference_authorized=false` remains a HOLD.
3. Build a separate no-weight preflight and bounded worker. They must freeze V5/V6 protocol/source hashes, checkpoint/Transformers source, tokenizer and actual prompt/alias IDs, per-clip processor tensors and placeholder counts, the **independently verified unpadded projector row count per clip**, exact masks and seeds, power/lid/clock admission, no-retry attempt identity, model FP32/eval/no-autocast state, MPS/disk/time caps, immutable result schema, and independent saved-data audit. Do not call this library directly on a live checkpoint before these gates pass.
4. Implement the processor-specific `contextual_encode` for each of six surfaces per word and prove its returned full IDs have the frozen prompt IDs as an exact prefix. If any alias changes that prefix or differs from standalone continuation IDs, **stop and amend the alias coverage** before inference; do not silently drop aliases after model outputs. Also confirm the pinned model returns exactly one projector hook and answer-only logits of length `Li` on one teacher-forced alias.
5. The runner must preserve all 16 planned contexts and all seven generation arms, score every frozen alias/condition, run grad/no-grad parity at each context, compare exact natural donor/full replacement suffixes, save all token IDs and per-token EOS likelihoods, **serialize each returned selected-row gradient tensor losslessly** with its hash/norm and dtype, and evaluate the strict crossing gate without selecting favorable cases. This core does not schedule runs or save artifacts.

The source tests establish control-flow and tensor-index correctness on a fake model. They do not show that real Voxtral's batch geometry, contextual alias encoding, singleton-state bit parity, backward memory, or Track B answer behavior passes.
