# Voxtral Track B answer-link core: source handoff

This source-only handoff follows the independently reviewed [V3 protocol](VOXTRAL_FP32_TRACK_B_ANSWER_LINK_PROSPECTIVE_V3.md), [V4 erratum](VOXTRAL_FP32_TRACK_B_ANSWER_LINK_PROSPECTIVE_V4_ERRATUM.md), and [design GO](VOXTRAL_FP32_TRACK_B_ANSWER_LINK_PROSPECTIVE_V3_PLUS_V4_INDEPENDENT_GO.md) at commit `5bf240d`. The core scorer uses the **prospective sequential B=1 alias topology** requested after that GO; it requires a separate V5 protocol amendment and independent review before any inference. Neither the core nor this handoff authorizes loading weights.

## Implemented in source

- [`voxtral_track_b_answer_link_core_v1.py`](voxtral_track_b_answer_link_core_v1.py) has no CLI, checkpoint loader, corpus reader or model construction. It accepts an externally supplied FP32 model, one checked processor batch, exact projector states, frozen rows and frozen aliases.
- It derives nominal projector rows from the PCM word slot; checks nonempty/in-range rows, finite matched FP32 states and donor mean direction; produces a seed-derived equal-norm random direction. This row rule is an index heuristic, not a time-localization result.
- Its hook validates Voxtral's flat `[B*T,3072]` projector output against the singleton source, edits raw `b*T+r` for every alias `b`, and returns the original flat order. It asserts one hook call, exact-zero bit parity, no outside-row changes, finite realized FP32 edit norm and at most 5% relative realization error. Full donor replacement is separate.
- The production class scorer runs **one B=1 model forward per alias**, with prompt plus `Li−1` answer tokens and `logits_to_keep=Li`, where `Li` includes EOS. It stores each complete alias's token likelihoods and log probability; class mass is `logsumexp` of those log probabilities. For gradients, it takes one source gradient per alias and softmax-weights them to obtain the exact class-mass gradient. Donor minus recipient yields `S0` and the directional Jacobian `J`.
- It validates contextual alias tokenization through a caller-supplied encoder of the **actual chat prompt plus assistant surface**. A standalone word encoding is rejected unless it matches that continuation. Generation captures the full greedy suffix, EOS, strict six-way class, alias coverage and hook evidence. Separate helpers enforce grad/no-grad per-token score parity, exact clean/zero and natural/full-donor suffix parity, and every V3 predicted-switch clause.
- [`test_voxtral_track_b_answer_link_core_v1.py`](test_voxtral_track_b_answer_link_core_v1.py) uses only fake CPU models/tokenizers. It covers contextual boundary rejection, word-row and direction validation, flat `B*T` indexing, one-hook rejection, zero/full controls, variable-length EOS scoring and answer-logit slice, sequential class mass, grad/no-grad parity, a finite-difference check of a multi-alias answer Jacobian, and exact switch clauses. Run with `python -m unittest models.second_architecture.test_voxtral_track_b_answer_link_core_v1 -v` in a Python environment with PyTorch. No real model or audio is used.

## Required integration before any candidate inference

1. Amend and independently review the V5 sequential alias schedule and time/memory caps. Maximum planned core calls with six aliases per word: **112 generations, 1,152 no-grad score forwards, 192 grad score forwards/backwards**, plus at most 16 unique natural captures and two old-FIT plumbing generations. Deduplicated aliases reduce actual calls; an execution ledger must record them. The V3 336-call batch estimate no longer describes this source path.
2. Obtain the actual independently audited **32/32 blinded human QA GO** and independent evidence review; bind its SHA-256 and all 16 selected WAV hashes to both the frozen Track B manifest and V3 table. The technical WAV fixture's `candidate_model_inference_authorized=false` remains a HOLD.
3. Build a separate no-weight preflight and bounded worker. They must freeze V5/protocol/source hashes, checkpoint/Transformers source, tokenizer and actual prompt/alias IDs, per-clip processor tensors and placeholder counts, exact masks and seeds, power/lid/clock admission, no-retry attempt identity, model FP32/eval/no-autocast state, MPS/disk/time caps, immutable result schema, and independent saved-data audit. Do not call this library directly on a live checkpoint before these gates pass.
4. Implement the processor-specific `contextual_encode` for each of six surfaces per word and prove its returned full IDs have the frozen prompt IDs as an exact prefix. If any alias changes that prefix or differs from standalone continuation IDs, **stop and amend the alias coverage** before inference; do not silently drop aliases after model outputs. Also confirm the pinned model returns exactly one projector hook and answer-only logits of length `Li` on one teacher-forced alias.
5. The runner must preserve all 16 planned contexts and all seven generation arms, score every frozen alias/condition, run grad/no-grad parity at each context, compare exact natural donor/full replacement suffixes, save all token IDs and per-token EOS likelihoods, and evaluate the strict crossing gate without selecting favorable cases. This core does not schedule runs or save artifacts.

The source tests establish control-flow and tensor-index correctness on a fake model. They do not show that real Voxtral's batch geometry, contextual alias encoding, singleton-state bit parity, backward memory, or Track B answer behavior passes.
