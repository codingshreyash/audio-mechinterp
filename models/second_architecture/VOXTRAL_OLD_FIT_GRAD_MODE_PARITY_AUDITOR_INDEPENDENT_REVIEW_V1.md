## Blocking gaps

1. **Saved batch is not independently pinned.** `audit_payload` accepts any finite feature tensor of the right shape, any token IDs preserving the audio-placeholder count, any binary attention mask, and arbitrary optional position IDs. Four separate synthetic mutations of a valid fixture—setting one attention-mask entry to zero, adding position IDs filled with 99, changing one non-audio input ID to 999, and changing one input-feature value to 12.5—each returned `audited_old_fit_fp32_graph_inference_parity_saved_data_only`. The runner requires the old-FIT mask to be all ones, and the protocol requires the same pinned task batch. The auditor needs independently known byte hashes for the complete batch field set and every batch tensor, or independent reconstruction and byte comparison to the pinned old-FIT input. At minimum it must reject the wrong mask and unexpected position-ID presence/content. Rehashing a changed batch only into the report does not establish its identity.

2. **Saved output size cap is not independently checked.** `audit_run` verifies that the sidecar size equals the value claimed in `result.json`, but neither that number nor the attempt directory is bounded against the protocol's 1 GiB output cap (or the runner's smaller worker cap). A self-consistent oversized sidecar can reach `torch.load(..., mmap=True)` and receive an audit report if its tensors validate. Check the actual sidecar and attempt-directory byte counts against frozen limits before loading, and bind the limits to the receipt. This gap follows directly from the source; I did not create a gigabyte-scale synthetic sidecar.

These findings do not invalidate the reported arithmetic on a valid bundle. They prevent the current auditor from independently confirming that the reported arithmetic belongs to the fixed input and within the fixed resource envelope. A corrected auditor and tests should be re-reviewed at new source hashes before any freeze or model launch.
