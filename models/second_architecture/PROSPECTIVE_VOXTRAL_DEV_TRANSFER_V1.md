# Prospective Voxtral development transfer: word-state loss and restoration

**Unfrozen proposal, 18 November 2026. No Voxtral development or locked-test model output has been opened for this proposal.** This document specifies a one-shot development test to be implemented, independently reviewed, and frozen with exact source and mask hashes before any development inference. It does not authorize an inference run by itself.

## Prior FIT result and question

The completed, independently audited [eight-record FIT assay](runs/voxtral_fit_v2_causal_full/20261118T0928Z/result.json), SHA-256 `e29a686e30505a69a3e4b26bddde606a02db753a3a5410c38432cdd14ac3baaf`, used the frozen [FIT design](VOXTRAL_FIT_V2_CAUSAL_DESIGN.md), SHA-256 `cd2cbd762af3568f85d43c2dec47824666a95d689a3dc89d9cbdf6471ef54ab0`, and [outcome decision tree](VOXTRAL_FIT_V2_OUTCOME_DECISION_TREE.md), SHA-256 `1f7b4a28bbaf8f6a65e6e667f427c65e4063f8afcba69ee63f9424aebc41fad2`. At each site, whole-word restoration succeeded in 16/16 eligible directions and valid lexical loss in 15/16. The strict **loss** time-preference gate passed at both sites. The strict **restoration** time-preference gate **failed** at both sites because malformed control answers left only 1–9/16 valid paired comparisons, below its required 14/16. Finite teacher-forced scores do not repair that failed FIT gate. All FIT outcomes are training-split evidence from synthetic speech and constructed feature/state edits.

The development question is whether the **complete-answer** restoration and loss effects, and the loss arm's strict time preference, transfer to new lexical pairs and phrasings without changing the intervention or answer policy. The development speakers use the same two TTS families as FIT, so a pass would show word/template transfer, **not independent speaker-family, human-voice, or acoustic-noise transfer**. The corpus is shared with Qwen; cross-model agreement would not be independent-stimulus replication.

## Population and firewall

Use only the `development` rows of the pinned [Voxtral CPU index](voxtral_corpus_v1_index.json), SHA-256 `bc739cf1f0d265426cc760ddd6a42223554b1097cab6ba87c2c8b81129d1b971`. Its metadata contain **12 whole word pairs** (three each in animal, color, nature, object), `piper` and `kokoro`, both `dev_listen` and `dev_hear` templates, and both directional recipient words: **48 matched pair/voice/template records and 96 planned directions**. These 24 development words are disjoint from FIT and locked-test words in the index. Select all 48 records in a deterministic `(category, pair_id, engine, phrasing_id)` order; no model-answer, ASR, waveform-quality, or first-template selection. Hash each selected WAV and PCM against the index before model load. Keep all 96 cases, including malformed or incorrect natural answers, in every all-planned denominator. Do not open the 12 locked-test pairs for model inference in this stage. Use locked-test metadata only for split disjointness checks.

Before inference, build and freeze a **development-only CPU mask manifest** for all 48 records. Reuse the FIT mask construction exactly: direct-overlap word mel frames; four half-open equal-duration word quarters; full-word-width pre/post intervals; encoder centers `320j`; projector centers `160(8r+3)`; and equal-count nominal-padding rows. Refuse unequal matched-pair row lists, empty bins, overlap, unsupported source shapes, or non-padding mel frame 2999. Verify identical PCM outside the word slot. The FIT mask file is a method reference, **not** a license to substitute FIT rows for development rows. Save the new mask builder and manifest hashes, plus a CPU-only independent review, before loading Voxtral weights. Do not change a failed development mask after seeing outputs.

## Frozen model path and intervention grammar to carry forward

Use the pinned `mistralai/Voxtral-Mini-3B-2507@3060fe34b35ba5d44202ce9ff3c097642914f8f3`, the same audited Transformers 5.20.2 source, BF16 MPS, audio-instruct user message, no system message, exact prompt `Answer the question in the audio with exactly one word. No explanation or punctuation.`, greedy `max_new_tokens=32`, and EOS ID 2. Require matched prompt token IDs and audio placeholder counts. Verify the pinned processor, tokenizer, model-shard, index, mask, runner, and runtime hashes before model load. Hook sites independently: audio encoder block 31 post-block/pre-final-norm (`[1,1500,1280]`) and post-projector (`[375,3072]`); no simultaneous site patches and no decode-step edit.

At every matched record/site, capture clean and blank states for both words. Make the blank by replacing only the recipient's direct-overlap word mel columns with its own nominal padded-silence column 2999; require bitwise identical features outside that word-frame mask. Run the same **six** feature inputs as FIT (two native, two word-versus-outside, two padding swaps), plus a blank baseline per direction. For both directions and each site, replay clean/blank with passive hooks and same-source self patches. Exact complete suffix-token parity is required for **96/96** per clean/blank passive condition and **96/96** per restoration/loss self condition at each site; any failure invalidates that site's causal gate. Capture source tensor hashes, hook count, shape, dtype, edited-row hash, effective BF16 edit norm, and unchanged-source checks.

For each direction/site, preserve both arms and all ten FIT patch conditions: whole word, four quarters, pre, post, padding, self, and one equal-norm random direction. Restoration patches the **matching clean recipient** rows into the blank recipient; loss patches the **matching blank recipient** rows into the clean recipient. Use the same single-scale equal-effective-BF16-norm rule and 5% tolerance for pre/post/padding/random controls as FIT, without iterative retuning. Define the new deterministic random seed from the low 63 bits of SHA-256 of UTF-8 `voxtral-dev-transfer-v1|{pair_id}|{engine}|{phrasing_id}|{recipient_word}|{site}|{arm}|random_0`; freeze the generator and row-major draw algorithm in executable code. Run the opposite-word clean-donor patch as a content control. The four word quarters are descriptive; there is no best-quarter selection.

For every generated condition save suffix IDs, decoded visible string, full special-token string, terminal EOS, nonterminal specials, classification, and the complete initial-capital candidate+EOS teacher-forced contrast `C=LL(recipient+EOS)−LL(opposite+EOS)`. For restoration, signed score movement is `C_patched−C_blank`; for loss it is `C_clean−C_patched`, so the whole-versus-control paired comparison uses the same base. Use **exactly the FIT answer policy**: only a single alphabetic word with one final EOS and no earlier special token can be `recipient`, `opposite`, or valid `other`; punctuation, quoted words, missing EOS, or extra special tokens are malformed. Casefold only after that surface check. A wrong or malformed blank answer is restoration-eligible only when the corresponding clean natural answer is a valid `recipient`; a correct blank answer is ineligible. For loss, the clean natural answer must be a valid `recipient`. Apply that same arm-specific eligibility to the whole-word and each control's binary success count; all directions remain in the **96 all-planned denominator** regardless. Teacher-forced scores may be finite for a malformed generated answer, but such an answer is **not a valid pair** for the strict time-preference comparison. Report finite-score-only comparisons separately as diagnostics without granting a time-preference label. This prospective reporting rule leaves the failed FIT restoration time-preference result unchanged.

## Planned workload and prespecified development gates

The fixed workload is **96 directions × two sites × two arms × ten patch conditions = 3,840** patched generations, plus **96** blank baselines, **288** feature generations (`48×6`), **192** opposite-word controls, and **384** passive replays: **4,800 complete generations or explicitly recorded invalid slots**. Expect **384** source captures (`48×2 sites×4 states`) and **at most 9,600** candidate teacher-forced forwards (two for each generated condition; invalid slots are not scored), for **at most 14,784** forward-like operations before load/preprocessing/I/O. Do not silently shrink the planned 4,800-slot denominator when a condition fails. Each record has the FIT grammar of 108 capture/generation/invalid rows; the complete run has **5,184 rows**. Checkpoint each record, bind every attempt hash, and independently audit all counts and score arithmetic before an outcome label is accepted.

The **effect-transfer gate** is separate for each site and requires all of the following:

1. All source, hook, feature, norm, resource, and passive/self parity checks pass; all 96 directions and 48 records are present. Any invalid main/control condition or missing score fails that site's gate rather than changing a denominator.
2. At least **80/96** clean natural answers are valid exact recipients, and at least **72/96** have both a valid exact-recipient clean answer and a non-recipient blank baseline. A malformed blank answer counts as non-recipient for this paired eligibility test but is reported by class and raw surface.
3. Whole-word restoration yields a valid exact `recipient` from that paired-eligible blank in at least **72/96 all-planned directions** and at least **75% of paired-eligible directions**. Whole-word loss yields a valid `opposite` or `other` from a clean-correct base in at least **72/96 all-planned directions** and at least **75% of clean-correct directions**. Malformed or missing-EOS outputs count as failures, not lexical loss.
4. For each arm, the whole-word primary success count strictly exceeds each pre/post/padding/random control count over the same 96 cases, and each control succeeds in no more than **18/96**. Report pair, voice, template and category rows without selecting a best subgroup; require at least **12/24** whole-word successes per category and **30/48** per voice and per development template in each arm/site.

**Both sites must pass all effect-transfer conditions** for a cross-site development pass. A one-site or one-arm result remains a precisely labeled partial result. Passing these effect conditions shows transfer of conditional restoration/operational loss under constructed edits, not a reusable lens or security property violation.

Preserve the FIT-compatible **strict time-preference gate** separately for restoration and loss at each site. Scale the FIT all-planned criteria to 96: whole-word complete-answer successes must strictly exceed each pre/post/padding/random control; its signed `C` movement must strictly exceed each control's movement in at least **72/96** paired directions, with at least **84/96** finite **and valid-complete-answer** pairs per control, no invalid main/control conditions, and no ties counted as wins. An answer that is malformed on either side makes that pair invalid for the gate even if both teacher-forced scores are finite. Because the FIT restoration time gate failed, **development restoration time preference is exploratory under this unchanged strict rule and is not required to pass the effect-transfer gate or to justify a later locked-test protocol**. The **loss** time-preference gate must pass at both sites to justify advancing this particular time-specific loss claim. Do not rename a finite-score-only restoration comparison as a pass, revise the FIT rule, or pool the two arms/sites.

The decision to draft a separately frozen locked-test assay requires the two-site effect-transfer gate **and** the two-site strict loss time-preference gate to pass on development after independent audit. If either fails, stop this protocol before locked-test inference and report the complete negative or partial result. Passing development only permits a new locked-test protocol review; it does not authorize opening locked test automatically.

## Resource bounds, audit, and interpretation

The FIT full run took **670.76 cumulative seconds** for eight records and peaked at about **9.94 GiB** MPS driver allocation. Six times that record count projects about **4,025 seconds (67 minutes)** for development before additional preparation. Before development inference, measure CPU-only preprocessing and calculate a conservative projection from the FIT per-record times plus setup; stop if the projection exceeds **120 minutes** or if memory is expected to reach **30 GiB**. The development runner has a **cumulative two-hour wall cap across attempts**, including load, preprocessing, failed attempts and resume work, and a **30 GiB MPS driver cap**, checked around every operation. Create the exclusive output directory and invocation timing receipt **before any preprocessing**, then update cumulative elapsed debt on every completed checkpoint or caught failure. A hard kill leaving a preprocessing or model-load invocation without a terminal elapsed receipt must fail closed on resume rather than reset the budget. An uninterruptible forward can overshoot an operation-boundary timer; record that limit. Require immutable elapsed-time error receipts, fail-closed resume after an unreceipted partial attempt, and an exclusive result path. No concurrent model, cloud instance, or dynamic case substitution. Incomplete work is reported as incomplete, not analyzed on its successful subset.

An independent CPU-only auditor must rehash all chosen inputs, masks, progress logs, checkpoint/result files, replay parity, all-planned denominators, strict answer classes, effective edit norms, and the gates above. It may check score arithmetic and provenance without a second model forward; label that limitation. Freeze its source before development inference. The already released FIT result and its failed restoration time-preference gate stay visible. A development pass would still use two synthetic voice families and a shared source corpus; follow-up human/accent/noise and naturally playable audio interventions need separate prospective studies. No constructed hidden-state patch is an attacker-controlled waveform or a security finding.
