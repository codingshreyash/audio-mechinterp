# Independent review: word-disjoint audio state validation V1

18 November 2026. Reviewed commit `6d7a5a4`, `WORD_DISJOINT_TIME_STATE_VALIDATION_PLAN_V1.md`, corpus-v1 specification and render-manifest metadata, and corpus-v2 render-manifest metadata. I did not open locked-test WAVs or answers, render audio, or run candidate-model inference.

**Decision: HOLD for candidate inference.** The corpus and matrix design are coherent, but two rules need a prospective amendment before implementation review and model runs. Source preparation can proceed only against a newly frozen amended design. This review is not a listening receipt or a runner review.

## Checks that pass

- The three cited SHA-256 values match the checked files: corpus-v1 specification `4c4cb6beafdd27509a073872f71dea004be686a6d8fafccbae410b8b11d7f265`, corpus-v1 render manifest `adf8cd02d24a43ef576bcb993dc54bd2527440a62798e12fc788def3c063971f`, and corpus-v2 render manifest `15395c7d132eb3f1c1a6b2b7d555146faa83be4ee2b77fba4f481cf70f26761d`.
- Track A uses all 12 corpus-v1 development pairs, the lexicographically first development template `dev_listen`, and both Piper and Kokoro voices. The manifest has 24 matching pair/voice rows and 48 WAV references. Both directions give 48 comparisons; S and C give 96 directed mode cells; six arms at the single post-block-11 site give **576** patched forwards and 96 clean model/mode forwards. The plan correctly calls this an exploratory reuse of development, not a fresh held-out result, and does not request locked WAVs.
- Track B freezes eight pairs with 16 unique casefolded words. The intersection is empty with each of corpus-v1 FIT, development, locked-test, and historical-exclusion word lists, and with all corpus-v2 rendered primary-pair words. This check used only JSON metadata. Piper Amy plus macOS Samantha are two synthetic TTS engines; Samantha is present in the local `say -v ?` listing. One template, two engines, and two words per pair give **32 WAVs**, 16 pair/voice cells, and 32 directed comparisons. The plan requires matching PCM outside the frozen word slot, distinct PCM within, pinned source and WAV hashes, and a 32-clip opaque-ID queue with two independent blinded listeners per clip and a third on disagreement.
- Track B's proposed matrix is arithmetically correct: Wav2Vec2 has 32 directions × two S/C modes × two sites × six arms = **768** patches plus 64 clean forwards; Whisper has 32 directions × two sites × six arms = **384** complete decodes plus 32 clean decodes. Self/full and random-region controls, no-weight preflight, independent source and saved-data audit, all-planned denominators, and reporting partial/negative outcomes are specified. The plan does not claim that state transfer is an attacker-reachable security exploit.

## Required amendments before runner freeze

1. **Freeze an executable clean-transcript eligibility and listening normalization rule.** “At the reference slot” has no defined meaning for a full ASR transcript without timestamps or an alignment algorithm; “punctuation/space removal by tokenization” also leaves multiple possible parsers. Specify one exact Unicode normalization and token-splitting function, then an exact token-position or full-template criterion for each baseline. For example, require normalized tokens to equal `i said {word} and then stopped` for each member of the pair, with the word at position three and the paired alternative absent; or specify and freeze a different deterministic rule. State whether the same function judges human full transcripts. Test boundary cases such as repeated target word, paired alternative elsewhere, punctuation, omitted template words, empty output, and Unicode variants before seeing candidate outputs. Preserve all raw transcripts and planned cases even when ineligible.
2. **Prove the 512-MiB output cap before inference.** The prior reviewed Wav2Vec2 complement run wrote 166,918,747 bytes for 192 patch rows, including 384 full patched-state sidecars. Scaling that storage pattern to 768 arms would write about 668 MiB before new clean-state sidecars and exceed this plan's cap. The amended plan or runner preflight must list exactly which clean states, logits, IDs, and edit receipts are retained; compute a conservative per-file and total byte upper bound from the complete case enumerator and measured tensor shapes; and fail closed if the bound exceeds 512 MiB. Reconstruction and independent audit must remain possible without storing each full patched state. The 30-minute and 4-GiB limits can remain hard stop conditions that produce an explicitly partial, nonclaim-bearing run.

After these amendments, independently review the concrete renderer, paired-PCM auditor, candidate runners, complete-case enumerator, hash-bound no-weight preflight, fake-model tests, and resource estimate. Track B inference additionally requires the independently audited 32/32 listening receipt. The existing HOLD applies to both tracks' candidate inference; it does not imply that the arithmetic or word-list selection failed.
