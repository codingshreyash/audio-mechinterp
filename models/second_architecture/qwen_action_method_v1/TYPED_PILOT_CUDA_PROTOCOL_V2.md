## Exact active checkpoint bytes

`TYPED_PILOT_CUDA_HF_SNAPSHOT_MANIFEST_V2.json` records the **18 files at the pinned HF revision** `f75b40e3da2003cdd6e1829b1f420ca70797c34e`, including `config.json`, `chat_template.json`, `preprocessor_config.json`, `generation_config.json`, tokenizer files, `model.safetensors.index.json`, and all three weight shards. The manifest was obtained from the [official HF revision API](https://huggingface.co/api/models/Qwen/Qwen2.5-Omni-3B/revision/f75b40e3da2003cdd6e1829b1f420ca70797c34e?blobs=true): large-file expected digests are HF LFS SHA-256 values; small-file expected digests were SHA-256 of the revision's `resolve/` bytes. An independent reviewer must verify this manifest and its provenance before any GO. `verify_snapshot()` uses an offline HF snapshot resolution, requires the exact revision directory and complete 18-file inventory, and streams SHA-256 over every *active cached file*, including 11.99 GB of shards. Its result binds the absolute snapshot path and manifest hash to `source_identity` and each GO. Source admission, parent pre-attempt validation, and the worker after nonce all rehash those bytes. The worker feeds that **verified local path directly** to both processor and Thinker `from_pretrained`; it does not resolve the model ID again at load time. The worker's after-nonce hash is its immediate pre-load check. Hashing consumes wall time and may cause the 180-second load-only stage to fail; such a failure is preserved and requires a fresh reviewed protocol. `local_files_only=True` and offline worker flags remain mandatory.

V2 verifies the wheel digest and each installed torch shared binary against the verified wheel's RECORD. It hashes installed `tokenizers`, `safetensors`, `triton`, the required CUDA runtime/cuBLAS/cuDNN binaries, and every installed NVIDIA CU12 distribution with shared libraries; their versions and hashes are bound to the independent GO. The installed Transformers Git commit and pinned Qwen modeling/processing source bytes remain checked. If any binary or wheel is missing or differs, admission stops before weights. V2 explicitly disables CUDA matmul and cuDNN TF32, sets float32 matmul precision to `highest`, requires default FP32, records cuDNN version, and checks the resulting math mode at load, each VJP, and generation samples. CUDA and MPS numerical outputs are compared only within their own backend.

## Exclusive A100 admission

At `--capture-admission`, before creating a stage attempt, immediately before launching its worker, and after worker exit, V2 queries the full physical GPU inventory and compute-process list with `nvidia-smi`. It requires one physical A100 80GB, MIG **Disabled**, no compute process, and idle used VRAM **strictly below 512 MiB**. The exact UUID, name, memory size, driver, CUDA version, math mode, reviewed `gpu_baseline`, and isolation policy are bound to the stage GO. The stage-start inventory is fsynced and hashed into both parent and worker start receipts; the saved auditor verifies pre/start/post isolation records. If a competing job or 40-GiB baseline appears, the GO check rejects before attempt creation or the stage-start gate stops before worker launch. During execution, process-tree RSS and total GPU memory are sampled; monitor errors invalidate the attempt. The parent itself avoids creating a CUDA compute context before the isolation probe.
