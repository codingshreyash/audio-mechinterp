# Qwen2.5-Omni-3B typed/audio action-label method rehearsal V1

19 November 2026. **Source-only protocol; candidate inference on HOLD.** This is a smaller same-checkpoint method rehearsal while the [primary VoiceChat native-function study](../VOICECHAT_ACOUSTIC_ACTION_PROSPECTIVE_V2.md) awaits timing, human listening, and live parity gates. It does not revise or reopen the earlier Qwen corpus V1 [failed development Stage A](../../../eval/audio_jlens/corpus_v1/STAGE_A_RESULT_INDEPENDENT_REVIEW.md), and it does not open that study's locked test. The 2026 [audio Jacobian Lens paper](https://arxiv.org/html/2609.33458v1) already showed Qwen2.5-Omni-7B audio readouts and some complete-answer changes; a generic first-audio-lens claim is unavailable.

## Question and claim boundary

**Question:** for the same words and system instruction, where in the pinned Qwen Thinker is a three-way calendar *intent label* decodable from typed versus spoken input, and can replacing the audio-derived state change the model's **entire EOS-complete label response** under controls?

The three labels are `LIST`, `ASK`, and `CANCEL`. They describe whether the user's words ask only to view, require another confirmation, or explicitly confirm cancellation now. They are **text classifications**, never native tool calls or executed calendar changes. An incorrect `CANCEL` label would be a task error. It would require a separately justified tool/harness path before it could be called a security consequence. VoiceChat's native function stream is the primary action endpoint.

## Frozen source corpus and no-leakage split

[`frozen_spec_v1.json`](frozen_spec_v1.json) fixes the model/Transformers revisions, the single system prompt, 30 manually written English requests, labels, EOS ID and generation cap. [`endpoint.py`](endpoint.py) verifies the split and source hashes without importing model weights. Every request refers to the same date, 19 November 2026; those words are task context, not a live clock. No event list or real calendar is supplied. The model must produce only one label.

| Split | Wording | Input forms | Voice | Source units |
| --- | --- | --- | --- | ---: |
| FIT | Six separate phrasings per label | Typed only | None | 18 text requests |
| Development | Two new phrasings per label | Typed plus same-word speech | Piper `en_US-amy-medium` | 6 scripts / 6 WAVs |
| Locked | Two further new phrasings per label | Typed plus same-word speech | macOS Samantha `en_US` and Kokoro `af_bella` | 6 scripts / 12 WAVs |

The exact full script text and ID occur in one split only; `plan.py` fixes all 18 audio source cases and all inter-class donor pairs before a candidate answer. FIT never contains audio. Development and locked scripts are disjoint from the old Qwen V1 *one-word lexical-pair* corpus: these are new calendar authorization sentences with a three-class whole-response task, a new prompt and new source recordings. The old rank-16 map's negative gate remains a negative result and is **not** carried forward as a validated reusable mapping. The held-out group changes wording and voice together, so a positive locked result supports joint transfer and cannot isolate either factor. The two locked voices are still synthetic; no human-speech generalization follows.

Before any candidate inference, freeze the exact TTS engine packages/model or OS voices, rendered raw files, conversion source, and SHA-256. Render each whole script independently to mono signed PCM16 at 16 kHz; append zeros to exactly **16.0 seconds** (256,000 samples), with no trimming or tempo change. A script longer than 16 seconds fails the source version; do not speed it up or choose a replacement after model output. The fixed duration is intended to make full audio-state donor shapes comparable, but the actual processor placeholder and projection counts must be checked live. No result is selected or discarded for convenient model behavior.

Two English-fluent reviewers independently hear **all 18 opaque WAVs**, in separate randomized queues, without scripts, labels, split, ASR, or model output. They first lock a verbatim transcript and critical fields: `show/list only`, `possible cancel plus wait`, or `explicit confirm now`, plus date and Design Review where present. Reveal source wording only after their transcripts are locked. A third reviewer handles critical disagreement. All 18 source units must be intelligible with the case-critical meaning intact; failures stay in the denominator and put the planned candidate run on HOLD. Human model-blind timestamps of the critical phrase and an equal-width displaced speech interval are required before any later *local time-row* patch. This protocol freezes wording and source identities, **not yet WAV bytes, timing, or human verdicts**. The candidate run cannot begin from this document alone.

## Exact baseline and complete-response endpoint

Reuse the pinned [Thinker adapter](../../qwen_omni/adapter.py) and [source pathway map](SOURCE_MAP_V1.md). The typed user message contains exactly the script text. The audio user message contains exactly one audio item with those spoken words and no added text; both use the identical system prompt. The processor's chat template may expand different numbers of tokens; record those IDs and the raw feature mask. Use `do_sample=false`, `use_cache=true`, `max_new_tokens=12`, tokenizer EOS `151645`; record every generated token ID, both special-token and plain decodes, prompt length, stop reason and timing. A live pilot must verify tokenizer EOS and all resolved generation defaults before batch execution.

The primary observed endpoint is one of the three labels **followed by terminal EOS** and nothing else except surrounding whitespace. [`score_complete_answer`](endpoint.py) rejects a missing EOS as `censored`, and extra words, special tokens, multiple labels or a wrong token path as `malformed`; those outcomes remain in denominators. A restricted first-token `LIST` versus `CANCEL` logit margin, a model-written explanation, and a likelihood score cannot substitute for this full answer. Save the complete typed/audio 2×2 table by script, label, and voice; report incorrect complete labels separately from malformed and censored outputs.

The *task feasibility* development gate is fixed before outputs: at least **5/6** typed and **5/6** audio development responses must be the intended exact label+EOS, with no missing source. If it fails, report the task failure and do not open locked responses. This small gate is a feasibility screen, not a population accuracy estimate. The locked group remains sealed until human QA, source/runner independent review, live parity and resource admissions, and this development gate all pass.

## Readout and causal order

1. **Representation readout.** Fit only on the 18 typed FIT prompts, capturing the final prompt-token residual at the fixed shared Thinker sites `text.residual.17` and `text.residual.35`. Evaluate unchanged fit, development typed, development audio, then locked typed/audio only if gates pass. Fix the exact estimator, its hyperparameters, target sequence scoring and permutation baseline in a separate source-only runner amendment **before any candidate output**. An ordinary linear class probe is a decodability diagnostic. A Jacobian Lens map must be identified as such and compared with zero and simple-probe baselines; it cannot inherit the failed old Qwen rank-16 map. Report balanced accuracy and raw scores for all cases, including wrong/malformed generation. A readable label state does not prove the model used it.
2. **Audio-to-answer influence.** For each spoken case, measure a full-sequence teacher-forced score `log P(label + EOS)` for all three labels at fixed prompt and decoding state. Different label token lengths require full-sequence scoring, not first-token alias scores. Calculate a local derivative from the `audio.to_language` projected audio state to the three full-sequence scores. Save vector norms, row distribution and a zero-edit replay; a finite derivative is still a local sensitivity measurement, not a complete response change or reusable map.
3. **Complete-response intervention.** [`plan.py`](plan.py) freezes nine cross-label source pairs, two directions per pair, five arms per direction: exact self, full projected donor, a same-label donor from the other wording, and two independently seeded equal-L2 random edits. This is **90 planned edited forwards**, 30 on development and 60 on locked, plus separate stock/no-hook/read-only baselines. All pairs are same split and voice; every original WAV must be exactly 16 seconds. The full projected donor is allowed only when audio feature, placeholder and projected-state shapes match exactly and the recipient prompt differs only through those projected audio values. Require no-hook/read-only/self exact **complete token path** parity, then full-donor exact donor-path parity. If full donor fails, report that site as insufficient and do not promote a narrower claim. Random arms use `PCG64` seeds from `plan.py`, scaled to the exact donor-minus-recipient L2 norm; record realized norms and tensor hashes. Same-label donors test generic disturbance from another naturally generated state. No donor or site may be chosen using its observed answer.
4. **Time localization is a later gate.** The existing encoder-layer and projection hooks can capture states, but their row-to-WAV map must be derived from pinned source and verified against human phrase timestamps before a decision-window versus displaced-window test. Do not call the entire 16-second active array a narrow decision phrase. No local-row intervention or late shared-state swap across divergent histories is authorized by this V1 schedule.

The primary causal endpoint is **complete donor label+EOS transfer**, conditional on the donor itself producing its intended complete label and exact full-donor parity. Each of the 18 directions stays in the all-planned denominator; report eligible and ineligible directions separately. The same-label donor and both random edits must not make the donor target label in a credited direction. Report category, wording, voice and site rows; correlated reverse directions and two locked voices are not independent random samples. A score shift without an EOS-complete transfer is a score finding only. A full-donor transplant is a white-box sufficiency test, never an attacker-suppliable waveform attack.

## Resource, source and failure gates

The previous Qwen short MPS studies measured roughly 18.6–21.3 GiB of driver allocation, but the 16-second inputs and 12-token generations have not been measured. Before a batch, run exactly one development, no-patch resource pilot under a separate reviewed launch: Mac on AC, lid open, no thermal event, MPS allocation below **24 GiB**, process tree RSS below **30 GiB**, and total pilot wall time below **300 seconds**. A breach aborts and preserves the failure. A later candidate launch needs a separate run cap and independent executable review; do not run Qwen concurrently with other memory-heavy jobs. The stopped H100 VoiceChat instance stays stopped.

No candidate weights were loaded to create this protocol. The five source/endpoint tests and one schedule test are fake/no-weight checks. They do not attest tokenizer behavior, model parity, label accuracy, lens validity, resource fit, or a security vulnerability. Keep every source failure, audit correction, null result and census visible. The next concrete step is source-only independent review, followed by TTS byte freezing and two-listener QA; candidate model inference remains on HOLD.
