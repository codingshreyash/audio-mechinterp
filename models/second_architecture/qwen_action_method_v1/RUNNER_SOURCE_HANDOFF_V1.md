# Qwen action method runner evidence contract V1

19 November 2026. **Source-only; candidate inference on HOLD.** This contract is a small, executable, no-weight check for a future runner. It uses the independently reviewed [method V3 gate](INDEPENDENT_METHOD_V3_SOURCE_REVIEW_GO_20261119.md), the fixed V1 scripts, V2 target-restricted readout, and the real 18-WAV source render. It does not load Qwen, produce a candidate answer, grant a development/locked-test reveal, or change the [failed earlier Qwen Stage A result](../../../eval/audio_jlens/corpus_v1/STAGE_A_RESULT_INDEPENDENT_REVIEW.md).

Run from the repository root with the pinned TTS environment, which can read the source audit but does not load Qwen weights:

```sh
eval/tts/.venv/bin/python -m models.second_architecture.qwen_action_method_v1.runner_contract_v1 --source-preflight
eval/tts/.venv/bin/python -m models.second_architecture.qwen_action_method_v1.runner_contract_v1 --show-plan
eval/tts/.venv/bin/python -m unittest models.second_architecture.qwen_action_method_v1.test_runner_contract_v1 -q
```

The first command re-runs the reviewed technical source and blind-bundle audits; it checks 18 rendered source cases, 54 raw/converted/final files, 36 blinded copies, source hashes, and the stored byte-audit result. It intentionally reports `candidate_inference_authorized: false` and `human_reviews: 0`. `--pilot`, `--run-development`, and `--run-locked` explicitly fail. They are reserved names for a later independently reviewed backend, not hidden execution paths. The plan lists one typed FIT resource-pilot case, 18 typed FIT cases, six typed and six Piper-audio development cases, and six typed plus twelve two-voice locked cases. A future development runner may not open `H_*` audio or answers before a passing V3 gate and a separate locked-run GO.

## Minimum future runner sequence

1. **Admission before model load.** Bind the exact source and readout hashes, the independently audited WAV/bundle hashes, an independent 18/18 two-listener wording QA receipt, the runner source hash and an independent executable GO. Record host AC, lid-open and thermal-log evidence. The present contract has no human QA schema or runner GO, so it cannot pass this admission.
2. **One typed FIT resource pilot.** Use `F_L1__typed`, the pinned Thinker and processor, deterministic generation, and three fixed teacher-forced targets `LIST+EOS`, `ASK+EOS`, `CANCEL+EOS`. Record full prompt IDs and hash; each target's teacher-forced input must be those prompt IDs plus its one label token, with logits from positions `prompt_len-1` and `prompt_len`. Save both complete FP32 vocabulary-logit vectors, prompt-last post-block states and score VJPs at `text.residual.17` and `.34`, exact hook counts, and complete generated IDs. `validate_teacher_forced_triplet` recomputes all three full label-plus-EOS scores from logits and requires the prompt-last state to agree across suffix passes within `1e-5`. This is **three scalar VJPs**, not a full Jacobian. Limit the pilot to 300 seconds, sampled MPS driver allocation below 24 GiB and sampled process-tree RSS below 30 GiB, with separate saved host-log checks. The numerical validator alone cannot prove the host was healthy.
3. **FIT then development.** Only after a separately reviewed pilot, collect all 18 typed FIT records in frozen order (54 total scalar VJPs), with a whole-job 3,600-second cap and durable per-case evidence. Fit the frozen rank-at-most-three mean-VJP plus constant/ridge comparisons from those records; no audio fitting or prior failed rank-16 map reuse. Evaluate all six typed and six same-word Piper-audio development cases, saving complete generated token IDs and all three teacher-forced full-sequence scores. Use [V3 gate](gate_v3.py) directly on raw token and score records; do not supply predicted labels or canonical flags as claims. A score shift without a complete label-plus-EOS answer is a score result.
4. **Causal controls and locked firewall.** The V1 audio-junction schedule and V2 prompt-last direction schedule remain separate causal questions. Before any narrow intervention, require stock/instrumented no-hook/read-only/self exact **complete token path** parity, then full projected donor exact donor-path parity for the junction study. `validate_complete_controls` re-derives label/termination from raw IDs and checks these exact paths. Save hook call counts, all prompt and feature IDs, tensor shapes/hashes, realized edit norms, raw logits and every censored/malformed output. A failed parity gate stops interpretation and remains a failed record. Locked items require the independent human QA, successful development V3 gate, separate resource and executable reviews, and a new bound GO; no locked answers have been opened here.

Every future candidate run needs an immutable attempt directory with start, per-forward progress, saved tensor references, terminal completion after fsync, post-host evidence, and a separate read-only saved auditor that rehashes and reconstructs each score and edit. Partial, failed, late, over-cap, or missing evidence must stay visible and cannot be pooled as a completed run. The 18 WAVs are technically byte-bound; technical integrity is not human intelligibility. No model-origin action or security consequence has been measured by this contract.

**Current tests:** six no-weight tests cover the real source preflight, split firewall, full-sequence score and prompt-state alignment, teacher-forcing target/hook/position tampering, raw-token control parity and false label assertions, resource caps, and candidate-entrypoint refusal. They load no Qwen weights. A future real backend, host/evidence protocol, human QA auditor and independent executable review remain necessary before candidate inference.
