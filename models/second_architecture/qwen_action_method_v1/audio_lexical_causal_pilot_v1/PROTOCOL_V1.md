# Prospective Qwen audio lexical-state pilot V1

**FIT-only synthetic speech. No model-weight result exists at source freeze.** This method pilot asks whether a donor audio state from one spoken color can change a complete answer to a matched recording at two Qwen2.5-Omni-3B Thinker boundaries. It is not a calendar, tool-call, multilingual, human-voice, or security test. The checkpoint is pinned to `f75b40e3da2003cdd6e1829b1f420ca70797c34e`. A prior 16-second non-study Qwen run established H100 resource feasibility and passive-hook parity for one unrelated Apple clip; it did not establish this pilot's baselines or hooks.

## Frozen source and processor-only observation

The source-controlled Piper red/blue WAVs are each PCM16 mono 16 kHz and 49,724 samples, with original difference confined to PCM samples `[18082,26626)`. `render.py` zero-pads both to exactly 256,000 samples. The original pair is retained unchanged. Its pinned Qwen processor features differ in 29,972/30,000 frame columns, including a `0.067305088` floor shift throughout all 28,400 padded columns, although the PCM difference is short. Pinned `WhisperFeatureExtractor` applies a per-utterance max-relative log-mel clamp; the blue word changes the maximum and hence the floor. This is an audio-preprocessing observation, not a model behavior result.

Before any model-weight call, `calibrate.py` applies exact nearest-even integer gain `73/100` to **both** original word slots only, with no other PCM edits, yielding two separately named 16-second WAVs. `PROCESSOR_ONLY_RECEIPT_V1.json` binds the pinned processor outputs: red and blue calibrated input IDs/masks are identical, active mel count is 1,600, and the feature arrays differ in precisely 41 columns `[118,159)`, bitwise equal outside including padding. The original red/blue pair remains a separate observational baseline. The calibrated word is quieter; its recognizability has not been shown. Neither pair has independent human lexical QA. Source-controlled TTS provenance and these processor facts do not substitute for an observed model answer. `plan.py` verifies all WAV, manifest, and receipt hashes before inference.

The same audio-only user content and system instruction are used for all four WAVs: “Listen to the audio. Reply with the single color word spoken, and nothing else.” The prompt contains neither candidate word. Pinned no-weight geometry is `[1,432]` input IDs/mask, `[1,128,30000]` features, `[1,30000]` feature mask, 400 contiguous audio placeholders at positions 26–425, 800 encoder rows, and 400 projected rows. The Mac processor receipt is frozen as source evidence. Pinned Whisper STFT/mel arithmetic is not byte-identical across Mac and Dallas, as the prior V2 Apple pilot showed. Before model weights, Dallas admission must reconstruct all four batches and bind its own **complete** processor receipt. It must match the Mac receipt on every token, mask, prompt, shape, and time-geometry field while allowing only the `input_features` tensor hash to differ. On Dallas, calibrated pair features must have exactly 41 differing columns `[118,159)`, zero difference outside including padding, equal finite pair maxima and floors, and nonzero finite difference; failure stops admission. The worker and saved auditor compare full runtime records and tensor sidecars against the admitted Dallas receipt. This cross-platform rule is prospective and does not weaken same-machine integrity. No calendar `D_*`/`H_*` clip is used.

## Site and row meaning

`audio.pre_attention.0` is the input `hidden_states` to `audio_tower.layers[0]` after conv2, GELU, positional addition, and valid-index packing, **before** its first self-attention. It is a forward *pre-hook*; a normal layer-0 output hook would be too late. The pinned `chunk_and_pad_features` splits into 200-mel-frame chunks, giving 100 packed pre-attention rows per full chunk. Conv1 `k3/p1` and conv2 `k3/s2/p1` expand mel support `[118,159)` to conservative pre-attention rows `[58,81)` in the first chunk. The first-chunk window is `[0,100)` and same-chunk relocated window `[0,23)`. Expected full state is `[800,1280]`.

`audio.to_language` is the output of `audio_tower.proj`, after encoder self-attention, pooling, and layer normalization, in language-model width. Nominal pooled word rows are `[29,41)`; the first-chunk window is `[0,50)` and same-chunk relocated window `[0,12)`. Expected full state is `[400,2048]`. Attention can distribute information throughout the first chunk. A positive at this site does **not** localize a phoneme to `[29,41)`. These row windows were fixed from source geometry and no-weight features before observing any model answer.

## Frozen generation and causal schedule

Use FP32, disabled TF32, greedy decoding, and `max_new_tokens=24`. Save raw token IDs, decoded suffix, full first-step logits for baselines, stop reason, and terminal EOS ID 151645. A complete calibrated baseline must be exactly one intended color word (case insensitive; optional final period and surrounding whitespace) followed by EOS for **both** directions. A censored or unexpected answer is a valid negative baseline record and stops intervention; no word-specific post-selection. First capture stock calibrated red and blue answers. Capture read-only site states on no-cache forwards and require full first-logit agreement within `1e-5` and exact read-only generated paths for both. An observational stock answer is also recorded for each uncalibrated original WAV under the same prompt, without treating original/calibrated differences as solely a normalization effect.

For each site and each direction (red recipient/blue donor, blue recipient/red donor), run the following predeclared arms with a fresh model generation call, one hook firing on the prompt audio state, complete token path and EOS endpoint:

1. `local_donor`: replace only the fixed local rows with donor rows.
2. `chunk_donor`: replace the whole first attention chunk with donor rows; this tests spread within a chunk.
3. `full_donor`: replace all rows with donor rows. Its complete path must match the stock donor path exactly, or the causal interpretation fails.
4. `self`: copy the entire recipient site state through the hook. Its complete path must match the stock recipient path exactly.
5. `relocated_delta`: add the donor-minus-recipient local-row delta to the same-width **non-word window in the same first chunk**. Require a nonzero delta and equal realized L2 edit norm.
6. `equal_l2_noise`: add deterministic seeded noise to the local window with the same realized L2 norm as the local donor edit. Save seed and realized norms.

Capture live prepatch state and compare it to the no-cache recipient source before each arm; save full-state maximum absolute and L2 differences and reject any maximum absolute difference above `1e-5`. Require the donor-minus-recipient **local** edit to have L2 norm at least `0.01` at each site/direction, and require live prepatch drift L2 no greater than 1% of that edit; otherwise stop as numerically inconclusive. Save each arm's **full** effective edited-state delta `(patched - live)` as a hashed float32 sidecar. The saved auditor must verify exact zeros outside the declared window, reconstruct the expected donor, relocated, self, or seeded equal-norm edit from the frozen source states, and compare the full sidecar, allowing only the predeclared live-source drift bound where relevant. On calibrated inputs, source states outside the fixed pre-attention local window and outside the first projected chunk should also agree within `1e-5`; a larger difference stops attribution as unexpected spread or nondeterminism. No generated response is used to choose rows, noise, prompt, gain, or candidate words. Save all arms regardless of whether local/chunk edits change the answer, unless a precondition or resource cap fails. A baseline, no-hook/read-only, self, or full-donor control failure stops attribution and is preserved as a failure. Endpoint scoring is based on complete generated suffix plus EOS, not a first-token score alone. A successful local or chunk transfer in this single FIT pair would be a white-box representation sufficiency observation, not evidence of generalization or attacker reachability.

## One-shot executable gate

Source-only tests and independent source review precede an isolated one-H100 no-weight admission. A separate independent executable review and later committed one-shot GO must bind exact source bytes, four WAVs, manifests, processor receipt, snapshot, Torch/CUDA binaries, Slurm job/node/GPU UUID, and fixed `runs/audio_lexical_causal_pilot_v1/attempt_001`. The attempt path must be absent at launch. The same local-owner parent-pipe/nonce liveness boundary from the reviewed V2 technical pilot applies; it is not cryptographic proof against a malicious local owner. Caps are 900 seconds including terminal reserve, sampled physical GPU use and PyTorch reservation below 60 GiB, process-tree RSS below 24 GiB, and whole attempt evidence below 256 MiB. Missing samples, changed inputs, cap crossing, failed worker, broken receipt, or unreviewed code invalidate the attempt; no silent rerun into the fixed path. A source-only or processor-only check never authorizes inference by itself.

The saved auditor must check the raw parent/worker/terminal/resource receipts, every sidecar hash/shape/dtype, exact processor reconstruction, all scheduled paths and hook counts, baseline/EOS and parity gates, realized edit norms, and explicit no-security scope. Independent raw review follows. A result on this pair cannot establish a reusable Jacobian lens or a security vulnerability; the next lens study must fit an audio-source-to-terminal-state map on disjoint words/voices and validate on held-out audio.
