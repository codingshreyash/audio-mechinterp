# Independent source review: Slurm step GPU fallback

19 November 2026. **PASS for the source-only allocation amendment frozen at `9e36408`; HOLD admission and model weights until the separate live no-weight capture and fixed executable review.** This is an addendum to `INDEPENDENT_EXECUTABLE_SOURCE_REVIEW_V1.md`, not the gate's fixed `INDEPENDENT_EXECUTABLE_REVIEW_V1.md`. No admission, GO, attempt, or model inference was created by this review.

The no-weight cluster probe observed `SLURM_JOB_GPUS` empty, `SLURM_STEP_GPUS=0`, `SLURM_GPUS_ON_NODE=1`, `CUDA_VISIBLE_DEVICES=0`, and one visible idle H100 80 GB. This is consistent with Slurm's documented distinction: [job GPU IDs](https://slurm.schedmd.com/sbatch.html) are set for batch/interactive jobs, whereas [step GPU IDs](https://slurm.schedmd.com/srun.html) are set for other job steps. The amendment accepts the observed single step ID only when the job field is empty. It requires one GPU on node, one strictly parsed ID in each populated field, and equality when both fields are populated. Both empty, either multi-GPU field, or conflicting job/step IDs fail closed.

`runtime_identity()` records both raw fields and the selected source/value. Admission and GO bind the full runtime identity; parent and worker recheck it, alongside the Slurm job/node, visible physical H100 UUID, CUDA/package state, and cached snapshot. The global Slurm GPU ID is deliberately not compared to the local CUDA ordinal `0`, which can be remapped by a device cgroup. The physical UUID and one-visible-GPU checks supply the device identity within this trusted local-owner test.

Independent checks at `9e36408`: **10/10 no-weight tests passed** with `ResourceWarning` treated as an error; direct probes accepted `('', '0', '1')` and `('0', '0', '1')` and rejected `('0', '1', '1')`. `gate.source_identity()` returned 29 clean tracked source hashes. This amendment changes bound source bytes, so any admission made before `9e36408` would be stale; the live admission must be captured and committed after this freeze. No remaining source blocker was found for that no-weight admission. If the step GPU field is absent in the actual launch context, the gate correctly stops instead of guessing from CUDA visibility.
