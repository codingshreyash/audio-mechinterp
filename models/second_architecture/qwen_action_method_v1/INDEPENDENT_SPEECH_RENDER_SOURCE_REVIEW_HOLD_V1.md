# Independent source review: Qwen action speech renderer V1

19 November 2026. **HOLD on real TTS rendering under commit `0b88445`.** This is a source and fake-data review only. I loaded no Qwen weights and rendered no real speech. The planned 18-source population and two-listener design are useful, but the saved byte auditor is guaranteed to reject the current renderer output. The source and completion evidence also need stronger binding before an independent result claim.

## Checks performed

- `eval/tts/.venv/bin/python -m unittest models.second_architecture.qwen_action_method_v1.test_render_sources -q` passed **2/2** no-weight tests. `py_compile` passed for `render_sources.py`, `audit_sources.py`, and `listening_bundle.py`.
- The source plan contains six Piper development recordings and six each of Samantha and Kokoro locked recordings. The renderer uses the previously pinned VoiceChat TTS implementation. Its conversion path rejects nonfinite/silent input and quantization clipping, writes mono 16-kHz PCM16, refuses a converted clip that reaches 256,000 samples, and appends exact zeros to that frame count. The reused TTS constructor checks installed package, asset, OS-build, voice and `say` binary pins. These are source checks, not real audio quality results.
- The pre/post host helper requires AC power, an open lid and a power log free of sleep/wake/thermal events. The renderer starts a 900-second alarm, writes start/failure/manifest records, and checks a 200-MiB file total after each case. It records peak self/child RSS but has **no RSS admission threshold**. The manifest's elapsed time is measured before its final write; the auditor does not require a post-manifest terminal receipt.
- I ran a fake 18-case render using an in-memory one-second constant PCM TTS substitute and fake host probes. It wrote 54 audio files and 18 manifest rows. The unchanged auditor then raised `ValueError: render case/word/voice changed`. The fake files and exact failure receipt are preserved at `runs/FAKE_SOURCE_REVIEW_DO_NOT_USE_v1/`; they are **not candidate sources**. A separate fake copy with only `id = case_id` added to each manifest row passed the remaining byte reconstruction and produced two distinct opaque listener queues. This narrows the immediate failure to the row-key mismatch without treating the modified copy as a production pass.
- In a third fake copy, I added `failure.json` beside an otherwise audit-passing manifest. `audit_sources.audit` still returned `technical_bytes_pass_human_review_pending`. That copy is `runs/FAKE_SOURCE_REVIEW_FAILURE_ACCEPTED_v1/`. The fake test patched host validation, so it is evidence about auditor logic, **not** live power behavior.

## HOLD findings and exact corrections

1. **Fix the inevitable case-ID mismatch.** `expected_sources()` includes `id`; `render_sources.render()` records the same value as `case_id` but omits `id`. `audit_sources.audit()` compares *all* expected keys against the row before separately checking `case_id`, so all real attempts fail. Compare only the shared source fields and explicitly require `row["case_id"] == plan["id"]`; add a fake complete 18-case render-to-audit test.
2. **Reject failed or partial attempts.** A manifest plus `failure.json` currently passes the saved auditor. Reject any failure receipt and require a terminal completion receipt written and fsynced *after* the manifest, with its hash and a post-write deadline check. The auditor should verify that receipt's hash/time and the absence of failure before saying technical bytes pass. Preserve the original failed attempt if a write or alarm fails after manifest creation.
3. **Bind the reviewed source, not a self-repin.** `source_identity()` records current hashes of the Qwen spec, plan and renderer, but compares none of these to an independently reviewed fixed admission. It does not include the imported `endpoint.py` or host helper source. A changed plan or implementation could silently create a new matching manifest/audit pair. Freeze an exact source list and commit an independent GO/admission after the corrections; require clean committed bytes and compare the run's identity against that approved receipt before real TTS.
4. **Audit reviewer-copy integrity before handing out bundles.** The builder copies each opaque WAV and verifies its hash once; there is no later read-only bundle audit to rehash all 36 copied files and bind each `REVIEW.html` to the technical mapping. Add that check and preserve the technical mapping outside both reviewer directories. The current HTML source itself exposes ordinal and `qNN.wav` names, without source scripts or expected labels. The two fixed queue permutations differ. No human responses exist.
5. **Set a memory/host completion policy.** The existing pre/post power gate is sound as source logic. Choose and enforce a prospective process-tree memory cap appropriate to the TTS engines, and verify terminal power/time evidence after all files have been written. A sampled peak alone without a limit is a measurement, not a resource gate.

After a versioned fix, rerun no-weight fault tests and obtain a new independent GO. Then one bounded real TTS attempt may start. Any future technical byte pass still requires two independent blinded listeners for all 18 recordings, with a third on critical disagreement, before Qwen candidate inference. The separate [Qwen method V1 HOLD](INDEPENDENT_SOURCE_REVIEW_HOLD_V1.md) remains in force.
