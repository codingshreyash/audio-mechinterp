## HOLD reasons and exact corrections

1. **The current admission conflicts with an approved gate.** [Runner source contract step 1](RUNNER_SOURCE_HANDOFF_V1.md#minimum-future-runner-sequence) requires an independent **18/18 two-listener wording-QA receipt before model load**. The typed backend calls `validate_go()` and checks host/source state, but neither parent nor GO schema requires human QA. The typed-only pilot can reasonably be separated from audio QA, but that exception is **not present in the approved protocol**. Either obtain and bind the 18/18 receipt before issuing GO, or write a versioned, independently reviewed typed-only resource-pilot exception that permits only `F_L1__typed`, forbids all audio/development/locked model outputs, and bars using its answer to select or change later cases. Bind that amendment in the GO source identity. Until then, I cannot issue a GO consistent with the existing admission.
2. **Real unmodified teacher-forced forward parity is not measured or saved.** The leaf hook should preserve values algebraically, and the fake check showed exact equality, but the worker only records the three **leaf-hooked** suffix passes. Its cross-suffix state check cannot prove that inserting a differentiable leaf left the pinned model's logits and prompt-last states unchanged. Before crediting the three VJPs, save a no-hook full-logit reference and a read-only-hook site-state reference on the same prompt and label suffix for each target. Verify first/second full-logit and prompt-last state parity at both sites under predeclared tolerances; audit those references from saved arrays. A failed reference parity must make the typed pilot invalid, not merely annotate it. This is the resource pilot's stock/instrumented parity gate, not a claim that the fake model proves real parity.
3. **The host archive and directory durability claim needs a fix.** The reused `host.archive()` writes compressed `pre/post_power_log.txt.gz` with `flush()` but no `os.fsync()`. The parent fsyncs the JSON file bodies via `backend.write_once`, but it does not fsync the directory after creating host archives, result, or terminal entries. The saved auditor checks hashes and timestamps when files are present, but the handoff's assertion of durable complete evidence after terminal fsync is stronger than the current write protocol. Fsync each archive file and the relevant attempt/worker-output directories before publishing a complete terminal receipt; include a no-weight fault test that absence of an archive or terminal cannot pass audit. Preserve any failed attempt.

The current `generation_pair()` also does not itself require a positive read-only hook count; the saved auditor does, so a zero-count run would be invalid at audit. The worker records, but the auditor does not currently enforce, the resolved generation-config snapshot. A later FIT/development runner must compare resolved generation defaults and teacher-forced versus generated token alignment before treating the pilot as behavioral evidence. These are additional review points, not permission to run the present backend.

No Qwen candidate result, reusable lens, audio behavior, action proposal or security finding follows from this source review. A corrected version needs new source hashes, a new independent executable review, and a GO bound to the corrected attempt before one candidate load.
