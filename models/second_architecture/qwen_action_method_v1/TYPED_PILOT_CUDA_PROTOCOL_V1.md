# CUDA typed F_L1 continuation: source review handoff

19 November 2026. **Source only; no GPU allocation, weight load, stage GO, or result.** This is a new Linux/CUDA placement after the immutable [MPS V3 load failure](TYPED_PILOT_V3_FAILURE_REVIEW.md). The MPS script and `runs/typed_pilot_v3/attempt_001` remain unchanged. The CUDA attempt directories and GO files are deliberately absent. An independent executable reviewer must inspect committed source bytes and environment identity before either stage runs.

## Scientific contract

The only case is `F_L1__typed`, with the frozen Qwen/Qwen2.5-Omni-3B checkpoint revision `f75b40e3da2003cdd6e1829b1f420ca70797c34e` and Transformers revision `e7e568dc7673ac99a87660c7c50e84830268285c`. The text-only Thinker uses FP32. The three canonical targets are LIST 22852, ASK 7384, CANCEL 88493, each followed by EOS 151645. The score is log P(label at prompt-last) plus log P(EOS after the teacher-forced label). The VJP is taken at post-block residuals 17 and 34, width 2048, with the first site's numerically identical leaf and the second site still connected. The implementation copies the audited V3 teacher-forcing and generation functions, replacing only MPS memory sampling with CUDA sampling. It saves all 36 FP32 sidecars, including unmodified and read-only full-vocabulary logits, read-only and leaf states, and six VJPs. All no-hook/read-only/leaf logits and prompt-last states must match within `1e-5` on the same CUDA run; generation must save and match the complete no-hook/read-only token paths. The saved no-weight audit calls the existing independent sidecar reconstruction, score, and parity checks. No MPS/CUDA byte equality is assumed.

## Pinned environment and GO

Linux, Python 3.12, CUDA runtime `12.8`, one visible NVIDIA A100 80GB (compute capability 8.0), PyTorch `2.11.0+cu128`, Transformers `5.24.0.dev0` from the exact git commit above, Accelerate `1.16.0`, NumPy `2.5.5`, psutil `7.2.2`. The [official PyTorch CUDA 12.8 index](https://download.pytorch.org/whl/cu128/torch/) lists the `torch-2.11.0+cu128-cp312-cp312-manylinux_2_28_x86_64.whl` with SHA-256 `d252cf975fb18c94a85336323ad425f473df56dab35a44b00399bd70c7a3b997`; it does not list the Mac's `2.15.0` package as a CUDA 12.8 wheel, so this is a new numerical backend. The installed Qwen modeling/processing source bytes and tokenizer files must match the frozen hashes. A pre-staged local HF snapshot must contain the exact checkpoint; the worker is offline and disallows download. The *exact* GPU UUID, name, memory, driver version, installed package/source hashes, and CUDA runtime are captured before any candidate attempt and bound into its independently authored GO. If a pinned Linux wheel or runtime cannot be installed, this route is HOLD; changing a pin needs a new source review, not an ad hoc install. The parent requires one physical/visible GPU and no competing job. Review the actual `nvidia-smi` inventory for MIG or shared-device use before GO.

The reviewer writes `TYPED_PILOT_CUDA_INDEPENDENT_REVIEW_V1.md` and stage-specific `TYPED_PILOT_CUDA_LOAD_GO_V1.json` or `TYPED_PILOT_CUDA_PILOT_GO_V1.json`. The GO schema is `qwen_action_typed_pilot_cuda_go_v1` and binds `status=independent_executable_go`, `stage`, resolved `approved_attempt`, `scope=one typed F_L1 pilot only`, `qa_policy=typed_F_L1_only_no_audio_QA_exception`, `qa_amendment_sha256`, `parent_amendment_sha256`, `source_identity`, `runtime_identity`, and `review_sha256`. The pilot GO additionally binds the passing `load_001_audit.json` and load GO hashes. No self-issued GO belongs in this source commit. Both parent and worker fail before weights if their stage GO/nonce/deadline chain is missing.

## Stages and limits

| Stage | Fixed attempt | Whole wall time | Sampled GPU cap | Host tree RSS | Evidence | End condition |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| Load only | `runs/typed_pilot_cuda_v1/load_001` | 180 s | `<56 GiB` | `<24 GiB` | `<64 MiB` | Load pinned FP32 Thinker, validate dtype/sites/tokenizer, save CUDA telemetry, unload. No forward, generation, or VJP. |
| Full pilot | `runs/typed_pilot_cuda_v1/pilot_001` | 900 s | `<60 GiB` | `<24 GiB` | `<64 MiB` | One typed F_L1 three-target teacher-forced VJP and full-path generation, then saved audit. |

Parent samples process-tree RSS and `nvidia-smi` used VRAM, checks source/evidence, sends pipe heartbeats, and kills the worker process group at any limit or monitor error. Worker authenticates a fresh 256-bit nonce and a live parent before importing candidate code, installs an absolute deadline alarm, and exits if parent heartbeats stop. Worker samples PyTorch allocated/reserved/peak VRAM after load, each target, and generation; these samples can miss short transients, so CUDA OOM and monitor failure also invalidate the attempt. Parent reserves 15 seconds for post-probe, result, directory fsync, and terminal receipt. A success requires all files to be durable and a saved no-weight audit. Any partial/failed attempt consumes its fixed path, is not pooled, and cannot be rerun under the same GO. No GPU run is authorized by a passing source-only fake test.

## Minimize billed setup

Before allocating the A100, prepare a Linux Python 3.12 environment/container with pinned wheel and commit availability verified, package the committed repo source, and stage the exact HF snapshot/tokenizer/config to a reusable volume or cache. Do not transfer 43GB of weights after starting the billed stage if an external cache can be populated first. Once the fresh A100 is available: capture its identity and baseline VRAM, confirm no other GPU job, run source/tokenizer checks without model weights, request independent load-stage review/GO, then run the 180-second load stage and saved audit. Only a passing load audit supports a *separate* pilot review/GO and 900-second attempt. Export the receipts and sidecars before deleting the instance; then stop it. Boot, image preparation, checkpoint staging, and reviewer latency are outside the 180-second worker stage and should be budgeted separately. If setup is not ready, do not start billing merely to wait for it.
