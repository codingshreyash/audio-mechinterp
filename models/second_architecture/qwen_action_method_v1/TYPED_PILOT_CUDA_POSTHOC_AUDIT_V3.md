# Read-only posthoc timing audit for CUDA V3 load_002

19 November 2026. **Source only; no result is declared here.** The pinned V3 saved auditor rejected the completed `load_002` receipt at its whole-stage deadline check. Its temporal predicate required `terminal_utc <= terminal.json` filesystem mtime. The remote terminal receipt says `2026-11-19T13:18:33.312483+00:00`, while the remote file mtime was reported as `2026-11-19T13:18:33.308256507+00:00`, a **4.226493 ms** difference. The copied local file has a later copy-time mtime, so its mtime cannot independently resolve the remote condition. All pinned V3 source, GO, attempt files, and the original auditor remain unchanged.

The separate `typed_pilot_cuda_posthoc_audit_v3.py` retains the V3 auditor's exact identity, hash chain, attempt census, GPU isolation, process-tree RSS, framework VRAM, evidence-size, and load-only output checks. It replaces only the file-mtime comparison with a same-parent wall/monotonic cross-check. The parent recorded UTC start, result end, and terminal times alongside monotonic elapsed seconds before writing each receipt. The posthoc check requires the same ordered host and worker timeline, wall and monotonic durations each within the frozen 180-second load limit, and agreement of start-to-result, start-to-terminal, and result-to-terminal durations within **0.25 seconds**. This bound allows small clock sampling and filesystem timestamp offsets while rejecting a materially shifted clock or deadline. It does not use local copied file mtimes.

For orientation only, the copied receipts' start-to-result wall/monotonic durations differ by about **2.7 microseconds**, and start-to-terminal by about **16.6 microseconds**. Those arithmetic checks do not establish that the complete saved audit passes. Run the new read-only auditor only after an independent source review; write its receipt outside the immutable `load_002` directory. A passing load-only audit would say the model and processor loaded within resource limits. It would not be a behavioral, mechanistic, or security result. **It does not unlock `pilot_002`:** the pinned V3 pilot gate still invokes the original V3 load auditor, which rejects the mtime predicate. A separate reviewed protocol and GO change would be required before any pilot run.
