## Remaining executable HOLD: direct worker bypasses the bounded parent

`typed_pilot_backend_v2.run_worker()` rechecks GO and the fixed attempt path, then only requires the attempt directory and a `pre_host.json` that passes `host.validate_power()`. It does **not** require a parent `start.json`, a bound launch nonce, proof that the 300-second/RSS-monitoring parent is alive, or the parent deadline before importing torch and reaching `load_pinned_thinker()`. The public `--worker --attempt <fixed path>` entrypoint calls this function. Once a valid GO exists, a direct invocation with a manually created attempt and live-looking pre-host record can load the model outside `typed_pilot_parent_v2.run_bounded()`. The saved auditor would later reject the missing parent evidence, but that cannot restore the wall/RSS cap during the unbounded candidate load. It also permits using a partial attempt directory without the parent's one-shot start receipt.

I reproduced the negative path without a model load. In a temporary attempt with only `pre_host.json` and **no** parent start receipt, I patched GO and power validation to fake success and patched `torch.backends.mps.is_available()` to false. `run_worker()` passed every parent-evidence check it has and reached its MPS availability assertion, raising `ValueError: typed pilot requires MPS`; the parent `start.json` remained absent. With MPS available, the next operations would set the MPS fraction, create worker output, and call `load_pinned_thinker()`. This is a source-level control-flow demonstration, not a Qwen run.

Before executable GO, require an explicit, non-replayable parent-to-worker launch handshake **before torch/model import**: a parent-created start receipt bound to GO and pre-host hashes, parent PID and a fresh nonce digest; pass the nonce through the spawned worker's environment or inherited IPC; verify the fixed attempt, parent PID/liveness and deadline in the worker. Give the worker its own wall timer before weight load so loss of the monitor cannot leave an indefinitely running model. Retain the parent process-tree RSS monitor and require its liveness through worker completion; a failed handshake or missing monitor must exit before loading weights. Add a no-weight direct-worker regression using a valid-looking pre-host record but absent parent launch proof. A reviewed V3 source and new GO identity are necessary.

The narrow QA exception and normal-path evidence are supportable; the direct-worker gate is the remaining reason for HOLD. No typed pilot result, audio transfer, reusable Jacobian Lens, native action or security finding exists here.
