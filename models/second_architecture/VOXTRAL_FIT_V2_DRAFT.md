# Voxtral v2 fit pilot: prospective repair after v1 gate failure

**Draft, no new model inference.** The [v1 Stage-2 report](VOXTRAL_FIT_STAGE2_GATE_V1.md) remains gate-failed at 14/16 strict natural endpoints, despite the aggregate 28/32 capability pass. Its four full-pilot misses were `deer`→`dear`/`Dear`, a same-pronunciation spelling ambiguity in local `espeak-ng`; they remain strict misses. This v2 is explicitly **fit-informed**. Its purpose is to test the method on unopened fit-pool words without claiming v1 passed or changing the corpus's development/test split.

The CPU-only [selector](voxtral_fit_v2_select.py) uses the frozen index and v1 failure report. It excludes every v1 pilot pair ID, rejects any remaining pair with a non-ASCII/nonalphabetic word, a word shorter than four letters, or a word in its fixed common-homophone exclusion table (which includes `deer`→`dear`). It selects the lexicographically first eligible `map_fit` pair ID in each category. The table is a pragmatic fixed list, **not** a comprehensive pronunciation dictionary; its inclusion of `deer` is an adaptation to v1. No ASR or Voxtral result for a candidate v2 clip is used to choose among eligible pairs. The selector hashes only the 32 chosen fit WAVs; it does not open development or test WAVs. The resulting [selection](VOXTRAL_FIT_V2_SELECTION.json), SHA-256 `f897d360dbcec9c09f1813f9c070294753fbabc25c6213ba6bdac34b1d79b56b`, fixes `animal_08` (`beaver`/`monkey`), `color_05` (`silver`/`teal`), `nature_09` (`waterfall`/`garden`), and `object_05` (`phone`/`book`). These clips are unopened by **Voxtral**; the shared corpus may be used independently by Qwen.

Before any v2 Voxtral inference, freeze the selector result, exact prompt, model/processor revision, generated-answer classifier, candidate score surfaces, script hashes, clip hashes, and resource limits. A v2 run would use the same audio-instruct user prompt, BF16 checkpoint, greedy 32-token cap, EOS requirement, 30 GiB MPS cap, and **strict** one-word spelling criterion as v1. Run all **4 pairs × 2 voices × 2 fit templates × 2 words = 32** new fit clips once. The preregistered capability threshold remains **≥24/32 overall and ≥12/16 per voice**. For the eight first-template pair records, require **all 16 natural endpoints** to pass before any feature hybrid or hidden-state intervention. If either gate fails, stop and report; do not substitute more fit words based on outcomes.

If both gates pass, a separate v2 mechanism protocol can carry forward the same six-bin word/pre/post and word/outside/padding feature controls, projector output and last audio-encoder sites, and complete answer+EOS endpoint. Its intervention count and FP32 feasibility must be measured on fit only before scheduling MPS. The 12-pair development and 12-pair locked-test pools remain unopened for Voxtral candidate answers under this draft. Even a successful fit mechanism would be a lexical pathway result, not a security finding.
