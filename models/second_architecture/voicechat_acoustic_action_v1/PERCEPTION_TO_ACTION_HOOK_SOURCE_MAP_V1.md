## The complete pre-generation audio tuple

1. `setup_speech_encoder` builds `AudioPerceptionModule` from the combined checkpoint's embedded config (`pretrained.py:105–155`). Its inference path preprocesses the 16-kHz waveform, runs a 24-layer Conformer encoder, passes it through the configured **identity** modality adapter, and projects to the 4,480-dimensional LLM input width (`perception.py:104–158`; pinned config). The module returns **three** values when `return_encoder_emb=True`: projected `source_encoded` `[B,T,4480]`, `encoded_len` `[B]`, and preprojection encoder frames `[B,T,1024]`. The third value becomes `asr_emb`; despite the name, it is an encoder activation, not a transcript or text embedding.
2. `DuplexSTTModel._init_inference` calls that perception module once before generation (the pinned raw `duplex_stt_model.py` call is at **3630–3632**). It then prepends the same system-prompt embedding to `source_encoded`, adds matching zero rows before the encoder-frame `asr_emb`, applies any FSDP length padding, clones the projected sequence into `audio_embeds`, and precomputes `input_embeds[:,0]` through the fusion module (`3637–3838`). The rest of `input_embeds` starts at zero. With a nonempty system prompt, row zero is a **prompt position**, not the first acoustic frame. Editing only later `audio_embeds` would miss the already fused row zero if that row carried audio; `asr_emb` is separately retained, but the pinned default settings do not establish it as an active path to pass-1 text/function logits.
3. At each subsequent step, `audio_embeds[:,t:t+1]` is combined with the previous agent-text token and previous function token (`duplex_stt_model.py:3916–3970`). With this checkpoint's absent `fuse_method`, the source default is `add`; the pinned weights are audio `1.0`, agent text `1.0`, function `2.0` (`duplex_stt_model.py:210, 295–307`; `fusion.py:72–105`; config). The shared LLM hidden state feeds separate `lm_head` and `function_head` logits (`duplex_stt_model.py:475–509`). The function token uses argmax in inference (`3990–4029`). The pinned config has `use_function_head=true` and `predict_user_text=false`; the separate user-text head is inactive. `asr_emb` is consumed by optional RNNT transcript decoding only when `_run_rnnt_in_loop` is true (`3918–3929`). The required ASR/RNNT flags are absent and default false in the VoiceChat offline path (`nemotron_voicechat.py:599–626`), so source inspection shows **no active `asr_emb` feedback** into pass-1 LLM text/function logits under those settings. A live runner must verify resolved flags and consumers rather than infer behavior from defaults alone.
4. The pinned helper runs pass 1 with `decode_audio=False`, parses the **first raw function span**, and may run pass 2 with a canned tool response injected (`offline_voicechat_097dfe9.py:184–280`). VoiceChat calls `_init_inference` anew in each pass (`nemotron_voicechat.py:584–628`). Pass 2 has a changed function timeline and conditioned text/TTS trajectory. A pass-1 state patch must be scoped to that pass; replay speech cannot be treated as simultaneous with pass-1 function tokens.

The raw `input_signal` also remains in inference state, but the inspected post-inference path uses it to retain or time-expand **source audio** for reporting (`duplex_stt_model.py:4100–4160`). The source shows no raw-waveform bypass into the pass-1 LLM after the perception return. This is a source-level inference, not proof: the live no-hook/read-only/self/full-donor checks must test it. A full-donor patch cannot make the recipient's saved raw source waveform equal the donor's and must not claim that parity.

## Causal interface and mandatory live checks

The strongest **single conservative hook site** is the output of the final perception module, *before* `_init_inference` constructs prompt-aligned state and row-zero fusion. It is a **tuple**, not a single direction or tensor. A `register_forward_hook` there can return the donor's exact `(source_encoded, encoded_len, encoder_frames)` for a full-donor arm. That lets the pinned code itself rebuild prompt alignment, `audio_embeds`, the retained `asr_emb`, and first-step fusion. This deliberately patches an inactive-by-default encoder-frame branch too; a successful full-tuple patch would **not** show that `asr_emb` contributed to the action. The included [fake-tensor helper](perception_tuple_patch_source_v1.py) patches the complete tuple, validates one-sample shape/dtype/device and equal encoded lengths, and rejects a hook that leaks into a second forward. Seven fake tests pass. It is intentionally not wired to a live model.

The future runner must freeze the donor and recipient WAV/sample/processor hashes, prompt IDs, model/code bytes, resolved config, hook identity, and the complete source/encoder tuple before seeing endpoint outcomes. It must verify equal waveform sample counts, equal perception row counts/lengths and same prompt and generation settings. Capture/restore must preserve tensor dtype and values exactly; save pre/post tensor hashes and realized edit norms. At the same site, run no-hook, read-only, exact self, full donor, local decision-window donor, displaced-window donor, and independently seeded equal-norm random controls on **all eligible pairs**. Local rows must be mapped from model-blind human timing marks by a separately frozen rule; equal shape alone does not establish phonetic alignment or localized causation. The pinned identity adapter makes projected and encoder outputs share a frame count, but the Conformer has temporal context, so a row patch is not an isolated acoustic instant.

Before interpreting an outcome, require exact complete **pass-1 text and function token IDs plus first-span parser** parity for no-hook/read-only/self, and require full-donor parity with the donor's complete pass-1 tokens/parser. If the full-donor arm fails, keep that pair as a failed causal case rather than choosing a different site after seeing results. A local patch that transfers a parsed action only supports sufficiency under this artificial interface; it does not show unique mediation or an attacker-controlled waveform exploit. The unmodified noisy-WAV endpoint and the independent inert authorization result remain separate tests.

If route attribution is later desired, a separately frozen experiment could compare projected-only and full-tuple patches after confirming the resolved ASR/RNNT flags. The present protocol treats the complete tuple as a conservative patch interface and does **not** claim two active audio routes to the pass-1 action.

**Current decision:** GO as a source-grounded hook target and fake prototype; HOLD for live hook integration, candidate inference, model-mechanism or security claims until human QA, stock/adapter identity, resource admission, and independent executable review pass.
