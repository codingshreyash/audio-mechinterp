## Correct tuple boundary and blocking causal wording

The offline [`_init_inference` source](https://github.com/NVIDIA-NeMo/Speech/blob/097dfe9e2f55baf653b83035868bdc89849f1b47/nemo/collections/speechlm2/models/duplex_stt_model.py#L3397-L3504) calls `self.perception(..., return_encoder_emb=True)` at **lines 3427–3429**, not the map's cited `3599–3633`. [`AudioPerceptionModule.forward`](https://github.com/NVIDIA-NeMo/Speech/blob/097dfe9e2f55baf653b83035868bdc89849f1b47/nemo/collections/speechlm2/modules/perception.py#L93-L145) returns projected frames, encoded lengths, and preprojection encoder frames. `_init_inference` prepends the prompt, aligns `asr_emb`, clones projected frames into `audio_embeds`, and computes row-zero fusion. The proposed whole-tuple hook is therefore a valid **conservative pre-generation site**, assuming the live model preserves this path and a one-call hook is attached to the correct module.

The map calls `asr_emb` a separate audio-derived route and warns that editing only `audio_embeds` would miss it. That is structurally true, but it is **not yet an active second route to the pass-one text/function decision in this pinned configuration**. In the inspected inference loop, `asr_emb` is consumed by optional RNNT transcript decoding only when `_run_rnnt_in_loop` is true; the pinned absent RNNT flags make that false by default in [`NemotronVoiceChat.offline_inference`](https://github.com/NVIDIA-NeMo/Speech/blob/097dfe9e2f55baf653b83035868bdc89849f1b47/nemo/collections/speechlm2/models/nemotron_voicechat.py#L533-L560). `predict_user_text=false` also disables the user-text head. I found no source-proven `asr_emb` feedback into the pass-one LLM text or function logits under those settings. The map should distinguish a **retained encoder/transcript tensor** from a **proven active causal route to the action**. A whole-tuple patch remains prudent, but a successful patch cannot establish that both tensors contributed to the action. The future live trace should record resolved RNNT/user-text flags and test projected-only versus full-tuple edits only under a separately frozen design if route attribution is desired.

The map should also state that with a nonempty system prompt, row zero is a **prompt-aligned** position, so `input_embeds[:,0]` being pre-fused does not make it the first acoustic frame. The raw waveform is retained for later source-audio reporting; source inspection supports no raw-waveform bypass into pass-one LLM tokens after the perception return, but full-donor complete-token/parser parity is still the required empirical check. A hook spanning the whole official two-pass helper would hit the second perception call and intentionally fail; the live wrapper must attach for pass one only and remove it in `finally`.

## Fake primitive checks

I reran all **7/7** fake-tensor `unittest` cases with the project Torch environment. Additional direct fake probes rejected a two-tensor return (`return_encoder_emb=False`), donor/recipient encoded-length mismatch, a row interval outside valid frames, and a nonfinite donor. The primitive checks one-sample rank/shape/dtype/device, clones captured and donor state, changes both projected and encoder rows for a local patch, and rejects a second forward call. These tests establish API behavior only; they do not establish that the live FSDP-wrapped module invokes the hook once, that a local row is phonetic, or that a donor patch changes a full answer.

**Required correction:** fix the `_init_inference` line reference and qualify the retained `asr_emb` path before treating the map as a source-grounded complete-action mechanism. Re-review the corrected map. Before any causal claim, complete stock/adapter identity, exact pass-one hook scope, no-hook/read-only/self and full-donor complete text/function-token plus first-span parser parity, human QA and resource gates. A successful white-box patch would show sufficiency at this artificial interface, not an attacker-suppliable exploit or security finding.
