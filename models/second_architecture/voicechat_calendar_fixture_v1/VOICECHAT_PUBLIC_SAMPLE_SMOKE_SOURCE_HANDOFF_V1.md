The minimum reviewed total cap is 64 KiB. It reserves at least one quarter of a small cap, up to 1 MiB, for terminal receipts. Aggregate output growth and VRAM peaks are **sampled**, so a worker can temporarily exceed a cap between polls. After a failure it records the observed bytes, truncates raw artifacts to fit the retained evidence cap, and records each original size/hash (or an explicit unavailable hash above the 1 GiB read ceiling) and retained size/hash. This is **partial preservation**, not a hard live-write quota. A final manifest hashes every retained prior file including `result.json` or `failure.json`; `final_manifest.sha256` is an independently checkable digest of that manifest. The digest file cannot recursively hash itself. Successful output is labeled only `environment_smoke_only`; failures are `failed_or_incomplete_environment_smoke`. An abnormal telemetry error kills the process group and follows the same failure seal. Independent source review must assess these exact cap semantics before a live freeze. A future controller must protect the review HMAC key and attest the reviewer; a caller-supplied key alone is not proof of independence.
