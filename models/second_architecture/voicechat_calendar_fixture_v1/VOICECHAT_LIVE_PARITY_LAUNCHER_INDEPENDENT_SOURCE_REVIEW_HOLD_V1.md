# Independent source review: synthetic VoiceChat parity launcher

19 November 2026. **Decision: HOLD for the claimed bounded source-only supervisor; no live VoiceChat authorization.** I independently reviewed `live_parity_launcher_v1.py` and its tests from `dce005b` and `f8b380d` against the [prospective orchestration protocol](VOICECHAT_LIVE_PARITY_ORCHESTRATOR_PROSPECTIVE_V1.md), [source-plan rereview](VOICECHAT_LIVE_PARITY_SOURCE_PLAN_INDEPENDENT_REREVIEW_V2.md), and [launcher handoff](VOICECHAT_LIVE_PARITY_LAUNCHER_SOURCE_HANDOFF_V1.md). I did not author or edit the launcher, load model weights, run inference, call a calendar tool, or access a remote service.

## Blocking bounded-evidence gap

`run_synthetic_protocol` checks `output_bytes` only on files inside each arm directory (`live_parity_launcher_v1.py:176–180, 221–224`). The adapter's parsed-call response is written to top-level `api_response.json` (`191–193`), and top-level `source_plan_exact.json`, `synthetic_scope.json` and `synthetic_comparison.json` are also outside that cap. I reproduced a successful five-stage synthetic run with an **8,192-byte** per-arm output cap and a **20,083-byte** `api_response.json`: the fake adapter returned a 20,000-character string inside `response_selector.response`; all arm checks and a fake comparator returned `synthetic_test_only_no_model_work`. The required response bytes were generated according to the pinned rule, but the claimed bounded evidence was not bounded by the supplied cap. `_artifact_hashes` also reads each complete arm file into memory before checking its byte count, so an overlarge fake artifact can consume unbounded memory before rejection.

For a source-level bounded supervisor, set and enforce an explicit total evidence cap that includes all top-level and arm files, with a limit on serialized response and plan sizes **before writing**. Stream artifact hashing with a pre-read file-size check. Add negative tests for an oversized parsed response and oversized top-level summary, plus an artifact that exceeds the cap before its contents are read. A production implementation needs its own separately frozen caps and independent review regardless of this fix.

## Checks that passed within the synthetic slice

- The launcher rejects the real `source_plan_only_no_model_work` status and requires the explicit synthetic status/injection flag before creating an output directory or calling a worker. It fixes case B/Piper, `official_sample → adapter → stock_a → stock_b → stock_no_tts`, seed type/range, expected input-hash map, and exact `1e-4` comparison contract. It snapshots the plan and rechecks the supplied hash map before each arm and before comparison. In-place mutation of the plan/hash object is rejected against the snapshot.
- Arm directories are exclusive and consumed after failure. Reported process IDs must be distinct; reported seed, checkpoint hashes, selected WAV and prompt-token digest must match the bound plan or each other. These are **worker assertions**, not independent proof of process reset, checkpoint bytes or actual prompt tokens. The fake test for missing raw/pass capture stops before stock, and response tampering is checked within stock and before comparison, including the final arm.
- Adapter discovery alone chooses the response. The no-call branch uses the exact frozen 86-byte placeholder and rejects any of the six second-pass injection fields. The parsed-call branch preserves Python default JSON insertion order and requires all six fields in pass 2. Every stock arm receives the one response digest; no first-pass function injection is allowed. The actual default comparator is wired to stock A/B/no-TTS and adapter trace/calls at `1e-4`; a caller-supplied fake comparator can return the expected status, which is appropriate only for this synthetic test surface.

I reran the launcher, source-plan and prior-HOLD regression suites: **27/27 tests passed**. `py_compile` passed. ## Live interpretation boundary

The current entry point accepts an arbitrary injected worker; a synthetic plan label does not technically prevent that callback from loading a model. It has no production CLI, NeMo import or built-in real worker, and it correctly rejects a real source plan, so this source review makes **no live-use claim**. Its arbitrary `.bin` files are not checked against the in-memory captures, PID and VRAM are self-reported, and a fake comparator can assert success. Before live use, independently authenticate the 12/12 human listening QA, case-B receipt, C controller grants and external anchor; rerun pinned ready/preload checks and the official sample; implement fresh checkpoint-loading processes, inert dispatch, real resource monitoring, lossless hash-bound raw outputs, and a separately reviewed external executable freeze. Neither this synthetic run nor a future parity pass would itself establish a speech/tool mismatch or security finding.
