# Independent source review: VoiceChat step-400 probe core V2

19 November 2026. **PASS for the source-only instrumented core at `0e9d4b3`; HOLD executable/GPU inference.** This review supersedes the [V1 metadata-path HOLD](VOICECHAT_H200_STEP400_PROBE_CORE_INDEPENDENT_SOURCE_REVIEW_HOLD_V1.md). It does not review a launcher, parent watchdog, staged host, or one-shot GO.

The pinned NVIDIA NeMo `NemotronVoiceChat.offline_inference` loop calls `_step_inference(t, inference_state, ans, force_bos_positions)`, then `infer_codes_one_step` with the eight kwargs checked by the probe. The latter returns `(code, past_key_values)`, and the loop writes `gen_codes[:, t]` after that return. The function-call helper parses only after pass 1 completes. Thus the core's step-400 `DiagnosticStop` is at the reviewed post-TTS, pre-`gen_codes` boundary, and prevents a pass-2 return in the fake callback. The source also records the post-load/pre-step-1 CUDA baseline and resets peaks before the first generation forward, then writes ordered snapshots at `1, 50, 100, 200, 300, 400`. The measurement method is instrumented and cannot claim uninstrumented output parity.

The blocking V1 issue was reproduced with a dict key containing arbitrary text; it appeared verbatim in saved `tensor_rows[].path`. Revision `0e9d4b3` replaces every dict key in recorded paths with a structural `[entry:n]` index, including nested and unknown-node paths. Its new regression places prompt-like text and a token-like integer in STT/TTS dict keys and proves neither appears in serialized metadata. No storage pointer is serialized. Shared tensor views are counted once in the cross-family storage union; unknown container types mark the inventory incomplete. The ledger is append-only, has per-record and total size caps, fsyncs each checkpoint, and hashes its saved bytes.

I reran all **9/9 no-model tests** with `models/second_architecture/.venv/bin/python` and checked the pinned local helper's first-pass argument shape against the core. The tests cover six snapshots, STT/TTS call-through, method restoration, return identity before the planned stop, cache metadata, shared storage, no retained step result, redacted dict paths, and failure on wrong step/argument/order. These are fake-model checks: actual cache class coverage and live allocator/NVML measurements remain unverified. `nvml_process_sample` checks its subprocess output size after capture; the future parent must enforce its own independent bounded telemetry and resource watchdog.

**Executable gates still required:** bind the exact pinned NeMo callback, official sample WAV/prompt, checkpoint and runtime; add a separate parent that polls NVML and kills the process group on cap or telemetry failure; enforce the 130,000-MiB GPU, 1,800-second wall, 30-GiB disk and 64-MiB evidence limits with sealed partial failures; independently review the launcher/auditor and fresh host freeze; then issue a one-shot GO. The old H200 sample failure remains unchanged. No model weights were loaded and no GPU instance was started in this review.
