# Prospective amendment V1: isolated NVIDIA public-sample smoke

19 November 2026. **Status: conceptual design only; no model run, no production source approval, and no executable freeze.** This amendment changes exactly one ordering rule in the [prospective live parity protocol](VOICECHAT_LIVE_PARITY_ORCHESTRATOR_PROSPECTIVE_V1.md): its all-12 human-QA, external-anchor, and C-controller-grant gate need not precede **one run of the unchanged NVIDIA public random-number sample**, provided this separate sample-only path passes the checks below. Every gate remains mandatory before importing NeMo into a **calendar fixture** worker or loading VoiceChat weights for any calendar WAV. This amendment does not authorize the existing fixture-coupled plan builder or synthetic launcher to run a model. It requires independent conceptual review, then a separately reviewed sample-only source implementation and externally reviewed executable freeze before the sample can run.

## Sample-only admission and execution

1. Implement a **versioned sample-only `ready` → `preload`** path, independently source-reviewed before use. It must preserve the existing [preflight](../voicechat_h100_local_preflight.py)'s clean NeMo commit/file checks, exact VoiceChat config and full weight hash/size, pinned package/GPU/disk checks, dedicated six-file Nano cache and offline class/tokenizer resolution, no bytecode or extra executable cache files, and same-shell offline environment checks immediately before the sample process. It must additionally hash the exact public sample WAV and response above. It may omit only calendar fixture WAV/render, human QA manifest/ledger/receipts, C grants and external anchor. Existing fixture `ready`/`preload` and [fixture source plan](live_parity_source_plan_v1.py) remain unchanged and cannot be substituted by sample-only receipts. The official sample script imports NeMo at module import time, so sample-only admission must finish **before starting that Python process**.
2. Before any sample weight load, an independent reviewer must approve the exact sample-only launcher/source/tests. A separate external executable freeze and independent freeze review must bind this amendment's committed bytes, source and review commits, every identity/hash above, canonical Nano environment, fixed command and output path, one-attempt rule, and finite caps. Provisional caps for that source review are one fresh process, **1,800 seconds** wall time, **75,000 MiB** peak GPU memory and **1 GiB** total new evidence; the freeze may tighten them but cannot silently relax them after inspecting output. Monitor actual process/GPU use and terminate on a cap breach, retaining partial evidence. If the source-only estimate cannot justify these caps, revise and review this amendment before any run.
3. Use a new exclusive run ID and output directory, then invoke only the unchanged pinned script with its four required arguments: `--checkpoint` to the pinned VoiceChat directory, `--wav` to the pinned `sample_fc.wav`, `--api-response-json` to the pinned static random-number response, and `--output-dir` to the exclusive directory. Keep the script defaults for `--template`, `--tools-json`, `--system-message`, `--sample-id` and `--device`; do not supply those optional arguments. Use a fresh model process, a frozen environment including any CUDA/PyTorch determinism flags, the pinned package set, and `PYTHONPATH` selecting the pinned NeMo tree. The unchanged script exposes no seed argument; do not add a wrapper that changes its behavior to simulate one. No calendar system text, tools, WAV, stub, adapter, or dispatcher may enter this process.
4. Record the exact command and environment receipt, UTC/monotonic start and finish, process identity, return code, complete bounded stdout/stderr, package/CUDA/GPU details, peak VRAM, all generated files and SHA-256/size, and any failure/timeout. Preserve the official sample's generated outputs as **transport artifacts**, not a pass-by-pass stock/adapter comparison. Do not rerun under the same ID, change the sample, prompt, response, caps or settings after seeing output, or select another public sample. An environment failure ends this attempt; any changed design needs a new version and review before another attempt. The only permissible result label is `environment_smoke_only` (or an explicit failed/incomplete smoke), with no calendar, parity, model-mechanism or security claim.

## Sealed fixture boundary

The [calendar parity protocol](VOICECHAT_LIVE_PARITY_ORCHESTRATOR_PROSPECTIVE_V1.md) still requires independently authenticated **12/12** human listening QA, every triggered adjudication, both signed C grants, immutable external anchor, fixture-coupled pinned `ready` → `preload`, separate production-worker source review, and an externally reviewed fixture executable freeze **before any calendar fixture model process**. Case B/Piper, the four fixture arms, response rule, `1e-4` raw PCM comparison, source/result reviews and inert calendar dispatch remain fixed. The early smoke receipt cannot authorize fixture inference or alter the fixture, response, arm order or denominator. The later fixture run must repeat the official sample under its own reviewed freeze if any source, checkpoint, Nano environment or sample input identity changed; reusing an unchanged early smoke as its environment check requires an explicit later independent freeze/result review. This amendment is a proposed design boundary, not permission to bypass the currently committed gate before its own reviews and implementation exist.
