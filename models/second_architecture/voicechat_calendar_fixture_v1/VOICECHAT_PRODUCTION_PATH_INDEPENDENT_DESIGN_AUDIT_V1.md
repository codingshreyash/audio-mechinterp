# VoiceChat production parity path: independent design audit

19 November 2026. **Status: source/design only; no model run.** I inspected the prospective live-parity protocol and current local source. I did not load VoiceChat or Nano weights, run inference, create listening/controller evidence, call a tool, or change implementation source. The [source plan](live_parity_source_plan_v1.py) is a no-model admission artifact; the [launcher](live_parity_launcher_v1.py) is a synthetic-worker supervisor that rejects real plans. Its [V3 review](VOICECHAT_LIVE_PARITY_LAUNCHER_INDEPENDENT_SOURCE_REREVIEW_GO_V3.md) is a GO for that synthetic path, not production use. No production worker or executable freeze is implemented by these files.

## Production entrypoints and evidence

1. **Admit before model load.** The [prospective protocol](VOICECHAT_LIVE_PARITY_ORCHESTRATOR_PROSPECTIVE_V1.md) fixes case `B`, voice `piper_amy_en_us`, the exact rendered final WAV, and the unchanged NeMo Speech `097dfe9…`, VoiceChat checkpoint `443794e…`, and Nano metadata `6533e8d…`. The production plan builder calls the real [12-WAV QA validator](audio_qa_v2.py), binds the selected receipt and cohort ledger, then runs pinned `ready` → `preload` checks ([source plan, lines 222–335](live_parity_source_plan_v1.py)). The external controller must separately attest reviewer identity, both C grants, and the pre-inference external anchor; local hashes cannot authenticate them. Recheck the plan's source, WAV, prompt, checkpoint, Nano and sample bytes immediately before **each** fresh model process. The high-level adapter accepts an *already loaded model*, so its internal QA check is too late to prove pre-load admission ([adapter, lines 508–545](two_pass_adapter.py)).
2. **Run the official sample first.** Execute the unchanged `examples/speechlm2/offline_voicechat_fc_infer.py` on pinned `sample_fc.wav` and `random_number_response.json` in its own fresh process. Save the exact command, exit code, stdout/stderr, generated files and hashes. This is an environment check, not a calendar result ([protocol, Hard pre-load gates](VOICECHAT_LIVE_PARITY_ORCHESTRATOR_PROSPECTIVE_V1.md)).
3. **Run four fixed fixture processes.** In order: adapter discovery, stock A, stock B, stock without TTS-code wrapper. Each fresh process loads the exact checkpoint with the same seed, generation defaults, `load_wav_16k_mono` input and `render_fc_system_prompt`/`encode_system_prompt` prompt ([protocol, Arm order](VOICECHAT_LIVE_PARITY_ORCHESTRATOR_PROSPECTIVE_V1.md); [official helper, lines 66–111](vendor/offline_voicechat_097dfe9.py)). The adapter's [`run_live_case_from_audited_wav`](two_pass_adapter.py) binds and archives the WAV, QA, system/tools, rendered prompt, prompt IDs, two immediate raw pass snapshots and trace. The three stock arms must call the unchanged official `run_fc_offline_inference`; [`capture_stock_helper`](official_adapter_parity.py) wraps its original `run_offline_inference` twice, copying exact arguments/results and optional TTS codes without changing returns. That wrapper changes a module-global function reference and therefore must run serially ([comparator source, lines 74–131](official_adapter_parity.py)).
4. **Persist pass-by-pass channels, then compare.** Save and hash lossless pass-1 and pass-2 `tokens_text`, `tokens_function_pred`, `tokens_function`, `tokens_len`, optional `tokens_audio`, decoded `text`, unspliced `audio`/`audio_len`, all extracted raw call positions/text, parse status, selected first call, injected response bytes/token IDs/steps, six replay tensors, and per-step TTS codes. The [passive recorder](passive_dual_head_recorder.py) can additionally capture last-position shared hidden state, raw text/function head logits, returned head logits, selected IDs, and TTS code steps for each pass; its [review](PASSIVE_DUAL_HEAD_RECORDER_INDEPENDENT_SOURCE_REREVIEW_V2.md) leaves live identity untested. `tokens_audio` can be absent, and per-step codes do not prove the final trimmed local `gen_codes` tensor. Compare exact discrete IDs, parser objects, replay tensors, prompt/input tensors and TTS codes, then all three pairwise **raw unspliced** pass-2 PCM differences against `1e-4` ([comparator, lines 221–317](official_adapter_parity.py)). A final WAV with a tool gap spliced out is a separate transport artifact.

## Integration gaps and two-pass traps

- The [high-level adapter](two_pass_adapter.py) calls `run_two_pass` internally without exposing its `inference_runner`, while [`PassiveDualHeadRecorder.wrap_runner`](passive_dual_head_recorder.py) needs to wrap that runner. A production capture path must integrate the recorder **without bypassing the audited WAV/QA/prompt gate** and then source-review the integration. In addition, the synthetic [supervisor](live_parity_launcher_v1.py) creates `arm_dir` before calling a worker, while `run_live_case_from_audited_wav` creates its `output_dir` with `exist_ok=False`; passing the arm directory directly will fail. Use a new child directory and bind its files to the arm receipt. The synthetic supervisor expects `.bin` artifacts and worker-supplied capture/PID/VRAM assertions, so a production worker must persist actual tensors and telemetry and compare independently reloaded, hashed artifacts ([launcher handoff](VOICECHAT_LIVE_PARITY_LAUNCHER_SOURCE_HANDOFF_V1.md)).
- Pass 1 is `decode_audio=False`; it supports a **text/function** comparison, not a spoken/function claim. The pinned [official helper](vendor/offline_voicechat_097dfe9.py) uses `result.get("tokens_function_pred", result.get("tokens_function"))`: a present `None` suppresses fallback. It extracts only the first function-call position, strips special tags, attempts JSON parsing, and injects all six call/response fields in pass 2 only if a call parses. Pass 2 is `decode_audio=True`; its function output is a **new proposal**, not a third tool execution. Preserve both raw trajectories and do not compare pass-1 function output directly with pass-2 speech as though replay had not occurred ([helper, lines 171–289](vendor/offline_voicechat_097dfe9.py); [adapter, lines 325–475](two_pass_adapter.py)).
- The official helper requires a prewritten `api_response`, so the adapter discovery result fixes the one stock response **before** stock A. For a parsed call, construct `{"tool_name": ..., "response": ...}` in that order, serialize with default insertion-order `json.dumps` plus LF, and bind the exact bytes/hash. For no parsed call, use only the protocol's 86-byte placeholder and require **zero** injection fields in every arm; do not choose another clip or response after seeing output ([protocol, Arm order](VOICECHAT_LIVE_PARITY_ORCHESTRATOR_PROSPECTIVE_V1.md); [response rule](live_parity_source_plan_v1.py)). Keep every parsed call inside the inert [`calendar_stub.dispatch`](calendar_stub.py), never a live calendar API.
- The [original dual-head assay](../VOICECHAT_DUAL_HEAD_ASSAY_PROTOCOL.md) describes a later 12-WAV behavioral matrix and optional human voice. This live parity pilot is only one fixed B/Piper WAV and tests **instrumentation identity**. Even a passing stock/adapter comparison is neither a speech/tool mismatch nor a security finding. Missing human QA, a failed official sample, unstable stock repeat, incomplete pass capture, or a cap breach must stop the pilot with evidence preserved ([prospective protocol, Evidence/resources](VOICECHAT_LIVE_PARITY_ORCHESTRATOR_PROSPECTIVE_V1.md)).
