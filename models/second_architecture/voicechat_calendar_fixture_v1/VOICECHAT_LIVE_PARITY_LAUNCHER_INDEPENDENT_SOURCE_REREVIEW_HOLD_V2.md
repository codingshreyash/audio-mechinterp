## Remaining bounded-contract blockers

1. **Mutable caps can relax the frozen per-arm policy.** `run_synthetic_protocol` checks the caller's `caps` dictionary once and writes its original value into `synthetic_scope.json`, but later wall, VRAM and per-arm output checks read that same mutable object (`live_parity_launcher_v1.py:132–144, 181–184, 210–214, 257–259`). In a no-model reproduction, an `official_sample` fake worker changed `caps['output_bytes']` from **8,192** to **65,536** and wrote an extra 9,000-byte artifact. The complete five-stage run succeeded; the official-sample directory held **9,694 bytes** while its saved scope still claimed an **8,192-byte** per-arm cap. The local total cap did remain frozen, so this is a per-arm policy/provenance bypass. Snapshot and use all cap values immutably throughout the run, then add a worker-mutation negative test for output, time and VRAM caps.
2. **Response rereads can precede the size guard.** The stock-arm precheck, within-arm tamper check, and final precomparison use `response_path.read_bytes()` (`164–166, 246–247, 271–274`) instead of a stat-checked bounded stream. A deterministic fake `rehash_inputs` callback can enlarge `api_response.json` after adapter discovery and immediately before the stock-arm precheck. With a guarded `Path.read_bytes`, the launcher attempted to read the oversized **100,000-byte** response before `_evidence_bytes` could reject it. The same gap exists before final comparison. Recheck the total/per-file cap before every response read, use a bounded streaming digest, and add negative tests for tampering at both read sites. The changed digest must still fail, but only after a bounded read.

The second reproduction requires mutation of the synthetic callback or filesystem between checks. It is a resource-bound and evidence-order failure, not a demonstrated model or security behavior.
