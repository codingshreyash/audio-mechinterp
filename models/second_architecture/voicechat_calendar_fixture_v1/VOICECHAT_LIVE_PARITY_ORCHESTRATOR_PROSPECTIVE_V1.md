# Prospective VoiceChat official/adapter live parity orchestration — V1

18 November 2026. **Design only. No model load or parity result.** This plan fixes the order and evidence for a single official-helper identity pilot on one already rendered VoiceChat calendar WAV. The source-approved `official_adapter_parity.py` is a low-level capture/comparison utility; it does not establish a QA-approved input, a stock model load, identical initial state, or durable evidence. This protocol is prospective to those steps. It requires an independent conceptual review, then a separate implementation/source review and external executable freeze before live use.

## Fixed question and scope

On the exact final WAV for case `B`, voice `piper_amy_en_us`, in the frozen 12-clip render, does the QA-gated two-pass adapter produce the same pass-1 and pass-2 raw model outputs, parsed call, replay tokens, TTS codes and unspliced audio as the pinned NVIDIA helper when both receive the same initial checkpoint state and random seed? Use the same pinned NeMo Speech commit `097dfe9e2f55baf653b83035868bdc89849f1b47`, VoiceChat checkpoint revision `443794ea956ef0065f001967ffd00e77f519cb39`, Nano metadata revision `6533e8de2c68e4536bf7c411d7a3ce5734111476`, calendar template, tools, system text and WAV bytes already specified by the fixture. Case `B` is fixed before model output; if it produces no parseable call, report that fact and **do not select another WAV after inspection**. A new reviewed plan would be needed to test the injected-call branch on another clip.

This is an **instrumentation identity** pilot. A passing parity comparison does not establish a speech/tool mismatch, authorization failure or security finding. A failing comparison identifies an instrumentation or stock-repeat problem to debug before interpreting any calendar case. It does not by itself identify a model defect.

## Hard pre-load gates

Before importing NeMo into the inference process or loading any VoiceChat weight, require the accepted 12/12 v2 human listening manifest, every triggered independent second/third listening review, both independently authorized case-C controller grants, and the immutable external pre-inference anchor. Run `check_audio_qa_v2` on the exact manifest and ledger, verify the selected B receipt and WAV hash, and preserve the exact QA manifest, ledger, receipt, grants and external anchor descriptor in the run evidence. The existing local validator checks hashes and chronology but **cannot authenticate the external store or the identities of human reviewers**; an independent controller must attest those facts separately. A local success flag is not a substitute.

Run the existing pinned H100/A100 `ready` then `preload` source/checkpoint/Nano/runtime checks in their documented order and environment, and archive their exact outputs. The production launcher must verify the same preflight hashes and source commit again immediately before each fresh model process. Do not use a caller-supplied loaded model as proof of checkpoint identity. Require the unchanged pinned `examples/speechlm2/offline_voicechat_fc_infer.py` on its published `examples/speechlm2/sample_audio/sample_fc.wav` with `examples/speechlm2/function_calling/random_number_response.json`, with all three sample files and the exact command hash-bound before fixture inference. The sample is an environment check, not evidence for the calendar fixture. If any gate, sample source, checkpoint hash or cache identity is absent or changes, stop before the fixture's model load. Do not fabricate a human record, C grant, anchor or sample result in source tests.

## Arm order and initial-state equivalence

Use **fresh model processes** for the official sample and every fixture arm. Each fixture process must start from the same pinned checkpoint bytes, identical prompt/WAV bytes, generation settings and fixed random seed; record CUDA/PyTorch deterministic settings, package versions, and a process-specific environment/source receipt. Reloading in a new process is the reset. No in-place `model.eval()` call, RNG reseed or `state_dict` hash alone proves that internal generation caches reset. If a fresh-load arm exceeds the prospective runtime/memory envelope, stop rather than silently reuse a mutated instance.

After the sample passes, run exactly one **adapter discovery arm** first. Its QA-gated `run_live_case_from_audited_wav` loads the selected WAV through the pinned official loader, renders and tokenizes the exact pinned prompt, snapshots each unmodified pass before parsing or response selection, uses only the inert `calendar_stub.dispatch`, and saves the complete raw trace. Its first parsed call fixes the one `api_response` object for the three stock arms. If there is no parseable call, use a frozen harmless placeholder response for the official helper's required argument, record the no-call branch, and require that no call/response tensors were injected. This adapter-first order is necessary because the stock helper requires a prewritten response **before** its first pass. It must not become a search over responses or clips.

Next run stock A and stock B with the pinned, unchanged `run_fc_offline_inference` and the same prewritten inert response. A passive wrapper captures its two original `run_offline_inference` calls and return dictionaries without changing arguments or return values. Run stock C with the same helper and response but no TTS-code wrapper, to test whether passive code capture changes generation. Stock A/B/C and adapter must use the same audited WAV, official `load_wav_16k_mono`, `render_fc_system_prompt`, `encode_system_prompt`, exact prompt token tensors, model checkpoint, seed and generation defaults. Compare exact input tensors, pass labels and replay tensors using `compare_stock_adapter`; exact discrete IDs/lengths/parser objects must match, and all three pairwise unspliced PCM maximum absolute differences must be at most the predeclared `1e-4`. The stock A/B repeat must pass independently; do not widen the tolerance post hoc. If the official helper omits optional `tokens_audio`, report no raw audio-token-ID claim, while still requiring observed nonempty TTS codes in wrapped pass 2.

The comparator checks one captured output; the launcher must verify **provenance**: stock and adapter arms used the same independently bound WAV/PCM, prompt bytes/tokens, model state and seed. The official helper's final WAV writer may splice out a tool gap; compare the raw pass-2 audio first and treat final saved WAVs as separate transport artifacts. Never send any parsed call to a live calendar, MCP server or external API.

## Evidence, resources and stopping

Create one immutable run ID and exclusive arm directories before the first model load. Predeclare a finite per-process wall-time, VRAM and output cap in an external freeze after a source-only resource estimate; stop on a missing or partial arm and preserve it rather than retrying under the same ID. Record every command, return code, stdout/stderr, start/finish UTC and monotonic elapsed time, seed, CUDA/GPU/package settings, exact source/checkpoint/WAV/QA/sample hashes, pass-1 and pass-2 raw tensors, TTS codes, call arguments, parser output, injected token tensors, unspliced PCM and comparator result. Hash each saved artifact. Keep all four fixture arms in the denominator, including failures, no-call behavior and stock instability. The external freeze must pin the executable source/tests, review commits, selected case/voice, sample and fixture WAV hashes, model and helper hashes, arm order, seed, generation settings and caps.

The source-only implementation should use injectable fake loader/model/official helper objects to exercise gate ordering and four-arm comparison without CUDA or fabricating human QA. Tests must reject missing 12-row QA/anchor/grants, changed source/checkpoint/WAV, different prompt/input/seed or model factory, changed first-pass response, missing pass capture, partial replay injection, TTS capture failure, stock instability, output cap and rerun of a consumed arm. An independent reviewer must inspect the exact implementation and rerun those tests before the external freeze. A separate reviewer must inspect the freeze before the published sample or fixture model is loaded.
