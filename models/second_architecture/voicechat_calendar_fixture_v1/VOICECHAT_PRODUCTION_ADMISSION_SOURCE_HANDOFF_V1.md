# VoiceChat fixture production admission source handoff v1

Status: **source candidate, live calendar fixture HOLD**. No VoiceChat
weights were loaded while implementing or testing this module.

`live_parity_production_admission_v1.py` adds an explicit pre-load gate. It
accepts only a real, canonical fixture source plan with the fixed case-B Piper
WAV and five-stage order. It recomputes the complete `_input_hashes` map,
including the system message, tools JSON, template, pinned NeMo helper and
model/checkpoint bytes. It validates the full v2 QA cohort and selected exact
receipt, calls an external-anchor attestation hook, checks current source-role
hashes against a separately reviewed source record and executable freeze,
verifies that every reviewed role has those exact bytes in the named Git
source commit, verifies a keyed freeze-review HMAC, reruns `ready` then
`preload`, and hashes
all inputs and source roles again before returning. The external attestation
hook is closed by default; this module cannot admit a live run on its own.
The freeze binds the exact nonsecret child-environment allowlist and its hash.
The supervisor adds only the two admission keys to that allowlist while
starting the worker; it does not forward arbitrary parent variables. The
worker replaces its entire `os.environ` with the frozen public allowlist
immediately after admission, removing both keys and every unrelated inherited
variable even if admission fails. It checks full environment equality before
model creation and after use. Torch can add a local compiler-cache variable
while it initializes, so the worker restores the frozen allowlist again after
Torch setup and before the adapter arm. It also checks equality after the
NeMo helper import and before the model factory. Direct worker calls with
extra parent variables fail at the model-factory boundary.

`live_parity_single_process_supervisor_v1.py` adds one fresh adapter-child
boundary. Its default official-sample verifier is also closed. After real
admission and a reviewed sample receipt, it reserves an exclusive run root,
launches the fixed worker module through the resource-bounded process runner,
checks actual PID/resource return and the complete nested evidence inventory,
reopens the lossless adapter capture, derives the prospective stock response
bytes from the saved trace, and preserves a consumed run on failure. It stops
there. It does not launch or compare the stock arms.
The reviewed fixture freeze carries the official sample receipt SHA-256.
Parent and child each require an independently verified match before
proceeding. Both default sample verifiers raise, so a direct child invocation
cannot skip this boundary.

The source record and freeze review are controller-owned, not generated by
this module. A fixture run needs an independent controller to authenticate the
human reviewers, both C grants, external immutable anchor, source reviewer,
freeze reviewer and HMAC key custody. A caller knowing the key is not by
itself evidence of independent review. CPU tests use temporary synthetic
review records only for code-path checks; none is a human, grant or anchor
record, and none is shipped as run evidence.

## Remaining gates

- Independently review this source/tests, then pin exact hashes and source
  commit in the external source review. The freeze must be created after it;
  a different reviewer must approve the freeze with a controller-held key.
- Connect the external attestation hook to a real read-only controller source.
  Keep default admission closed until the actual 12/12 human QA, grants and
  pre-inference anchor exist and pass review.
- Independently verify the child environment policy and controller key custody.
  The reviewed child still receives the two keys for its own pre-load QA and
  freeze checks; the pinned preflight subprocess executes during that
  admission. The keys must be gone before any NeMo import or model factory.
- Bind a fresh-process supervisor and official sample result to this
  admission. The present supervisor covers one adapter process only and its
  default reviewed-sample verifier raises. Authenticate the official sample
  receipt under the same frozen source/checkpoint identity before connecting
  that verifier. Extend to three fresh stock processes, rechecking source
  before and after each, with no silent retries. Current parent and child both
  recheck complete source-plan hashes around the adapter run.
- Bind the stock response expected hash to bytes computed from the saved
  adapter capture before stock A; do not accept a caller-selected hash.
- Compare saved raw captures, including exact final trimmed codec codes, with
  the predeclared stock-repeat and adapter identity criteria. A parity pass
  proves instrumentation identity only.

The worker module's direct diagnostic CLI shape is:

```text
python -m models.second_architecture.voicechat_calendar_fixture_v1.live_parity_fixture_worker_v1 --plan PLAN --freeze FREEZE --freeze-review REVIEW --nemo NEMO --checkpoint CHECKPOINT --nano NANO --qa-manifest QA_MANIFEST --qa-ledger QA_LEDGER --qa-receipt QA_RECEIPT --wav FIXED_B_PIPER_WAV --output EXCLUSIVE_RUN_ROOT
```

The supervisor's exact process command uses a reviewed `python -c` bootstrap
to insert this checkout into `sys.path`, then calls that same worker `main`.
The pinned preflight uses NeMo alone as `PYTHONPATH`, and the bounded executor
sets the run directory as cwd; `python -m` without this bootstrap would fail
to import the local worker package. The output root must
already be reserved by its supervisor. The CLI uses only the default real
admission. Currently it stops at the closed external-anchor hook, even with
well-formed local arguments. This example is an interface, not a request to
run it.
