# Independent source review: VoiceChat step-400 probe core V1

19 November 2026. **HOLD on this source revision (`b752143`); no GPU/model inference.** I reviewed `voicechat_step400_probe_core_v1.py`, its eight fake-model tests, and its handoff against the independently reviewed diagnostic V1/V2 design and NVIDIA NeMo Speech at pinned commit `097dfe9e2f55baf653b83035868bdc89849f1b47`.

The pinned `NemotronVoiceChat.offline_inference` loop calls `_step_inference(t, inference_state, ans, force_bos_positions)` and then `infer_codes_one_step` with the eight kwargs required by the probe, for `t` in `range(1,T)`. The TTS return is `(code, past_key_values)`; `gen_codes[:,t]` is written only after it returns. The official function-call helper does not parse or start pass 2 until pass 1 returns. The core's dedicated step-400 exception therefore targets the specified post-TTS/pre-`gen_codes` point. The core has no launcher or model-loading entrypoint. The pinned local `models/second_architecture/.venv` ran all eight no-model tests successfully; system Python lacks Torch and is not the test runtime.

**Blocking source issue:** `inventory_carried_state` puts dictionary keys verbatim into the serialized `tensor_rows[].path` and `unknown[].path`. A direct no-model reproduction with `{"DEMO_SECRET_CONTENT": torch.ones(1)}` produced `"path": "stt.DEMO_SECRET_CONTENT"`. This is a generic metadata walker over an inference-state dictionary, and the V1 design prohibits serializing prompts, token IDs, decoded text, audio, and model outputs. The current source cannot prove that future dictionary keys contain only approved structural names. Replace saved key text with a bounded structural index or approved static label, and test that a content-bearing key never appears in JSON. Preserve useful container paths without retaining values or raw keys.

The source correctly keeps storage pointer identities in memory only, de-duplicates shared storage across STT and TTS, records six ordered checkpoints, establishes the first interval baseline/reset, fsyncs its bounded ledger, and restores instance methods after a planned stop. These are source/fake-test observations, not a live cache-shape or memory result. The `nvidia-smi` subprocess checks its output size after capture, so a later parent watchdog must bound process telemetry independently. A complete executable still needs exact helper/source binding, an external resource supervisor, partial-failure sealing, host freeze, independent executable review, and a separate one-shot GO.
