# Independent source rereview of the VoiceChat parity plan builder

18 November 2026. I rereviewed corrective commit `d392542` against the [source HOLD](VOICECHAT_LIVE_PARITY_SOURCE_PLAN_INDEPENDENT_REVIEW_HOLD_V1.md), prospective protocol `8795015`, and conceptual GO `8cf7127`. Source SHA-256 values are `a4d751bfb5a176d2c5d03e4abd7f1eeda0d83bbda3c28ad1b26c552ac7f6a73c` for `live_parity_source_plan_v1.py`, `63347598df6b1c7c8f163c4f241ded066a995a45067765920febe0ed87793b0f` for its main tests, and `04e9d2a861c378318f1c7d6c9dd3a2c6f99c9cc0d9f9ef1329208cdb251b3113` for the preserved review regressions. **Decision: GO for the source-only VoiceChat parity plan builder. Live model parity remains on HOLD.**

I ran the 12 plan-builder tests, the three former HOLD reproductions, and 13 related low-level parity tests: **28/28 passed**, with no expected failures. I also inspected the correction. The production CLI calls the real `ready` preflight, then `preload`, before writing an exclusive plan file. Each phase receipt stores command, UTC start/finish, parsed output, exact stdout/stderr text and hashes. `_check_phase_pair` requires ready to finish before preload starts and compares their checkpoint, NeMo, VoiceChat, full-cohort QA, C-grant, Nano, GPU, and source-count identity fields. It requires the ready offline resolver and preload environment checks reported by the pinned preflight. These are source assertions; no real preflight was run without the missing human QA.

The builder now snapshots hashes of the selected and all cohort WAVs, QA manifest/ledger/receipt, frozen render, protocol/review/preflight source, system message/tools, checkpoint config and weight, six Nano metadata files, and pinned NeMo/sample files. It checks the same set immediately after `ready` and again after `preload`, and compares the phase-reported QA/config/weight hashes to that set. The three saved counterexamples—changing the selected WAV, QA manifest, or official sample WAV during preflight—now raise rather than yield a plan. The plan uses the initially validated hashes, records both phase receipts, and marks test-injected plans as synthetic. The CLI does not offer injected checker arguments.

This GO covers an **admission and plan artifact without model work**. I did not run the official NVIDIA sample, load VoiceChat, create human listening or controller records, authenticate the external anchor, execute a calendar tool, or observe a speech/action mismatch. The builder does not implement fresh model processes, four-arm capture, caps, saved raw evidence, or the live comparator run; its handoff lists those later requirements. The future launcher must revalidate the plan and all bound bytes before each model process and receive its own source review and external executable freeze. A passing future parity check would establish instrumentation identity, not by itself a security finding.
