## Evidence checked

Attempt 003 reached `Model ready` before its exact `torchaudio.load` path failed while TorchCodec tried FFmpeg backends and could not find `libavutil.so.59` for major 7 (or the corresponding library for the other majors). The missing library is the demonstrated blocker; no audio or response was generated. [Saved stderr](runs/public_sample_existing_a100_attempt_003/voicechat-sample-output-003/stderr.log). [TorchCodec's tagged installation instructions](https://github.com/meta-pytorch/torchcodec/blob/v0.10.0/README.md#installing-torchcodec) support FFmpeg majors 4–8 with separate shared libraries, and its [0.10 release](https://github.com/meta-pytorch/torchcodec/releases/tag/v0.10.0) states compatibility with PyTorch 2.10.

The plan's micromamba `2.9.0-0` `micromamba-linux-64` SHA-256, `366cd9cd8be14df1ab8ed50352a82111082a36686b2d389fdb79a92c3fafb3e3`, **matches the official GitHub release API asset digest** at `https://api.github.com/repos/mamba-org/micromamba-releases/releases/tags/2.9.0-0`. This verifies the published value, not bytes on the future host; the host must check downloaded bytes before execution. [Micromamba installation guidance](https://mamba.readthedocs.io/en/stable/installation/micromamba-installation.html) documents a self-contained binary and `MAMBA_ROOT_PREFIX`, but also says existing `.condarc`/`.mambarc` files may be read. [Micromamba's spec guide](https://mamba.readthedocs.io/en/stable/user_guide/micromamba.html#explicit-spec-files) and [Conda's explicit-spec guide](https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-environments.html#explicit-spec-files) support single-platform `@EXPLICIT` URL/checksum locks. The [conda-forge FFmpeg file index](https://anaconda.org/conda-forge/ffmpeg/files/manage?page=0&version=7.1.1) lists `linux-64` 7.1.1 builds. The version selector alone does **not** pin a build or its dependencies; the post-solve archive hashes and explicit lock are essential.

The fallback plan states that the Ubuntu extraction left over 40 unresolved transitive SONAMEs and an apt simulation proposed 93 installs plus 15 upgrades including `libstdc++6`. I could verify the prior attempt's TorchCodec failure in the retained archive, but did **not** find the apt dry-run or linkage output in the committed attempt-003 evidence. Treat those counts as a reported staging observation, not an independently rehashed fact. They do not affect the decision to keep the Ubuntu route stopped.
