## Observed host and arithmetic

After the instance was started for inspection, `nvidia-smi` reported one **NVIDIA A100 80GB PCIe, 81,920 MiB**. `/home/ubuntu/qwen-py312/bin/python` is Python 3.12.16; `/usr/bin/python3` is 3.10.12. `df -B1` reported **92,438,319,104 free bytes on root** and **119,767,867,392 free bytes on `/data`**, an empty mounted ext4 filesystem. The root filesystem is about 133.0 GB and `/data` about 126.2 GB. The separate 960 GB `nvme0n1` has no filesystem or mount in `lsblk -f`; this plan does **not** format, mount, or touch it. Recheck all readings just before setup; a transient SSH failure occurred on a later read, so a successful shell is another gate.

The pinned `model.safetensors` is **44,382,749,892 bytes** (41.33 GiB). If staged exactly once on `/data`, the arithmetic leaves **75,385,117,500 bytes** (70.21 GiB) before the small config, metadata, and any residual cache. The shared [preflight](../voicechat_h100_local_preflight.py) requires **at least 60 GiB = 64,424,509,440 bytes free on the checkpoint filesystem after staging**. The apparent margin is only **10,960,608,060 bytes** (10.21 GiB). Any second weight copy on `/data`, extra model file, incomplete download, Xet cache, or retained outputs can consume that margin. The previous 150–160 GiB single-filesystem planning margin cannot be met here; the split layout is viable only if the measured poststage hard gate passes without relaxing it.

## Storage layout and fail-closed gates

1. Before writing, save `date -u`, `brev ls --json`, `id`, `nvidia-smi --query-gpu=name,memory.total --format=csv,noheader,nounits`, `lsblk -f`, `findmnt /data`, and `df -B1 / /data` locally. If any fail, stop the instance and do no setup. Do not delete or prune pre-existing root, Qwen, or `/data` content.
2. Put a new pinned NeMo checkout, a **new** Python 3.12 venv, pip/build temporary files, the reviewed local runner, Nano's dedicated six-file HF cache, and receipts on root under unique `/home/ubuntu/voicechat-sample-*` paths. Do not reuse or change `/home/ubuntu/qwen-py312` or `/home/ubuntu/audio-mechinterp`. Keep the NeMo checkout clean as the shared preflight requires. Bind the final absolute paths and package versions in the host-specific freeze.
3. Stage the VoiceChat checkpoint once in a new HF hub cache on `/data` with `huggingface_hub.snapshot_download(repo_id="nvidia/NVIDIA-NemotronLabs-VoiceChat-11B", revision="443794ea956ef0065f001967ffd00e77f519cb39", allow_patterns=["config.json", "model.safetensors"], cache_dir="/data/voicechat-sample-hub")`. Use its returned **pinned snapshot path** directly as `checkpoint_dir`; `model.safetensors` is then a snapshot symlink to the one blob in the same `/data` cache, not a second local-dir copy. Put `HF_HOME`, `HF_XET_CACHE`, and temporary download/build caches on root during this network staging step so residual caches do not spend the `/data` margin. Do not use `hf download --local-dir`, copy the weight out of the blob store, or download Nano weights. The reviewed runner's source hash gate rejects symlinked source files; the shared checkpoint preflight reads and hashes the checkpoint symlink's target. Verify the snapshot's resolved path, exact config/weight hash and weight size.
4. Save `df -B1 /data`, `du -sb /data/voicechat-sample-hub`, and `df -B1 /` after each major staging step. Abort on less than **60 GiB free on `/data` after checkpoint staging**, less than **20 GiB free on root**, any second 44 GB weight copy, a changed checksum, or any attempted write to the existing Qwen environment. Do not work around a failed shared preflight or move its threshold. Set `HF_HOME`, `HF_HUB_CACHE`, `HF_MODULES_CACHE` to the dedicated **Nano** cache, plus its required offline flags, only for the final admission and model child. No model-related network is permitted after that offline switch.
5. Require the unchanged [H100 source packet](VOICECHAT_PUBLIC_SAMPLE_H100_EXECUTION_PACKET_20261119.md) pins, six-role source review, and `public_sample_smoke_v1.expected_freeze_fields(..., "a100-80gb")`.
