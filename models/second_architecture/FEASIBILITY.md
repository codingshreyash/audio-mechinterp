# Second audio architecture: feasibility and first gate

**Decision (18 November 2026):** use **LiquidAI/LFM3-Audio-2B** for the first cross-architecture replication **after confirming the intended organizational use is covered by its license**. It is a substantive change from the local Qwen2.5-Omni-3B experiment: a causal, stride-8 audio encoder feeds an LFM3 hybrid convolution/attention language model; it can answer in text or generate speech. The published BF16 checkpoint is small enough for this 48 GiB Apple Silicon Mac. PyTorch/MPS execution still needs a smoke test; the official example only specifies CUDA or CPU. If license clearance is unavailable, use the Apache-2.0 **mistralai/Voxtral-Mini-3B-2507** as a lower-priority fallback. Its Whisper-like encoder → text decoder topology gives a weaker architecture contrast, but it supports audio question answering and native Transformers hooks. [LFM3 model card](https://huggingface.co/LiquidAI/LFM3-Audio-2B); [Voxtral model card](https://huggingface.co/mistralai/Voxtral-Mini-3B-2507).

## What is being replicated

The existing local [controlled-pairs study](../../eval/controlled_pairs/FINDINGS_V1.md) asks where the information about a spoken word enters and affects a *complete* text answer. It has paired audio with a measured word interval, matched text prompts, encoder/connector/decoder interventions, and sham and random controls. Its [held-out follow-up](../../eval/heldout_flow/FINDINGS_V1.md) limits claims about transfer of a particular late decoder boundary. The second model should test whether time-resolved word information and a causal effect appear at comparable *functional* interfaces; layer numbers or coordinates need not transfer. A correct word answer by itself is a capability check, not a mechanism or security finding.

## Instrumentable path

The pinned [feature extractor](https://huggingface.co/LiquidAI/LFM3-Audio-2B/blob/2d6c1f99c129b3ef07a8d168bc0ff08e2bdb93f1/feature_extraction_lfm3_audio.py) takes 16 kHz mono audio, uses 400-sample windows and 160-sample hops (25 ms and 10 ms), `center=False`, 128 mel bins, and a fixed log-mel floor. The three stride-2 convolutions reduce eight mel frames to roughly one audio token per 80 ms. The extractor explicitly computes the STFT on CPU. Unlike the Qwen experiment's clip-relative log floor, this front end uses a fixed floor; nevertheless verify actual feature equality outside a changed word before describing any localization. [Pinned config](https://huggingface.co/LiquidAI/LFM3-Audio-2B/blob/2d6c1f99c129b3ef07a8d168bc0ff08e2bdb93f1/config.json); [pinned encoder](https://huggingface.co/LiquidAI/LFM3-Audio-2B/blob/2d6c1f99c129b3ef07a8d168bc0ff08e2bdb93f1/modeling_lfm3_audio.py).

Hook sites from `Lfm3AudioForConditionalGeneration` (verify names with `named_modules()` after load):

1. **Encoder:** `model.model.audio_encoder.downsample` and `model.model.audio_encoder.lfm.layers[i]`, `i=0..16`. Log the input/output shapes and map the measured word interval through the actual processor padding and stride. The encoder is causal and has past context, so a row after the word may still carry word information.
2. **Connector:** `model.model.audio_projector`. `get_audio_features()` selects valid encoded frames, projects width 768 → 2048, and returns a flattened tensor of audio tokens. Save valid-frame lengths and ordered audio-placeholder positions.
3. **Decoder handoff:** `Lfm3AudioModel.forward` inserts the projected audio vectors into `<|audio|>` token positions with `masked_scatter`, then calls `model.model.language_model`. Record the replacement mask and the first decoder input embeddings; check equality of the unpatched hook and no-hook logits before intervening.
4. **Decoder:** `model.model.language_model.layers[i]`, `i=0..23`, and final generated token IDs. Score the decoded **full answer and stop condition**, not only a target-token logit.

All four interfaces are explicit in the [pinned implementation](https://huggingface.co/LiquidAI/LFM3-Audio-2B/blob/2d6c1f99c129b3ef07a8d168bc0ff08e2bdb93f1/modeling_lfm3_audio.py). Do not transfer Qwen's layer-31 patch or assume 80 ms rows are independent phoneme slots. Use a measured word interval, one-frame-expanded candidate rows, and separate on-word/off-word and same-source-sham controls.

## Minimal bounded full-answer smoke plan (not yet run)

1. Clear the license gate. In a clean environment pin the above model revision and `transformers==5.20.2`; download only then. Load with `AutoProcessor.from_pretrained(..., revision=REV, trust_remote_code=True)` and `AutoModelForMultimodalLM.from_pretrained(..., revision=REV, trust_remote_code=True, dtype=torch.bfloat16)`, then move the model to `mps`. The official example picks CUDA or CPU; the pinned convolution source uses a CUDA fast path only when `hidden_states.is_cuda` and otherwise has a PyTorch fallback, which makes MPS plausible but does **not** prove end-to-end MPS support. If a specific operator fails, record it and try a **single CPU smoke**; do not silently switch implementations. [Official quick start](https://huggingface.co/LiquidAI/LFM3-Audio-2B#transformers-quick-start); [pinned convolution implementation](https://huggingface.co/LiquidAI/LFM3-Audio-2B/blob/2d6c1f99c129b3ef07a8d168bc0ff08e2bdb93f1/lfm3_conv.py).
2. Reuse one existing 3–5 second red/blue paired English WAV clip and its typed equivalents. Preserve bytes and record SHA-256, sample rate, duration, processor output shapes, input-token count, model/processor revisions, dtype, device, PyTorch/Transformers versions, and MPS peak allocation. Batch size 1; run under `torch.inference_mode()` with at most 64 new tokens and an explicit greedy setting. Abort this first gate if memory exceeds a conservative 30 GiB or the output does not terminate normally.
3. Use the same short question for both audio and typed input (for example, “What color was spoken? Reply Red or Blue.”). Build inputs with `processor.apply_chat_template(..., add_generation_prompt=True, tokenize=True, return_dict=True, return_tensors="pt")`. Generate **text only** with `suppress_mixed=True, suppress_audio_out=True`, as the official card directs; capture raw generated IDs and decode only the generated suffix. Evaluate the **complete answer** against the two paired labels, not a next-token score. [Official audio-Q&A example](https://huggingface.co/LiquidAI/LFM3-Audio-2B#usage-examples).
4. Repeat one clean clip with passive shape hooks and require identical token IDs to the no-hook run. Only if clean audio and typed controls are both correct and hooks are inert, freeze a small causal protocol: encoder word-window patch, connector word-window patch, self-source sham, matched off-word patch, and norm-matched random patch. Compare full answers; keep a separate unpatched same-word acoustic variation panel for robustness. Do not claim transfer or a vulnerability from a single pair.

## Fallback and rejected alternatives

**Apache fallback: Voxtral Mini 3B 2507.** The [official model card](https://huggingface.co/mistralai/Voxtral-Mini-3B-2507) states Apache 2.0, audio question answering, native function calling, and Transformers support (`VoxtralForConditionalGeneration`, `AutoProcessor`, Transformers ≥4.54). Its BF16 deployment note estimates ~9.5 GB GPU RAM. An MPS smoke is still necessary; the shown example uses CUDA. The [official configuration](https://huggingface.co/mistralai/Voxtral-Mini-3B-2507/blob/main/params.json) describes a 32-layer, width-1280 Whisper-family audio encoder plus a 30-layer, width-3072 text decoder. It is useful if LFM3 cannot be used, but it is another encoder→LM stack and lacks generated speech, so a positive result would support a narrower cross-architecture claim. Pin an exact Voxtral revision and Transformers version before loading; no Voxtral weights were fetched in this review.

**Not first:** [Voxtral Mini 4B Realtime 2602](https://huggingface.co/mistralai/Voxtral-Mini-4B-Realtime-2602) is Apache 2.0 and architecturally interesting (causal streaming), but its model card identifies it as a *transcription* model, not a general question-answering voice assistant; it cannot run the same full semantic answer assay without changing the task. [Kyutai Moshi](https://huggingface.co/kyutai/moshika-pytorch-bf16) is a stronger full-duplex speech-architecture contrast, but its 8B PyTorch checkpoint and CUDA-centered reference path make a 48 GiB Mac hook-and-patch replication substantially less certain. [Step-Audio-2-mini](https://huggingface.co/stepfun-ai/Step-Audio-2-mini) is closer to another audio-encoder/Qwen decoder pipeline and has already served a separate tool-call investigation; it is less informative for this particular architecture contrast.

**Status:** source and local-repo feasibility review only. No model weights downloaded, no GPU/MPS inference run, and no causal claim made for LFM3.
