# Independent source review: VoiceChat two-pass adapter `cac4a78`

**Verdict: no-go for a live calendar assay yet.** The source-only adapter reproduces the pinned helper's basic two-pass shape, but a signed-grant/QA-receipt binding is missing. No model, cloud, or real tool was used in this review.

I fetched the exact [NeMo offline helper](https://github.com/NVIDIA-NeMo/Speech/blob/097dfe9e2f55baf653b83035868bdc89849f1b47/nemo/collections/speechlm2/inference/utils/offline_voicechat.py) and [function-call template](https://github.com/NVIDIA-NeMo/Speech/blob/097dfe9e2f55baf653b83035868bdc89849f1b47/examples/speechlm2/function_calling/template.jinja) at revision `097dfe9e2f55baf653b83035868bdc89849f1b47`; their SHA-256 values match the adapter's `ebde701b...8da44` and `8b4f88e9...5edcc9` pins. The adapter calls `decode_audio=False` in pass 1, uses the predicted function stream and the first extracted call position, applies the stock tag cleanup and JSON parse, and injects a default-`json.dumps` one-object `<TOOL_RESPONSE>` with call step `start_pos` and response step `end_pos+1`. Pass 2 calls `decode_audio=True` with six stock-shaped function tensors when a first call parses, otherwise with no injection. It retains later positions and labels pass-2 calls as counterfactual proposals. It does not execute a calendar action or splice the returned waveform. These choices match the [fixture hardening review](VOICECHAT_CALENDAR_FIXTURE_HARDENING_REVIEW.md) and the official helper's first-call replay limit.

**Blocking counterexample:** `run_two_pass` verifies the input file hash and the supplied QA receipt's asserted WAV fields, then passes `confirmation_state` to `dispatch` without comparing its signed `qa_receipt_sha256` to the actual supplied QA receipt. In a fake-model probe, I signed a C grant with the correct case, WAV hash, date, event ID, and controller key but `qa_receipt_sha256` set to 64 `f` characters. A canonical serialization of the supplied receipt had a different SHA-256 (`5d5f85d804503a580a38d6b570bd1247ae2d24432abf1c4fb6aaa008`); the first-pass cancel still received `authorized_dry_run` and `independent_confirmation_granted=true`. `executed=false`, so this is an authorization-record integrity defect in the inert dispatcher path, not a real cancellation. Fix by defining the receipt's exact signed bytes, hashing the actual immutable receipt artifact, and requiring equality with the HMAC grant field before any C authorization; test mismatch and tampering.

The low-level adapter also accepts `input_signal` from its caller and cannot prove it came from the hashed `wav_path`. Its receipt validator accepts asserted identity/listening fields but does not verify the full QA template or independent review. A live launcher must load the exact audited WAV, bind that tensor to its path/hash, verify the complete external QA record and prompt/template bytes, and persist pass 1 before pass 2. The current `on_pass_complete` persistence callback is optional; without it, a pass-2 failure can lose pass-1 evidence. These are pre-inference integration gates, not claims that the fake tests failed.

The `infer_codes_one_step` wrapper records returned per-step codes and restores the original method. It does not expose the model's final prompt-trimmed `gen_codes` or valid lengths, so a claim of exact final codec-token identity still needs the planned stock-versus-stock, stock-versus-adapter, and wrapper-off-versus-on parity runs. The handoff describes these checks, but they are not implemented or passed. Do not infer audible/function agreement or a model security finding from this source review.
