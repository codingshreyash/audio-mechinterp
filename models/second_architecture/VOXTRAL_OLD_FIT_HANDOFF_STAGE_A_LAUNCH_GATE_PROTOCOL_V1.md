# Prospective external launch gate for old-FIT handoff Stage A

**Source scaffold, 18 November 2026. No model run or external freeze is present.** This gate implements the two native arms of the reviewed [old-FIT handoff protocol](VOXTRAL_OLD_FIT_NUMERICAL_HANDOFF_PROSPECTIVE_V1.md). It is a posthoc numerical mechanism diagnostic on one already opened case. It does not advance the development gate or support a security claim.

Before any Stage-A model load, independent reviewers must approve the corrected native runner and CPU auditor, and a separate reviewer must approve the launch gate, its CPU tests, and this protocol. An external actor must then author and commit `VOXTRAL_OLD_FIT_HANDOFF_STAGE_A_EXTERNAL_FREEZE_V1.json`. The gate never creates or commits that freeze. The freeze must bind exact SHA-256 bytes for the protocol and GO plan rereview, native source/tests, runner/schema/GO source rereview, auditor/tests/HOLD review/GO auditor rereview, launcher/tests/this protocol/GO launcher review. It records the exact source, auditor and launcher review commits, which must be ancestors in that order. The source review commit must contain the reviewed runner files; the auditor review commit must contain the auditor files; the launcher review commit must contain the identical launcher files. Git first-add history must show that the freeze first appeared after the launcher review commit, with exactly one addition. Dirty or changed bound files and an absent, uncommitted, stale or malformed freeze fail before a model call.

Run `--check-freeze` first. Then Stage A permits exactly one fresh BF16 process followed by exactly one fresh FP32 process, using the pinned `.venv`, offline model cache and pinned runner command. No retry, fallback, skipped cell or alternate arithmetic is permitted. Each arm receives an exclusive local output directory and a permanent exclusive reservation. The launcher writes exclusive `launch_start.json` and `launch_finish.json`, captures child stdout and stderr, and invokes the frozen CPU auditor only after a successful runner result. A failed or timed-out run remains a failed attempt. BF16 must be independently audited before FP32 admission.

**The BF16 launch does not self-authorize FP32.** After a successful audited BF16 result, a separate actor must inspect the attempt and commit `VOXTRAL_OLD_FIT_HANDOFF_STAGE_A_BF16_ATTEMPT_MANIFEST_V1.json`. The manifest binds the freeze hash, one BF16 attempt directory, immutable start and finish hashes, runner result hash, auditor hash and measured model-process wall time. Git first-add history must show that the manifest first appeared after the freeze. FP32 admission checks those exact local files and receipt statuses; it also rehashes the runner's metadata, layout, progress and both local content-addressed tensor sidecars and compares sidecar byte counts and auditor hashes. A missing sidecar blocks FP32. The gate rejects any second BF16 attempt or existing FP32 attempt and requires enough of the 4,500-second total budget to complete a full 1,200-second FP32 arm. The future Stage-B gate must bind the BF16 and FP32 Stage-A manifests and count both measured times toward the same 4,500-second total across all four model processes and failed attempts. This Stage-A launcher does not authorize Stage B.

The runner's in-process ceilings are 900 seconds BF16, 1,200 seconds FP32, observed MPS driver allocation below 30 GiB and serialized output at most 1.5 GiB per arm. The launcher independently limits the child process to the arm cap plus 120 seconds termination grace, records its measured process wall time, checks the cumulative budget, and requires the CPU auditor to validate the runner's time, memory, tensor sidecars and output bytes. It drains stdout and stderr through bounded pipes (8 MiB each), monitors the **entire parent attempt directory**, and stops the child if that directory reaches the 1.5-GiB ceiling minus reserved space for logs and receipts. The same bounded capture and whole-directory check apply to the CPU auditor, which has a separate 120-second timeout. Success requires the whole directory, including logs and finish receipt, to remain below 1.5 GiB. The launcher rechecks the committed freeze after the model process and after audit. It preserves every receipt even when an audit or source check fails. Exact sidecars stay local and are required for independent audit; the small committed manifest alone is insufficient to reproduce raw tensor arithmetic.

This gate checks committed source bytes, process order, immutable receipts, resource evidence and saved-tensor audit. It cannot attest an in-process kernel trace or prove that a numerical mismatch is specific to audio. The independent result review must make those limits clear before any interpretation.
