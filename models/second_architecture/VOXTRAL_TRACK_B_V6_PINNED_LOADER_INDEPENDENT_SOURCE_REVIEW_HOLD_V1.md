# Independent source review: V6 pinned FP32 Voxtral loader

19 November 2026. **HOLD for a pinned private loader; public model loading is hard-HOLD.** I reviewed [loader source](voxtral_track_b_v6_pinned_loader_source_v1.py) at `5c32fea` against the [pre-pilot admission/launcher contract](VOXTRAL_TRACK_B_V6_PRE_PILOT_ADMISSION_LAUNCHER_INDEPENDENT_REREVIEW_GO_V2.md), the V6 worker/runtime adapter, and V3–V6 protocol. I ran the four fake loader tests: **4/4 passed**. No checkpoint, candidate audio inference, or GPU was loaded.

The private factory calls `verify_pre_pilot` before either processor or model factory, checks the proof's exact W/A/R pins, requires MPS, and configures the 30-GiB PyTorch MPS allocator fraction **before model load**. It asks for local processor/model files, FP32 dtype, MPS device map and SDPA. It checks actual processor/tokenizer types plus EOS 2 and audio ID 24, then checks model eval state, every parameter's FP32/MPS state, generation EOS/pad, and post-load driver allocation. The public `load_v6_pilot_model()` always raises. These are useful source-only controls; the allocator fraction is a PyTorch ceiling and the post-load reading is not a measured transient high-water.

**Blocking snapshot identity gap:** `_load_after_verified` accepts any caller-supplied `snapshot: Path`. `verify_pre_pilot` freshly hashes the separate pinned `base.SNAPSHOT`, but the helper never proves that the path passed to either `from_pretrained` is that verified directory. The production-only wrapper currently passes `base.SNAPSHOT`, while the fake test intentionally demonstrates that the helper can load from a different supplied path after a successful admission. Before a loader-source GO, the production composition must assert the resolved supplied path equals the frozen pinned snapshot path, and reject an alternate path **before either factory**. Keep the dependency-injected fake path behind an explicit test-only boundary if needed; do not make arbitrary snapshots an admitted live path.

**Blocking load-time byte gap:** the fresh preflight hashes the checkpoint tree and required config/index/shards/processor/tokenizer files before construction, but the loader does not rehash those actual bytes immediately before and after `from_pretrained`. A mutation between preflight and factory reads would escape this source slice. Recheck the exact pinned snapshot manifest and required file digests immediately before the first factory and again after model construction; compare both checks with the admission-bound frozen/fresh preflight fingerprint, and reject a changed resolved path or changed file byte. Add fake adversarial tests for an alternate snapshot path, a pre-factory file change, and a fake factory that changes a bound file during load. A post-check narrows the ordinary time-of-check/time-of-use window; it is not a guarantee against a malicious concurrent writer that changes and restores bytes during the read.

Live execution remains separately blocked by real 32/32 human QA and external A/R pins, a reviewed spawned-child composition, hard process deadline, sampled MPS high-water, post-run host verification, saved-data pilot audit, and post-pilot GO. This memo does not authorize any weight load.
