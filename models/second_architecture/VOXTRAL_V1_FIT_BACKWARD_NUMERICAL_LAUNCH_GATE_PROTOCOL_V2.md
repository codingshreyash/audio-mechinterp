# External launch gate for amended old-FIT BF16 numerical arm v2

**Prospective source control, 18 November 2026; no v2 model attempt yet.** The [v1 numerical protocol](VOXTRAL_V1_FIT_BACKWARD_NUMERICAL_FOLLOWUP_PROTOCOL_V1.md) fixes the one old-FIT beaver→monkey case, signed alpha grid, three repeats, hook sites, four LM29 coordinates and 15-minute / 30-GiB BF16 cap. The [v2 amendment](VOXTRAL_V1_FIT_BACKWARD_NUMERICAL_FOLLOWUP_AMENDMENT_V2.md) changes only the checkpoint parameter dtype acceptance rule and records its full loaded layout. The first v1 BF16 attempt failed before generation and remains preserved. The separately frozen v1 FP32 arm completed and remains under its original source freeze; this v2 launcher permits **BF16 only** and must never relabel that FP32 output as a v2 result.

Before any model load, an independent reviewer must inspect the v2 runner, CPU tests, auditor and this launcher. A separate actor then authors and commits `VOXTRAL_V1_FIT_BACKWARD_NUMERICAL_EXTERNAL_FREEZE_RECEIPT_V2.json` after that review. The receipt must bind SHA-256 bytes for the v2 runner/tests, v1 numeric protocol, v2 amendment, BF16 diagnosis, v2 auditor/tests, both reviews, v2 launcher/tests/this protocol/review, and the exact completed v1 FP32 result and auditor JSON. The review commit must be an ancestor of the freeze commit, contain the identical launcher source/tests/protocol/review bytes, and contain no v2 freeze receipt. The launcher must reject an absent/uncommitted receipt, changed bound file, malformed or stale review, or wrong arm. A read-only `--check-freeze` is required before `--run --arm bf16`.

One launch reserves a fresh exclusive parent directory before spawning the pinned v2 runner in a child directory. It writes a start receipt with source and old FP32 comparison hashes, uses offline model files and the same Python virtual environment, and runs the BF16 arm once with no retries or alternate dtype. The v2 runner retains its 900-second and 30-GiB MPS checks; the launcher gives its process 120 seconds of termination grace, rechecks source bytes afterward, then calls the pinned v2 CPU auditor if the child created a result or error receipt. Save the raw child stdout/stderr, child receipts and sidecar, auditor stdout, and immutable launch finish. Audit rejection or a resource/error receipt is a failed launch. The v2 auditor must recompute numeric terms and verify that the sole BF16 FP32 parameter exception was the audio position table.

The comparison of a future v2 BF16 result with the v1 FP32 result is only a one-case arithmetic diagnostic. Both arms retain their own source hashes and frozen approvals. The v2 launcher does not attest an in-process model execution, a continuously sampled memory cap, donor/no-grad terminal content, or model-to-security behavior. No fresh v2 corpus or locked test may be opened by this numerical follow-up.
