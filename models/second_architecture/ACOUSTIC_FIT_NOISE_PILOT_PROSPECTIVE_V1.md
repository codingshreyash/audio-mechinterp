# FIT-only acoustic-noise engineering pilot (prospective V1)

18 November 2026. **Source and preflight only until an independent review and separate GO receipt.** This is a small engineering extension of the [cross-architecture FIT case study](AUDIO_TIME_LOCALIZATION_CROSS_ARCH_CASE_STUDY_V1.md), not a held-out replication, a novel method, an adversarial audio attack, or a security finding. It asks: with the *same recorded word*, how do a fixed noise field and its location change preprocessing, internal activations and the **complete transcript** in Whisper Tiny English and Wav2Vec2 English CTC? No internal activation is edited in V1, so a state difference is descriptive, not a causal explanation.

For each voice, NumPy **2.3.5** `default_rng(60520261118)` draws `standard_normal(n)` float64 values. Normalize the draw by its whole-clip RMS, multiply by `mean(RMS(silver), RMS(teal))/10` in raw PCM units (nominal **20 dB** amplitude SNR), and round with `np.rint` to int64. The same seed is used for both voices, although their different lengths and signal levels yield different frozen vectors; the *same* vector is used on both words of a voice. Its int16 PCM SHA-256 must equal `c10e891886b119df5982bc7fb1f6795fe4963a35fca910c3dd5b7cf3d778448d` for Piper and `b010976dc8ef9db6bbbd6cccbe7a053cfe1ef0b7dac2b99a3b7e8be3dac44eb5` for Kokoro. `clean`, `clean_repeat`, `full_noise`, `word_noise` (noise only inside the original PCM word slot), and `outside_noise` (noise only outside that slot) are the **five fixed arms** per source: 20 forwards per model. Adding noise must not clip any source sample. Partial arms have less total noise energy than full noise and are location diagnostics, **not** equal-energy controls. No alternative noise realization, SNR or replacement clip after observing an output.

## Pinned models, measurements and controls

Run as **two separate CPU-only processes**, one model at a time, frozen/eval FP32 and four Torch threads. Whisper is `openai/whisper-tiny.en@87c7102498dcde7456f24cfd30239ca606ed9063`, checkpoint SHA-256 `db59695928ded6043adaef491a53ef4e12da9611184d77c53baa691a60b958ad`; use the stock processor and greedy `max_new_tokens=128` path from [the FIT Whisper runner](whisper_fit_word_window_causal_v1.py). Wav2Vec2 is `facebook/wav2vec2-base-960h@22aad52d435eb6dbaf354bdad9b0da84ce7d6156`, checkpoint SHA-256 `8aa76ab2243c81747a1f832954586bc566090c83a0ac167df6f31f0fa917d74a`; use **stock utterance-normalizing processor mode S** and the [audited FIT capture path](wav2vec2_fit_baseline_stage_capture_v1.py). The no-weight preflight hashes these checkpoint snapshots, processor assets, imported Transformers source, and runner/protocol source through those existing preflights. It records installed Torch/Transformers/NumPy versions. Changed dependencies require a new review.

For every arm, save source/derived PCM hash, complete Whisper generated IDs, decoded transcript and EOS/censoring, or full Wav2Vec2 framewise greedy IDs and decoded CTC transcript. Save each selected internal tensor's shape and byte hash, plus float64 whole, nominal word-window and complement L2 difference **relative to that clip's clean state** and outside-window max absolute difference. Whisper stages are mel, pre-block-0 encoder state, post-blocks 0–3 and final norm. Wav2Vec2 stages are processor output, first raw convolution, its GroupNorm output, final feature convolution, feature projection, pre-block-0, post-blocks 0/5/11 and logits. Word windows are fixed heuristics from the source slot; receptive fields and normalization may spread information outside them. `clean_repeat` must match the clean output and every saved state exactly. Keep all four source cases and all five arms even if clean transcription is wrong or noise changes the entire sentence. Count intended-word-only errors separately from any complete-transcript difference. No model-internal patch, causal localization, cross-model vector comparison or attacker-reachability claim is licensed here.

## Execution and stop gates

`validate-only` checks input/transform bytes without model dependencies; `preflight` checks frozen sources and cached model files **without loading weights**. Each run must present the exact preflight JSON and a **separately committed independent GO** binding the runner SHA-256, protocol SHA-256 and receipt SHA-256. One exclusive output directory per model/attempt; preserve failures and missing arms. Stop before each forward and after each record if elapsed model-process time exceeds **1,800 s**, process peak RSS exceeds **4 GiB**, or JSONL output exceeds **32 MiB**. These are **between-forward** guards; a single blocked forward is not preempted. A reviewer should HOLD live execution if an external watchdog is needed for the host. Use AC power and an open lid on the Mac; record host/power state and UTC/monotonic timestamps in the eventual launcher. An observed sleep/thermal transition invalidates the attempt; do not silently retry. Source-only validation must not be described as a live resource or model parity test.

Report per-case rows and failures, not a success rate from 20 correlated arms. A difference at processor/hidden state without a complete transcript change is representation sensitivity. A complete transcript change is an ASR robustness observation, not yet a security-property violation. The next causal step would patch a predeclared state and show target-specific rescue versus equal-norm random controls; a later security step would require an unmodified assistant and consequential behavior on attacker-suppliable, human-intelligible audio.
