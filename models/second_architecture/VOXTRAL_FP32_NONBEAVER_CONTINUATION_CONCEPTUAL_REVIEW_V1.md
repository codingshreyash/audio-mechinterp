## Scope and implementation constraints

The protocol is suitably narrow for continuation: it keeps the original four-context reservation, fixes `_02` then `_03` as the only unstarted slots, bans retry and replacement, preserves the original numerical `runner.run_context` function and its V1 result/freeze binding, requires a new reviewed gate and small worker entrypoint, and binds new continuation receipts to an external freeze. Its exception applies only to hash-identified `_01` bytes and leaves both five-second timing checks mandatory for `_00`, `_02`, and `_03`. It requires saved-data re-audits, exact prior command/count/cap/source/sidecar/byte checks, strict UTC ordering, host stability before each new launch, post-slot power-log checks, and inclusion of failed or invalid slots in the four-context denominator. It explicitly keeps the original monotonic model-work numbers and discloses the UTC discrepancies; it must not silently add or subtract a presumed sleep interval.

**Resolve this wording in the V2 implementation and source review:** V1 `verify_worker_start` itself writes the exclusive `worker_claim.json`. The protocol's phrase “call V2 `verify_worker_start` exactly once, create the exclusive no-retry claim, then call” must mean one atomic claim operation, owned by V2 admission; the shim must not write or overwrite a second claim. Verify the claim exists before `runner.run_context` and that duplicate calls fail. This is an implementation condition, not grounds to broaden the experiment.

The 27-file manifest, two large local sidecars, and both saved-data audits require a separate independent evidence review before a continuation freeze, as the protocol says. This review recomputed the source/evidence-file hashes, clock gaps, power-log extraction, and absence of unstarted directories; it did not rehash both large sidecars or rerun the CPU auditor. A V2 source review and an independent external-freeze review are still required before any `_02` model load. If clamshell, external power, recent thermal state, or clock integrity cannot be verified, hold the slot. Even after a successful four-context run, these are local-linearity measurements, not a proven security exploit, held-out lens, or audio-specific mechanism.
