# Voxtral corpus_v1 follow-up: frozen CPU index and fit-only gate

**Design and CPU metadata only, 18 November 2026. No Voxtral or Qwen answer inference.** This is a bounded first implementation of the broader [held-out Voxtral proposal](NEXT_PHASE_VOXTRAL_HELDOUT_PLAN.md). The existing [Piper](DECOMPOSITION_FINDINGS_V1.md) and [Kokoro Sarah](VOXTRAL_KOKORO_INDEPENDENT_REVIEW.md) results use one Red/Blue fit pair; the new [corpus](../../eval/audio_jlens/corpus_v1/README.md) has 48 different lexical pairs and two different synthetic voices, Piper Amy and Kokoro Bella. It shares stimuli with the prospective Qwen study, so positive results would be cross-model transfer on a shared corpus, not independent stimulus replication. No speaker here is a human or a held-out speaker family. The already-opened Red/Blue material cannot enter the new development or test sets.

## Frozen CPU index

The builder [voxtral_corpus_v1_index.py](voxtral_corpus_v1_index.py) reads the fixed 192-pair/384-WAV corpus manifest at SHA-256 `adf8cd02d24a43ef576bcb993dc54bd2527440a62798e12fc788def3c063971f`. It verifies all WAV/PCM SHA-256 values and outside-slot PCM equality. It loads only the processor/tokenizer from the pinned `mistralai/Voxtral-Mini-3B-2507@3060fe34b35ba5d44202ce9ff3c097642914f8f3` local snapshot; it never loads model weights. For each clip it freezes four literal answer surfaces—lowercase and initial capital, with and without one leading space—as token-ID sequences including EOS. These are candidate scoring surfaces, not observed model outputs. The primary generated-answer criterion below is stricter than this likelihood surface set.

The index maps each word slot to **four equal-duration word bins**, one equally long pre-bin, and one equally long post-bin. It saves sample bounds, nominal mel frames, direct conv-receptive encoder rows, and direct pre-attention projector rows. Frame mapping uses the pinned 400-sample centered STFT, 160-sample hop, two convolutions, and grouping of four encoder rows per projector row. These rows are an input-support map only; Voxtral's bidirectional audio encoder can mix information across them. The builder refuses an empty bin, a pre/post bin outside the clip, or a word pair with unequal PCM outside the slot. It records all fit, development, and locked-test metadata without running any candidate model. It does **not** consult the independent ASR audit or any Qwen answer to choose cases.

The exact Voxtral user prompt for any later run is: `Answer the question in the audio with exactly one word. No explanation or punctuation.` Use the official audio-instruct user-message content with the WAV and that text, **no system prompt**, greedy decoding, `max_new_tokens=32`, and EOS ID 2. Record prompt token IDs and audio placeholder count at runtime; stop if matched pair token IDs or placeholder counts differ. The text-only comparison uses the frozen `spoken_script` as user text followed by the same instruction; label it a modality control, not an identical serialized prompt. The processor-only index does not assert a model answer.

## Bounded fit-only decision sequence

1. **Natural capability gate.** Select the lexicographically first `map_fit` pair ID in each of the four categories, independent of audio or answer outcomes. This yields **4 fit pairs × 2 voices × 2 fit templates × 2 words = 32 natural clips**. Generate each once under the frozen prompt. Record raw suffix IDs, full decoded text, EOS, strict one-word match after surrounding whitespace removal and casefolding, and failures. Do not repair a word, substitute a voice, or pick the better template. Proceed only if at least **24/32** complete exact answers pass and each voice reaches **12/16**. This is a method feasibility gate, not evidence of a general mechanism. The independent ASR screen is descriptive; it does not alter denominators.
2. **Frontend factor check on fit only.** For the same four fit pairs and both voices, use the lexicographically first fit template per pair: **8 matched pair records**. Independently reproduce the pinned Whisper raw log-mel and native normalized features with maximum error ≤1e-6. Require shared-max normalization to make off-word/padding features equal to ≤1e-6 where raw PCM is identical outside the word support. Run the predeclared six native/word-outside/padding feature conditions only if **all eight records' natural endpoints** pass; otherwise stop this stage and report every natural failure, without choosing a smaller subset. Save all complete answers/EOS and full-sequence alias log-likelihood margins. Feature hybrids are off-manifold; a changed answer proves an effect of the constructed tensor, not of a naturally spoken clip.
3. **Internal causal gate on those same eight fit records.** If the capability and frontend gates pass, patch one direction at a time at **projector output** and **post-block audio-encoder layer 31**, with each site evaluated separately. For both directions, compare full-word-bin donor patch, same-source sham, equal-duration and Frobenius-norm-matched pre/post donor edits, and padding-row edit. Use `α=1` for full generated-answer/EOS results, plus `α={0,.01,.025,.05}` for complete-answer margin sensitivity; save source/donor shape and hook-call count. This is at most **16 directions × 2 sites × 5 full-answer conditions = 160 patched generations**, plus the 32 clean capability generations and 48 feature-condition generations. The four small-alpha score checks and candidate-alias teacher-forced passes add cost; benchmark one fit pair before the rest. Stop on model instability, nonfinite score/gradient, missing EOS, changed no-op generation, or MPS driver allocation over **30 GiB**. No cloud GPU. A post-attention pre/post row can carry word information, so controls are comparative rather than guaranteed nulls.

The causal gate asks whether a **complete generated answer** changes to the donor word with normal EOS, while shams and comparators do not. Log-likelihood movement alone is secondary. A predeclared directional count over all 16 fit directions and per-voice counts prevents a few successes from becoming a broad claim. Do not fit a reusable transport or run a large Jacobian scan in this bounded stage. The earlier broad proposal's rank-16 corpus fit and full six-bin held-out assay require a separate measured FP32 backward memory/runtime gate; the BF16 ~9.93 GiB generation peak does not establish FP32 feasibility.

## Split firewall and interpretation

Development (12 pairs) and locked test (12 different pairs) are **indexed but unopened for Voxtral inference** in this stage. No choice of fit pilot cases, hook sites, prompt, aliases, control scales, or thresholds may use their candidate outcomes. If fit-only feasibility succeeds, freeze a new executable evaluation protocol, resource estimate, and any repairs **before** running development; run locked test once only after the frozen development gate passes. Report all-planned directions as the primary denominator, with clean-eligible results supplemental. Do not replace misheard clips, retune the prompt using test words, or promote fit failures out of the denominator. This first stage can establish a causal route for a lexical answer; it cannot establish a security violation, an audio-only bypass, or a human-voice effect. A later security assay needs the same transcript, explicit authorization policy, inert tools, and a wrong complete decision/action.
