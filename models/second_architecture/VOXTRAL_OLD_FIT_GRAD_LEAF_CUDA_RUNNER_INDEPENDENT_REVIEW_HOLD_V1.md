## Blocking source-contract gaps

1. **A claimed input-preflight failure leaves no worker error receipt.** `run_case` performs archived beaver load/hash checking or waterfall WAV/processor checking at lines 456–460, and its 30 GiB disk check at line 461, before it creates the attempt directory at line 463 and enters the exception handler at line 505. The launch gate already made the no-retry worker claim before calling `run_case`. Any such exception therefore leaves no `error.json`, contrary to the result schema's “On any worker exception” rule. The independent CPU negative test patches the archived-source check to fail and confirms that `error.json` is absent. Put the claimed attempt directory/progress creation and a receipt-capable exception boundary before input preflight, while keeping all checks before weight load; or explicitly change and independently review the schema/launcher contract to provide an equivalent durable failure receipt.
2. **A saved LM terminal tensor can be nonfinite without the worker rejecting it.** `language_hooks` delegates to `replay._language_stages`, which checks output rank, batch, width, and dtype but no finiteness. `full_forward` and `direct_forward` save `lm_terminal` vectors by slicing and `cpu()` without `checked(...)` (runner lines 269 and 320). The V1 protocol requires shapes and finiteness at each captured boundary. A CPU negative test injects a NaN into the LM0 capture while leaving model output finite; the worker returns a completed full-call record. The later independent auditor should reject such a sidecar, but the worker itself currently does not fulfill its capture-validation obligation. Validate each captured stage's exact expected shape and finiteness before saving the call in both paths.

The two independent negative tests in `test_voxtral_old_fit_grad_leaf_cuda_runner_independent_review_v1.py` intentionally fail against `5663b94` (two failures, no errors). They should pass after source correction. No CUDA result, pattern label, security conclusion, or permission to load weights follows from this review. **HOLD runner source and executable freeze** until the gaps are fixed and independently re-reviewed with the changed source/test hashes.
