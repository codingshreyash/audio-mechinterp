# Independent rereview of VoiceChat adapter binding fix `0adea31`

**Verdict: the specific signed-receipt blocker in review `536ba98` is closed at source level. The complete VoiceChat calendar assay remains gated on v2 human QA and official-sample identity tests.** No model, cloud, or real calendar call was used.

The adapter now reads an exact QA receipt file, hashes its bytes, requires a complete fixture-template field set, and checks the submitted WAV hash and case before the first model call. For C with a grant, it requires the grant's `qa_receipt_sha256` to equal the actual receipt file hash and its `controller_id` to equal the receipt's external controller ID. It rechecks receipt bytes before selecting/replaying a first-pass call and after pass 2; it rehashes the WAV after both passes. The dispatcher still verifies the HMAC, WAV/date/`DR19`, and trusted controller identity before returning `authorized_dry_run`; all tool responses remain inert (`executed=false`). A fake grant with a correctly signed but unrelated receipt hash now raises before the fake inference runner is called. Tampering with the receipt after signing also raises before inference. The signed grant authenticates an external controller's decision; this test does not prove the listener heard the request.

The new `load_bound_wav` validates mono 16-kHz PCM16 frame count and the exact terminal-zero count, calls its loader on that same path, and checks WAV and receipt bytes again afterward. The live entry point supplies the pinned official `load_wav_16k_mono` as that loader. It also checks the pinned official helper and template SHA-256 before model work, renders and encodes the prompt with official functions, archives the WAV, receipt, system message, tools, and prompt, and installs a callback that saves the unmodified pass-1 result and per-step codes immediately after pass 1, before parsing or pass 2. It preserves the existing first-position parser, stock-shaped injected response, pass-2 raw record, and nonexecuting counterfactual dispatcher. The helper/template pins still match the published revision.

I ran `test_two_pass_adapter.py` (**8/8**), `test_fixture.py` (**8/8**), and `py_compile`; all passed. The patched adapter SHA-256 is `b2fda40304ae8a15e772bd95ebf1260668d3edb1c5be6ad4938fc62f8d97bea5`.

**Remaining pre-inference limits:** the live entry point is source-only; no official sample parity, stock-versus-adapter identity, TTS-wrapper identity, or final trimmed codec-code identity has been demonstrated. The low-level `run_two_pass` still accepts a caller-supplied tensor; only `run_live_case_from_audited_wav` binds the tensor through the official loader. Its current receipt validation is based on the old fixture template and does not itself enforce the proposed v2 all-12 human QA manifest or 24 ASR observations. The v2 preflight and audited receipt/grant set must be separately implemented, reviewed, and anchored before any calendar-model claim. An invalid HMAC is rejected by the dispatcher at response selection rather than checked before pass 1; it cannot authorize a dry-run but should be preflighted if the run contract requires a valid C grant before model work.
