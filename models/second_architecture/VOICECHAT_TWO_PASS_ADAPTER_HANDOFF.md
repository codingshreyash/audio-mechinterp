# VoiceChat calendar two-pass adapter: source handoff

**18 November 2026. Status:** source implementation and fake-output tests only. No VoiceChat checkpoint was loaded, no fixture WAV was submitted to a model, no tool was executed, and no model result is claimed. Independent source review and external audio QA remain gates before inference.

The adapter is [`voicechat_calendar_fixture_v1/two_pass_adapter.py`](voicechat_calendar_fixture_v1/two_pass_adapter.py). It targets NeMo Speech [`097dfe9e2f55baf653b83035868bdc89849f1b47`](https://github.com/NVIDIA-NeMo/Speech/tree/097dfe9e2f55baf653b83035868bdc89849f1b47). The pinned [official offline helper](https://github.com/NVIDIA-NeMo/Speech/blob/097dfe9e2f55baf653b83035868bdc89849f1b47/nemo/collections/speechlm2/inference/utils/offline_voicechat.py) SHA-256 is `ebde701baec12a014443eac36262a6af7a7a62b3e052f1c4a387db6aaad8da44`; the pinned [function-call template](https://github.com/NVIDIA-NeMo/Speech/blob/097dfe9e2f55baf653b83035868bdc89849f1b47/examples/speechlm2/function_calling/template.jinja) SHA-256 is `8b4f88e9f0052c0dfc19896b9d6a84821f68f84a1049406908e1f664155edcc9`. The default inference runner rejects a loaded helper whose source hash differs. The new `run_live_case_from_audited_wav` entry point verifies both hashes, renders the fixture's prompt with the stock helper, and loads the exact audited WAV itself with the stock loader. The lower-level `run_two_pass` still accepts a caller-supplied signal and must not be used directly for live evidence.

## What the adapter retains

- Pass 1: original `offline_inference(..., decode_audio=False)` result dictionary, predicted and replay function streams where present, text tokens/text, audio fields where present, per-step TTS codes captured by a restored method wrapper, and **every** extracted call position with raw/clean strings and parser diagnostics. It mirrors the stock helper's *first-position* JSON parse for replay; a later position is retained but not promoted if the first is malformed.
- Replay: selected first parsed call, first-position and response steps, stock-cleaned call text and token IDs, call-specific `calendar_stub.dispatch` verdict, exact `<TOOL_RESPONSE>[` + default `json.dumps(response)` + `]</TOOL_RESPONSE>` UTF-8 bytes (as hex), and response token IDs. Only one response is injected even if a first-position JSON array contains multiple calls; that stock-helper limitation is explicit in the trace. A missing/malformed first call causes pass 2 without any injection.
- Pass 2: original `offline_inference(..., decode_audio=True)` result, per-step TTS code capture, every extracted function-call position, and dry-run **counterfactual** verdicts for pass-2 proposals. Nothing from pass 2 is injected into a third pass. The original unspliced `audio` tensor remains in the raw result; the adapter does not call the official writer that removes a call interval.
- Input binding: SHA-256 computed from the submitted WAV before and after the two passes. The adapter reads the exact supplied QA receipt **file bytes**, hashes them, and rejects a C grant whose signed `qa_receipt_sha256` differs before the first model call. It checks the receipt again before choosing a response and after pass 2; `save_trace` retains the exact bytes. The receipt is evidence asserted by an independent reviewer; code cannot prove anyone listened. The external HMAC grant in `calendar_stub.py`, when supplied, is the only route to an authorized C dry-run verdict. The model's `confirmed` argument never grants authority.

`save_trace(trace, new_output_dir)` saves the exact receipt bytes, `pass1_raw.pt`, `pass2_raw.pt`, and `audit.json`. The live entry point uses a mandatory immediate snapshot callback before the next pass and archives the audited WAV, receipt, rendered prompt, tool JSON, and prompt token IDs. Never save the external controller's secret key. Torch `.pt` files should be loaded only from this trusted local run because deserialization can execute code.

## Source checks performed

`python3 -m unittest models.second_architecture.voicechat_calendar_fixture_v1.test_two_pass_adapter -v` passed 8/8 fake-output tests. They cover first-position replay; default JSON wrapper bytes and token IDs; raw pass1/pass2 outputs and TTS-code capture; second-position retention; no-call and malformed-first no-injection paths; multi-call-array disclosure; counterfactual pass-2 cancellation; method restoration; exact WAV and QA-receipt hashes; signed-grant mismatch and post-signing receipt tampering before inference; and the future loader's actual PCM/tail check. These tests do **not** establish real-model identity or audible output.

## Future official-sample and identity gate (not run)

1. **Review and QA first.** Independently review the adapter and pinned source, then QA each final fixture WAV with a completed receipt. Verify `final_wav_sha256`, the exact script, sample format, five seconds of terminal zeros, listener transcript, independent ASR, and C confirmation phrase. An external reviewer signs any C grant; keep its key outside the process logs. Reject any unclear clip before looking at model output.
2. **Official sample environment check.** In a new CUDA environment, pin checkpoint [`443794ea956ef0065f001967ffd00e77f519cb39`](https://huggingface.co/nvidia/NVIDIA-NemotronLabs-VoiceChat-11B/tree/443794ea956ef0065f001967ffd00e77f519cb39), NeMo source above, dependency lock, and helper/template SHA-256. Run the vendor's **unchanged** `offline_voicechat_fc_infer.py` on its published function-call sample and canned random-number response. Record the complete files and hashes. This only checks installation and stock behavior; it does not test the calendar adapter.
3. **Same-input helper parity.** For one QA-approved calendar WAV, render **one exact** system prompt with the pinned template and encode it once. Reset the model to a fresh identical state and RNG state before each arm. Run the adapter first; its selected inert response becomes the `api_response` for the unchanged stock `run_fc_offline_inference` on the **same input tensor and prompt**. Wrap the stock `run_offline_inference` solely to save its pass-1 and pass-2 return dictionaries; do not alter arguments or outputs. Compare pass-1 raw `tokens_text`, `tokens_function_pred`, `tokens_function`, `tokens_len`, all extracted call positions/clean strings, and selected parsed call. Compare exact pass-2 injected call/response token IDs and step tensors, then pass-2 text/function/codec IDs, lengths, and raw unspliced waveform (before either writer). The adapter's call-specific response must equal the stock `api_response` object. Any extra call position remains an audit item, not a different replay choice.
4. **Numerical identity and hook gate.** Fix all generation settings and Python/NumPy/Torch/CUDA RNG states; record backend determinism settings and two stock-versus-stock repeat traces. Require exact discrete IDs, steps, parser objects, codec IDs, and waveform length. Predeclare a waveform maximum absolute error of `1e-4` in float PCM samples; also report exact maximum error and stock repeat variation. If stock repeats vary beyond this bound, stop and diagnose nondeterminism rather than treating a model difference as a finding. Then compare adapter without TTS-code wrapper to its passive wrapper under the same reset conditions; require the same identity criteria. Confirm the wrapper is removed after both passes.
5. **Interpretation gate.** Only after identity passes, run the approved A/B/C/D and literal-date cases. Report pass-labelled raw text, function, codec, and audible outputs separately. The official tool-call example is a two-pass **proposal/replay**; its returned script is not an executed calendar action. A pass-2 call is a new proposal with a counterfactual stub verdict, not an observed third-pass action.

Known source-level limits: the pinned model's `offline_inference` may return `tokens_audio=None` despite generating local `gen_codes`; the wrapper captures the codes at `tts_model.infer_codes_one_step`, but a real-model parity run must verify its shape and order. The adapter does not save head logits or shared hidden states; those are a later read-only hook stage after this output-boundary parity gate. Audio QA is still an external trust assertion. The live entry point binds the tensor to a stock-helper load from the hashed WAV; this has only been source reviewed, not exercised on VoiceChat.
