# Independent source review: VoiceChat calendar fixture `b9340d2`

18 November 2026. Scope: source and local tests only; no audio render, model load, or calendar action. Compared the fixture with [`VOICECHAT_DUAL_HEAD_ASSAY_PROTOCOL.md`](VOICECHAT_DUAL_HEAD_ASSAY_PROTOCOL.md) and the pinned official [function-call template](https://raw.githubusercontent.com/NVIDIA-NeMo/Speech/097dfe9e2f55baf653b83035868bdc89849f1b47/examples/speechlm2/function_calling/template.jinja) and [two-pass helper](https://raw.githubusercontent.com/NVIDIA-NeMo/Speech/097dfe9e2f55baf653b83035868bdc89849f1b47/nemo/collections/speechlm2/inference/utils/offline_voicechat.py).

## Assessment

**The source-only fixture is a sound starting point, but it is not ready to satisfy the protocol's two-pass evidence gate.** `scripts.json` has A/B/C/D plus literal-date A/B controls; the ASCII system message and fake calendar consistently fix 18 November 2026 UTC and target 19 November. `tools.json` offers separate list and cancel tools with the expected `date`, `event_ids`, and model-reported `confirmed` fields. A/B cannot gain a C authorization by setting `confirmed=true`; C is restricted to `DR19` on the target date. `dispatch` only returns dictionaries marked `executed:false`, with no real calendar client. The zero-tail helper removes only terminal zero samples and appends exactly 80,000 zero frames; its local test passes. The planned audio and QA do not yet exist, so no behavioral finding follows from this commit.

## Blockers before a model run or authorization claim

1. **QA approval is self-asserted, not independently authenticated.** [`approved_c_state_from_receipt`](voicechat_calendar_fixture_v1/calendar_stub.py) checks positive booleans, nonempty listener/ASR strings, WAV hash and zero tail. It does not verify that the transcript contains the C phrase, that an actual listener/ASR produced those fields, or that the receipt is signed by a trusted reviewer. The existing [`test_fixture.py`](voicechat_calendar_fixture_v1/test_fixture.py) deliberately grants approval for a WAV made of short pulses by setting those fields to `"test only"`. `dispatch` also accepts a caller-supplied state dictionary without checking a receipt. This is acceptable only if the test controller is itself a trusted authorization source and receipt completion is audited separately; it cannot support a claim that the code independently verified audible confirmation. Fail closed on unreviewed receipts and document who can mint/pass the grant.
2. **The fake calendar is mutable through returned responses.** A successful list returns the original `CALENDAR["events"]` list and event dictionaries; a dry-run cancellation also exposes the original event dictionaries in `would_cancel`. In a fresh process, mutating `dispatch("A", list_call)["response"]["events"][0]["title"]` changed the in-memory `CALENDAR` title. This violates the README's immutable-fixture assumption and can contaminate subsequent trials. Return deep copies or immutable event values, then test that caller mutation leaves later responses unchanged. The file on disk was not changed.
3. **The claimed replay string is not the pinned helper's injected bytes.** [`calendar_stub.py`](voicechat_calendar_fixture_v1/calendar_stub.py) builds `formatted_response` with sorted, compact JSON. The pinned helper instead computes `json.dumps(api_response["response"])` with default spacing and insertion order before making `<TOOL_RESPONSE>[...]</TOOL_RESPONSE>`. A direct comparison returned `False`. The future instrumented helper must record the *actual* string and token IDs it injects, or deliberately accept the stub's preformatted string and mark that change from the stock helper. Do not call the stub string “the exact bytes” injected by the official helper.
4. **The two-pass adapter is still absent.** The stock helper takes `api_response` before pass 1, replays only the first extracted call, and returns only the second result. A call-specific response cannot be selected from this fixture until the protocol's minimally changed helper is implemented and identity-tested. Preserve every raw call position, both pass results, and the selected replay response. This is expected unfinished work for a source-only commit, but blocks model-level conclusions.
5. **Malformed argument behavior differs from the stock parser.** `first_pass_response` returns `None` for a non-JSON string such as `"nonsense"`. The pinned helper converts a string that does not start with `{` to `{}` and still records the parsed call before replay. This difference can mislabel a model-emitted call as “no call.” The adapter should define one parser and record both raw and parsed outcomes, including malformed JSON, instead of mixing these rules.
