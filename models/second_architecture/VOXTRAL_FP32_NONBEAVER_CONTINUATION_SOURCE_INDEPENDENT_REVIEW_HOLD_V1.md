## Blocking findings

1. **A stale or truncated power log can pass host admission.** `_power_events` asks only that *some* timestamped event appears anywhere in `pmset -g log`. `_host_probe` then accepts a log whose sole event is from yesterday because it sees no Sleep/DarkWake/Wake in the last ten minutes. The saved pre-host and post-host validators accept the same stale log. The original positive host test itself supplies a one-day-old event. Consequently, the source does not establish that the ten-minute prelaunch interval or the launch interval was covered by the captured log. Require fail-closed coverage of both intervals from bounded, timestamped log evidence. On this Mac, `pmset -g log` ends with a timestamped “Showing all currently held IOKit power assertions” snapshot near collection time; a corrected check can bind the oldest parseable event before the window and a recent terminal snapshot at/near collection, while still scanning exact tab-delimited Sleep/DarkWake/Wake and thermal events. Test stale/truncated and missing-terminal-snapshot cases.
2. **A new slot's start is not compared to its actual predecessor finish.** `check_prior()` verifies earlier completed slots but returns only model-work seconds. In `launch_context`, both preview and final `_check_new_completed` calls pass `after = start.wall_utc − 1 microsecond`, which makes `_check_new_completed`'s `after < start.wall_utc` condition tautological. A backdated `_02` start before `_01`'s finish is rejected if the actual predecessor finish is passed, but accepted when the launcher's synthetic `after` is passed. The same weakness applies to `_03` and has no later slot to catch it. Preserve and compare the actual preceding `launch_finish.wall_utc` at worker admission and final validation; test a backwards clock/start for both remaining slots. Do not widen the original timing tolerance to fix this.

Four exact CPU-only reproductions in `test_voxtral_fp32_nonbeaver_continuation_source_hold_v1.py` are marked `expectedFailure`: stale log at live preflight, stale saved pre-host log, stale saved post-host log, and a backdated start accepted with the synthetic `after`. They report `Ran 4 tests ... OK (expected failures=4)` against `d5b706b`. Remove those decorators only after the gate rejects the cases. The original nine tests report `Ran 9 tests ... OK`.

I did not find a separate failure in the one-shot worker claim or finish-byte reserve during this review. `v1._write_finish` includes the compressed post-host archive in the combined output accounting before writing `launch_finish.json`; cap failure retains a failed attempt. Source review cannot prove runtime sleep absence, reviewer identity, or post-run model behavior. Keep `_02` and `_03` unstarted until a corrected source commit, independent rereview, new external freeze, freeze review, and a stable externally powered host are all present.
