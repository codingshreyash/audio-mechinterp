**Prospective design only; no new causal inference.** The independently audited [v2 natural pilot](VOXTRAL_FIT_V2_RESULT_INDEPENDENT_REVIEW.md) passed **32/32** strict full-answer+EOS cases and **16/16** first-template natural endpoints. Those are entry gates, not a causal result. Bind the population to [v2 selection](VOXTRAL_FIT_V2_SELECTION.json), SHA-256 `f897d360dbcec9c09f1813f9c070294753fbabc25c6213ba6bdac34b1d79b56b`, not the index's earlier `pilot_fit` flag. Require exactly `animal_08`, `color_05`, `nature_09`, `object_05` × `piper`/`kokoro` × lexicographically first selected FIT template `fit_chosen` × both words: eight matched pair/voice records, 16 directional recipients. Verify each of the 16 selected WAV hashes against the selection and [corpus index](voxtral_corpus_v1_index.json), SHA-256 `bc739cf1f0d265426cc760ddd6a42223554b1097cab6ba87c2c8b81129d1b971`; reject extras/omissions. The second fit template, all other fit words, development, and locked test are outside this assay. Freeze executable code and resource estimate before further Voxtral inference.

## Causal question and bounded claim

Can a small time-indexed audio state **restore** the correct word answer when the target word features are blanked, and does replacing that state in a clean run **remove** the correct answer? Restoration tests *conditional sufficiency*; loss tests *operational necessity under a specified ablation*. Neither proves that the same rows are the only natural route to the answer. Voxtral's bidirectional encoder can spread word information outside nominal word rows, and the blanked feature input is constructed rather than a naturally spoken waveform.

The earlier Piper/Kokoro Red/Blue feature experiment found that native processor features differed across padding because Whisper's clip-wide maximum/floor changed. To prevent that frontend artifact from becoming an apparent hidden-state mechanism, run two distinct checks: (a) independently reconstruct native raw log-mel and shared-max features for each new pair, and (b) make the blank base by replacing only the union of predeclared **direct-overlap word mel frames** in the **recipient's own normalized feature tensor**, leaving every other feature element byte-identical. Copy the recipient's nominal padded-silence column at **mel frame 2999** into each word frame; save the exact feature hashes. This is an off-manifold intervention. A separate word/outside/padding feature-splice matrix follows the [v1 preprocessing protocol](VOXTRAL_PREPROCESSING_DECOMPOSITION_PROTOCOL.md): for the two words A/B in each matched record, run native A, native B, A's word frames with B's every other frame, B's word frames with A's every other frame, A native through the last real-audio mel frame with B's nominal padding, and B native through that frame with A's nominal padding. The word-frame set is the frozen direct-overlap union; nominal padding starts at the first mel frame `i` with `160i−200≥WAV_frames`. Require identical audio-instruct prompt IDs across six conditions and save all feature hashes. The expected word for each cross/padding condition is the word supplying its word frames. Never pool this matrix with hidden-state patches.

Verify natural baseline suffix IDs and processor token IDs against the saved pilot before interpreting any patch. The [pinned model source](https://github.com/huggingface/transformers/blob/18329f1065382e54db698e242cf98bd3f3e5a766/src/transformers/models/voxtral/modeling_voxtral.py) exposes two separate primary sites:

| Site | Hook | Frozen tensor shape | Downstream path |
| --- | --- | --- | --- |
| Last audio encoder block, **post-block and pre-final-layer-norm** | `model.model.audio_tower.layers[31]` **forward output** (tensor, not tuple) | `[1,1500,1280]` for one padded clip | audio final layer norm → 4-row reshape → projector → audio placeholder embedding → LM |
| Audio-to-LM connector, **post-projector** | `model.model.multi_modal_projector` **forward output** | `[375,3072]` | placeholder `masked_scatter` → LM |

Hook each site in an independent run; never patch both together or add their effects. Require exactly one site-hook call on prompt processing and no extra edit during autoregressive continuation. Passive-hook and self-patch generations must reproduce the saved clean/blank baselines exactly, including every suffix token ID. Record tensor dtype, full shape, selected row indices, effective Frobenius norm, hook count, and source/donor activation hashes. A failed shape/parity check invalidates that site's remaining planned rows; retain the failure in the denominator.

Use the [CPU-only frozen mask manifest](VOXTRAL_FIT_V2_CAUSAL_MASKS.json), SHA-256 `a634fc0ab8454b7a82802c56a5365dc90e79f446e4d280cee6321adfead4108e`, produced by [its builder](voxtral_fit_v2_causal_masks.py), SHA-256 `ab8bdcf0374794c32b904cbdee37cba48c87296cef2970fbc0af896e0d21c2fc`. Verify these literal hashes before the model loads and refuse mismatched row maps. For word slot `[s,e)` of full width `w=e−s`, quarter edges are `s+floor(w*k/4)` for `k=0…4`; `pre=[s−w,s)` and `post=[e,e+w)` are each **one full word-slot width**, not one quarter. Every interval is half-open. Assign encoder row `j` with center `320j` and projector row `r` with center `160(8r+3)` iff `lo≤center<hi`. The four word-bin union is main support; six bins are disjoint. Check both word directions have identical row lists, reject empty bins, and serialize the lists per record/site/bin. The index's receptive-overlap rows are a diagnostic cross-check, **not** patch masks. Nominal padding control is the first `N_word` rows whose centers are at least 200 samples beyond the actual WAV end, where `N_word` is that site's word-union row count. The mask manifest also freezes the direct-overlap word mel-frame union: frame `i` is included iff `160i−200<e` and `160i+200>s`. Frame 2999 must be nominal padding for each WAV. After blanking, assert bitwise equality of all feature elements outside that union to the recipient's normalized feature tensor; same-matched directions must share the feature mask. Rows after attention can contain word information outside the nominal word slot.

## Predeclared interventions on each of 16 recipients

First capture four natural/blank source states per matched pair, independently at each site: clean word A, clean word B, blanked word A, blanked word B. Use each state only with its matching prompt token IDs and shape. Save full generated answers and EOS for the 16 clean and 16 blank baselines. The blank base is **eligible for restoration** only when its complete classified answer is not `recipient`; retain all 16 in all-planned counts regardless. A clean case is eligible because the v2 gate is 16/16, subject to replay parity. For each site, run a passive no-edit hook on both clean and blank bases and require exact generated suffix-ID parity with the corresponding unhooked baseline **16/16 per base/site**. Run same-source self patch independently in each arm and require **16/16 per arm/site**. A failed parity check stops causal interpretation at that site and keeps all cases in its planned denominator.

1. **Restoration / conditional sufficiency.** Base = blank recipient features. At one site, replace rows in the **whole word union** with the matching clean recipient's captured rows, leaving the blank source tensor unchanged elsewhere. Success requires an **eligible** blank baseline and a patched complete `recipient` answer; an already-correct blank baseline cannot count as a newly restored answer. Repeat independently on each of the four word bins; a partial-bin score or answer is a time-localization measurement, not proof a phoneme circuit lives there. The content-specific opposite-word clean donor is an additional fixed control: replacing the same word rows with the opposite word's states should be classified as opposite/recipient/other, not silently counted as a restoration.
2. **Loss / operational necessity.** Base = clean recipient features. Replace its whole-word rows with the **matching blank recipient's** captured rows. Success means the previous exact recipient answer changes to a **valid complete** `opposite` or `other` answer. A malformed answer or missing EOS is a separate disruption, not evidence of lexical loss. Repeat the four individual word bins separately. A score decrease without a changed complete answer is secondary sensitivity, not binary loss.
3. **Comparative controls for both arms.** Use same-source self patch (zero edit); full-width pre and post row patches; same-count nominal padding row patch; and a deterministic equal-norm random direction on the same word-row support. In each arm, define `B` as that arm's base source state and `D` as its matching clean (restoration) or blank (loss) donor state. For any support `R`, raw edit is `D[R].float()−B[R].float()`. The word target norm `T` is the Frobenius norm of the **effective BF16 edit** from casting `B[R_word].float()+raw_word` to BF16 and subtracting `B[R_word].float()`. For `R=pre,post,padding`, set one fixed FP32 scale `alpha=T/||raw_R||_F`, cast `(B[R].float()+alpha*raw_R).to(BF16)`, and record the realized effective BF16 norm. No iterative retuning. Require `|realized−T|≤max(0.05*T,1e−6)`. Zero `T`, zero raw control norm, shape mismatch, or norm failure makes that control invalid, not a missing case. Save unscaled norm, alpha, effective edit norm, and edited BF16 tensor hash. The padding rows come only from the frozen mask manifest.

For the random control, derive a CPU seed from the low 63 bits of SHA-256 of UTF-8 `voxtral-v2-causal-v1|{case_id}|{site}|{arm}|random_0`, where `case_id={pair_id}|{engine}|fit_chosen|{recipient_word}` and arm is `restore` or `loss`. With a fresh `torch.Generator(device="cpu")`, draw a row-major FP32 Gaussian tensor of shape `[N_word, hidden_width]`, subtract its scalar mean, scale once to FP32 Frobenius norm `T`, and cast its addition to `B[R_word]` to BF16. Apply the same realized-norm tolerance. Save the seed input, seed integer, unscaled random tensor SHA, and effective edit hash/norm. A zero draw norm or target is invalid. This is a wrong-direction control on the same rows; pre/post/padding are wrong-time controls. All invalids remain among the 16 planned cases. None of these controls is assumed biologically or computationally inert.

Primary endpoint for **every** condition is raw generated suffix IDs, decoded full answer with and without special tokens, terminal EOS, nonterminal special-token check, and categorical result. Apply this precedence: (1) any special token other than exactly one **final** EOS, including early EOS, is `malformed_special`; (2) absent final EOS is `missing_eos`; (3) strip surrounding whitespace from the decoded visible suffix, then empty, multiple whitespace-separated words, punctuation, digits, or other nonalphabetic text is `malformed_surface`; (4) casefold the remaining single alphabetic word and classify `recipient`, `opposite`, or `other`. A case variant is accepted; punctuation is not. Record the unstripped visible string as well. Restoration success is `recipient`; loss success is `opposite` or `other`. Malformed/missing EOS counts as neither success, but is reported as disruption. A one-token or first-token score cannot substitute. Secondary continuous endpoint for **each generated condition** is the preregistered complete initial-capital candidate+EOS contrast in the natural v2 pilot: `C=LL(recipient+EOS)−LL(opposite+EOS)`, using two teacher-forced forwards and the same prompt and patched intervention. Restoration has signed movement `C_patched−C_blank`; loss has `C_clean−C_patched`. If scoring broadens to all four answer aliases, freeze and label that as a **new** score version before inference. Report generated-answer and score results separately. Save native, blank, word/outside, and padding feature hashes; record all 16 planned directional cases and pair/voice breakdowns.

## Resource and decision gates

The full 8-record FIT set has **16 directions × 2 sites × 2 arms × 10 conditions = 640 patched generations** (whole word, four quarters, pre, post, padding, self, random), plus **16** blank unhooked baselines, **48** feature-splice generations (eight records × six conditions), **32** opposite-word content controls (16 directions × two sites), and **64** passive-hook replays (16 directions × two sites × clean/blank). Thus budget **800 complete generations**, not 736. Budget **up to 64 source-capture prompt forwards** (four states × eight records × two sites; shared-site captures may reduce actual calls), and **1600 teacher-forced candidate+EOS forwards** (two per each of the 800 generated conditions). Total conservative forward-like workload is **2464 calls**, plus model loading, preprocessing, activation I/O, and output hashing. If a generation duplicates a baseline, still record it as its own planned condition. The earlier 32-clip pilot's 9.935 GiB peak and 10.1-second generation time do not estimate this workload.

Benchmark the complete **first lexicographic pair/voice record** (`animal_08`/`piper`) through both directions, sites, arms, all ten patch conditions, blank/native and feature conditions, opposite controls, passive parity, captures, and both teacher-forced scores per generated condition. Include model load and fixed setup time once, multiply the measured per-record variable time by eight, add measured fixed setup/I/O once, and require projected total **≤45 minutes** and observed plus projected MPS driver allocation **<30 GiB** before proceeding. If benchmark itself exceeds 45 minutes or either bound fails, stop and report partial FIT-only feasibility with exact completed conditions. Process one model at a time, batch size one, no cloud GPU. Freeze progress and output hashes, refuse overwrites, and never drop cases after inspecting answers.

Prespecified FIT-only interpretation thresholds: clean and blank passive-hook parity must hold in **16/16 directions per base/site**; self-patch parity must hold in **16/16 directions per arm/site**. At least **12/16** blank baselines must be restoration-eligible. Whole-word restoration must yield `recipient` **from an eligible blank** in **≥12/16 all-planned directions per site** and in **≥75% of eligible directions**; whole-word loss must yield a valid `opposite` or `other` in **≥12/16 all-planned directions per site**. These are separate arm/site rates with denominator 16 even when an intervention is invalid, crashes, or yields malformed output; report eligibility and missingness separately.

For a **time-preference** label, assess restoration and loss **separately at each site**. For each of pre, post, padding, and random, the whole-word primary success count must strictly exceed that control's success count over the same **16 planned directions**; ties fail. Also require the whole-word signed `C` movement to strictly exceed that control's signed movement in **≥12/16 paired directions** for every control; exact score ties, nonfinite scores, invalid norm controls, missing outputs, and malformed generated answers count as comparison failures in the 16. Require at least **14/16 valid finite paired score comparisons per control**, or withhold the label irrespective of the nominal ≥12 count. An invalid control also withholds the label; do not shrink any denominator. Report score and primary-answer gates separately. The four word quarters are descriptive, with no best-bin selection or threshold. All thresholds are design criteria, not achieved results. These FIT results can justify a separately frozen development protocol; they are not held-out validation.

## Limits and next boundary

Even a 16/16 natural gate plus successful word-row loss/restoration would demonstrate effects of **constructed feature and activation interventions** on a lexical answer in one model and two synthetic voices. It would not show human perceptual invariance, an attacker-reachable audio perturbation, tool-call integrity failure, or a security vulnerability. The separate Qwen study uses the same source corpus, so shared positive results would transfer across model implementations but not across independent stimuli. Development and locked-test Voxtral answer outputs remain unopened until a new protocol passes fit-only review.
