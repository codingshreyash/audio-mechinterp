# Voxtral Mini 3B: bounded cross-architecture smoke plan

**Decision, 18 November 2026.** Proceed with the Apache-2.0 `mistralai/Voxtral-Mini-3B-2507` checkpoint for the first local, complete-answer replication of the existing spoken-word assay. This avoids the unresolved LFM3-Audio-2B commercial-use license question recorded in [FEASIBILITY.md](FEASIBILITY.md). Voxtral is a **Whisper-family encoder → projector → Llama-family decoder**, rather than Qwen2.5-Omni's Qwen Thinker. It is a useful second implementation, although both remain encoder-to-language-model systems; a positive result would not establish transfer to native speech-output or streaming models. [Official Voxtral card](https://huggingface.co/mistralai/Voxtral-Mini-3B-2507); [official Transformers implementation](https://github.com/huggingface/transformers/blob/18329f1065382e54db698e242cf98bd3f3e5a766/src/transformers/models/voxtral/modeling_voxtral.py).

## Actual path and hook sites in pinned Transformers code

The `VoxtralForConditionalGeneration` object contains `model.model.audio_tower`, `model.model.multi_modal_projector`, and `model.model.language_model` in the [pinned implementation](https://github.com/huggingface/transformers/blob/18329f1065382e54db698e242cf98bd3f3e5a766/src/transformers/models/voxtral/modeling_voxtral.py). Verify these paths with `named_modules()` after loading.

1. **Processor / mel:** `VoxtralProcessor.apply_chat_template` uses the Mistral tokenizer and a Whisper feature extractor. It **pads to the next 30-second chunk**, then splits features into 3,000-frame chunks. The pinned feature config is 16 kHz, 128 mel bins, 400-sample FFT window (25 ms), 160-sample hop (10 ms). A 3–6 second input still exercises one full 30-second audio chunk; record padding and shapes. [Processor source](https://github.com/huggingface/transformers/blob/18329f1065382e54db698e242cf98bd3f3e5a766/src/transformers/models/voxtral/processing_voxtral.py); [pinned preprocessor config](https://huggingface.co/mistralai/Voxtral-Mini-3B-2507/blob/3060fe34b35ba5d44202ce9ff3c097642914f8f3/preprocessor_config.json).
2. **Audio encoder:** hook `model.model.audio_tower.conv1`, `.conv2`, and `.layers[i]` for `i=0..31`, then `.layer_norm`. The second convolution has stride 2; a padded 3,000-frame chunk yields 1,500 encoder rows, width 1,280. The encoder's self-attention is bidirectional and the padding is not masked in this implementation, so an encoder row must **not** be described as containing only its local 20 ms audio. [Pinned model source](https://github.com/huggingface/transformers/blob/18329f1065382e54db698e242cf98bd3f3e5a766/src/transformers/models/voxtral/modeling_voxtral.py); [pinned config](https://huggingface.co/mistralai/Voxtral-Mini-3B-2507/blob/3060fe34b35ba5d44202ce9ff3c097642914f8f3/config.json).
3. **Connector:** `VoxtralModel.get_audio_features()` reshapes adjacent encoder rows from `[1,1500,1280]` into `[375,5120]` and sends them through `model.model.multi_modal_projector` (linear → GELU → linear) to `[375,3072]`. Four 20 ms encoder positions make one *nominal* 80 ms decoder audio token. Hook the projector input and output; save the exact emitted token count rather than assuming it is always 375. [Pinned model source](https://github.com/huggingface/transformers/blob/18329f1065382e54db698e242cf98bd3f3e5a766/src/transformers/models/voxtral/modeling_voxtral.py).
4. **Decoder handoff and answer:** `VoxtralModel.forward()` replaces audio-placeholder embeddings (token ID 24 in this checkpoint) by `masked_scatter` of projected audio, then calls `model.model.language_model`; hook that decoder input and selected `model.model.language_model.layers[i]` (`i=0..29`). Check the placeholder count equals the projected token count, and record raw generated token IDs, decoded full answer, EOS ID 2, and stop reason. A change in a next-token margin alone does not count as a complete-answer effect. [Pinned model source](https://github.com/huggingface/transformers/blob/18329f1065382e54db698e242cf98bd3f3e5a766/src/transformers/models/voxtral/modeling_voxtral.py); [pinned generation config](https://huggingface.co/mistralai/Voxtral-Mini-3B-2507/blob/3060fe34b35ba5d44202ce9ff3c097642914f8f3/generation_config.json).

## Bounded full-answer smoke, after the dependency/weight gate

1. Create an isolated Python 3.12 environment. Download the pinned model/processor with `revision=REV`, selecting only the split safetensors files and index or only the consolidated file. Use `VoxtralForConditionalGeneration.from_pretrained(..., revision=REV, dtype=torch.bfloat16, low_cpu_mem_usage=True)` and `AutoProcessor.from_pretrained(..., revision=REV)`. Try `device_map="mps"` with `attn_implementation="sdpa"` first, batch size 1, `torch.inference_mode()`. The model card demonstrates CUDA, **not MPS**; if MPS fails, log the first operator/error and stop the MPS run. An isolated CPU run can identify model-vs-device issues, but must be labeled separately. [Official Transformers example](https://huggingface.co/mistralai/Voxtral-Mini-3B-2507#transformers-).
2. Use the existing [Piper red/blue WAVs](../../eval/tts/outputs/controlled_pair_v1/) first. The user message should follow the official *audio instruct* format: `[{"role":"user","content":[{"type":"audio","path":WAV_PATH},{"type":"text","text":"Answer the question in the audio with one color word."}]}]`. Use `processor.apply_chat_template(conversation)` and inspect `input_ids`/`input_features` shapes and audio-token count before generating. Voxtral's card says **system prompts are not yet supported**, so do not carry Qwen's system prompt over. The typed controls use the same user role with text: `I said the color red. Which color did I say? Answer with one color word.` and its blue counterpart. This is a matched *task*, not byte-identical prompt framing. [Official audio instruct example and system-prompt note](https://huggingface.co/mistralai/Voxtral-Mini-3B-2507#usage).
3. Run greedy `generate(do_sample=False, max_new_tokens=32)` for Piper red, Piper blue, typed red, typed blue, each twice at most; a second voice is a separate follow-up only if the first four are valid. Decode only the generated suffix. Save WAV SHA-256, manifest SHA-256, exact prompt-token IDs and count, mel tensor shape, projected audio-token count, checkpoint/dependency pins, output IDs, full decoded string, EOS/length stop, wall time, and MPS current/driver allocated memory (plus process RSS). Do not score only `red` vs `blue` logit. Use one output file per run under a new `models/second_architecture/runs/voxtral_smoke_v1/` directory; do not overwrite existing Qwen results.
4. Gate for further mechanism work: red/blue audio and typed controls must each yield the expected **complete** color answer and normal EOS on both repetitions, with total MPS driver allocation staying under 30 GiB. If that gate passes, repeat one clip with passive shape hooks and require the same generated IDs as no hooks. Only then freeze a patch plan that tests word-window encoder and connector changes against self-source sham, equal-size off-word, and norm-matched random controls. The bidirectional encoder and 30-second padding require explicit off-word feature/activation maps before any localization claim.
