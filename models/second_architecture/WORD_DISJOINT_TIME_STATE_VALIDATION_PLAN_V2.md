# Word-disjoint audio state validation: prospective design

19 November 2026. **V2 design amendment; no candidate-model inference until independent V2 review, runner review, and a frozen preflight pass.** V1 received an independent HOLD for an ambiguous transcript parser and an unproven output budget. This version fixes those two rules prospectively. The completed Whisper Tiny and Wav2Vec2 word-window/outside-state assays used two inspected corpus-v1 FIT pairs, `silver`/`teal` and `plate`/`cup`, in Piper Amy and Kokoro Bella. Their result is a local causal property of those ASR checkpoints and recordings, not a security finding. This plan separates a bounded, explicitly exploratory cross-word screen from a new, claim-bearing word and voice transfer study. It does not read locked-test WAVs or change any existing corpus.

## Provenance and the split decision

The [corpus-v1 specification](../../eval/audio_jlens/corpus_v1/SPEC_V1.json) SHA-256 is `4c4cb6beafdd27509a073872f71dea004be686a6d8fafccbae410b8b11d7f265`; its [render manifest](../../eval/audio_jlens/corpus_v1/rendered/manifest.json) SHA-256 is `adf8cd02d24a43ef576bcb993dc54bd2527440a62798e12fc788def3c063971f`. Metadata specifies 24 FIT, 12 development and 12 locked-test whole-word pairs with no word shared across splits. The development recordings are the same two TTS engines as FIT. Its candidate answers were already opened for Qwen Stage A, which failed; the [decision tree](../../eval/audio_jlens/corpus_v1/STAGE_A_OUTCOME_DECISION_TREE.md) explicitly makes this development split exploratory for later versions. Whisper Tiny was also used to screen corpus-v1 intelligibility. Therefore v1 development is a useful **exploratory Wav2Vec2 cross-word check**, but cannot be relabeled a fresh sealed, independent-voice validation. The corpus-v1 locked-test audio and candidate outputs remain sealed.

The [v2 render manifest](../../eval/audio_jlens/corpus_v2/rendered_v2/manifest.json), SHA-256 `15395c7d132eb3f1c1a6b2b7d555146faa83be4ee2b77fba4f481cf70f26761d`, contributes vocabulary **metadata only** to the exclusion check. Its 480-WAV [human/ASR QA gate](../../eval/audio_jlens/corpus_v2/ASR_LISTENING_QA_PROTOCOL_PROSPECTIVE_V1.md) is for a different Qwen study. That unfinished gate does not block source preparation here, and its WAVs are not used as a shortcut for this study.

### Track A: immediate exploratory CPU screen on v1 development

Use **all 12** v1 development pairs, both Piper/Kokoro voices, both word directions, and the prespecified `dev_listen` template only. This is 48 source WAVs and 48 directed comparisons, or **96 directed mode cells** with Wav2Vec2 stock normalization S and shared-outside-statistics counterfactual C. The choice of the lexicographically first development template is fixed here, before this Wav2Vec2 cross-word run; never change it based on a baseline or patch result. The other template stays in the denominator of the existing v1 study, but is outside this explicitly narrower exploratory run. Save every clean full CTC transcript first. At post-encoder-block-11, run the six fixed arms below on every directed mode cell, including cases with incorrect clean ASR: 96 × 6 = **576** patched forwards, plus 96 clean forwards. Record intended-word eligibility separately; no subset silently becomes the full population. Bind hashes and no-weight preflight as in the earlier Wav2Vec2 runner, but version new source and outputs. This run can reveal whether the FIT pattern survives 12 new words while the fresh corpus is rendered and listened to. It remains exploratory even if all outcomes look favorable.

### Track B: new, prospective word and independent-engine corpus

Freeze these eight pairs in this order, with two **unique** words per pair: `banana`/`tomato`, `carrot`/`cookie`, `train`/`plane`, `ferry`/`taxi`, `guitar`/`piano`, `violin`/`trumpet`, `broom`/`brush`, and `button`/`ribbon`. All 16 casefolded words are absent from **all** corpus-v1 split word metadata, including locked-test metadata, its historical-exclusion list, and all corpus-v2 primary-pair metadata. This was checked against the above fixed JSON files without reading locked-test WAVs or candidate outputs. The prospective corpus validator must recompute the three set intersections, 16/16 uniqueness and manifest hashes and fail closed on any change. Do not add replacement words after hearing audio, screening ASR, or observing model behavior.

Use the existing pinned **Piper `en_US-amy-medium`** as a voice anchor and the locally installed macOS **Samantha `en_US`** voice as the independent TTS engine. Samantha is a second *synthetic* voice engine, not a human voice. Both voices say one new fixed English template: prefix `I said`, word, suffix `and then stopped.` The full reference script is `I said {word} and then stopped.` This changes the FIT wording as well as the lexicon; it does not isolate wording as a separate factor. Render eight pairs × two voices × two words = **32 WAVs**, 16 paired cells, 32 directed comparisons for each model. There is no adaptive pair selection and no reserve list.

Render each prefix, suffix and middle word as separate fragments **once per engine**. Pin and save Piper checkpoint/config/package and its existing deterministic synthesis settings. For Samantha, pin the `say` command, selected voice name/language, OS build, conversion command/version and exact raw fragment file hashes; because an OS voice may change across machines, the frozen converted PCM and final WAV hashes, not the voice name alone, define the test. Convert each fragment to mono 16 kHz PCM16 with a pinned, documented CPU recipe. For each pair/voice, set the slot length to the longer processed word fragment and right-pad the shorter fragment with int16 zeros. Assemble `prefix + 1,920 zero samples + padded word slot + 1,920 zero samples + suffix`; never trim, time-stretch or peak-normalize a finished pair independently. Record original-fragment, converted-fragment, final WAV and raw little-endian int16 PCM SHA-256, sample counts and half-open slot `[start,end)`. An independent reader must verify equal pair lengths, exactly equal PCM before `start` and after `end`, and at least one unequal sample within the slot for all 16 pairs. Readback and render may use the WAVs; no candidate ASR or assistant model is loaded at this stage. Freeze renderer, auditor, pair list, template, exact source versions, hashes and no-weight receipt before any candidate-model run.

## Listening and clean-ASR gates

Make a shuffled opaque-ID listening queue for **all 32** new WAVs. Two independent humans each listen to every clip without filenames, word lists, reference text or model output, and enter a full verbatim transcript, the middle word, clear/unclear judgment and confidence. Save initial answers append-only. A third independent listener reviews any disagreement about the word, full transcript or clarity. Require an independently audited **32/32** quality-confirmed receipt before a claim-bearing candidate run: at least two blinded listeners must give the intended word, normalize to the full reference script, and mark the clip clear. A missing or unresolved clip fails this corpus version; report all failures and do not substitute a new word or voice. Human agreement supports this particular synthetic stimulus quality, not universal human intelligibility. A candidate checkpoint's own ASR must **not** serve as its independent input-quality gate. Exploratory Track A need not wait for these 32 listens, but must be labeled exploratory.

After Track B quality GO, run and save **all** clean, unpatched full transcripts and token IDs for Whisper Tiny and Wav2Vec2 before any patch inference. Whisper uses its pinned stock processor, greedy one-beam full generation and audio attention mask; Wav2Vec2 uses the pinned CTC checkpoint and both S/C input modes. Use this one deterministic parser for both human verbatim transcripts and ASR output: `tokens(s) = re.sub(r"[\W_]+", " ", unicodedata.normalize("NFKC", s).casefold()).split()` under the pinned Python version. Unicode letters and digits remain tokens; punctuation, whitespace and underscores only separate tokens. Do not delete an unexpected word or digit. The complete Track B reference token list is exactly `['i', 'said', word, 'and', 'then', 'stopped']`; the intended word is zero-based position 2. A clip passes the human full-script criterion only when at least two **independent blinded reviewers among the first two and, if triggered, the third** each have a full transcript yielding exactly that list, a middle-word field yielding exactly `[word]`, and a clear judgment. The third reviewer is independently blinded to the first two answers and can resolve a one-reviewer disagreement; one passing reviewer alone cannot. Preserve every initial and adjudicating record. The 32/32 rule above still applies. For Track A, derive the complete reference token list mechanically from the frozen `dev_listen` prefix, word and suffix, using this same parser; the word position is the length of the parsed prefix. A directed case has *strict clean-ASR eligibility* for a model/mode only when **both** paired clean transcripts' token lists exactly equal their respective complete reference lists, with no censoring or truncation. Thus the two lists differ only at the fixed word position; no separate fuzzy alignment or timestamp is used. The parser and eligibility tests must cover repeated target word, paired alternative elsewhere, punctuation and whitespace variants, missing template words, empty output, digits, underscore, and Unicode compatibility variants before model outputs are inspected. Save raw transcripts and IDs, the normalized lists and each failure reason. No synonym, homophone or phonetic correction qualifies. Retain every planned case in the overall denominator regardless of eligibility. If any model has too few eligible cells to say anything useful, report that coverage limit rather than choosing another pair. An ASR transcription error on intelligible audio is a model observation, not a reason to change the corpus.

## Frozen sites, regions, controls and outcomes

Pin exact checkpoint revision/weight SHA, package and processor/tokenizer versions, source hashes, CPU float32 `eval()` path, four Torch threads, and no masking beyond the original frozen path. Use the same two independently justified Wav2Vec2 sites as FIT: first feature-projection tuple tensor, and first tensor after encoder block 11. Its nominal direct-acoustic word window from the frozen sample slot `[s,e)` is `[ceil((s−399)/320), floor((e−1)/320)+1)`, clipped only to the actual unpadded frame count `T`; outside region O is all other `[0,T)` rows. Use the same two Whisper sites as FIT: output of encoder block 0 and final encoder LayerNorm consumed by decoder cross-attention. Its word window is `[floor(s/320)−5, ceil(e/320)+5)`, clipped to the active `N=ceil(WAV_frames/320)` rows; O is `[0,N) \ W`. Padded Whisper rows `[N,1500)` stay recipient values in partial patches. The five-row guard is fixed from FIT, not tuned to these outputs. Reject unequal pair time lengths or invalid windows before patching; record the failed planned cell. Never infer a word window from candidate attention, logits, alignments or observed patch success.

For each directed case, mode and site, hold the recipient **waveform/input** fixed and run exactly six arms: `self` (recipient state), `W` (donor W, recipient O), `O` (recipient W, donor O), `full` (all active donor state), `random_W` and `random_O` (independent seeded Gaussian edits in the named region, each matched in whole-region L2 norm to that natural donor-minus-recipient edit). Draw one vector over the complete region, including O left then O right, use separately derived seeds per case/model/mode/site/arm, and store seed, natural/realized norms and edit hash. Keep every other row recipient-identical. A zero/nonfinite norm or failure to reconstruct the patch is a failed arm, never an invitation to drop it. All arms must be recorded even when a control fails. `self` must reproduce the recipient baseline's full logits/IDs (Wav2Vec2) or generated IDs (Whisper); `full` must reproduce donor baseline outputs. Any control failure puts that site/case on **HOLD for mechanism interpretation** while preserving its row in the planned denominator. Record full token IDs and raw and normalized **complete transcripts** for every arm, including empty, truncated and collateral outputs.

Track B's planned matrix is Wav2Vec2 **64 directed mode cells × two sites × six arms = 768 patched forwards**, plus 64 clean model/mode forwards; Whisper **32 directed cells × two sites × six arms = 384 complete decodes**, plus 32 clean decodes. The two Wav2Vec2 modes reuse the same WAVs and are correlated, as are opposite directions, sites and arms. Primary per-model/site summaries are (a) all-planned donor-exact whole-transcript transfer for W versus O, (b) strictly eligible *intended-word-only* transfer, (c) recipient-transcript preservation in O, (d) self/full control pass rates, and (e) random-arm collateral and donor-word rates. Report raw numerator/denominator by word pair and voice, then aggregate; do not treat 768 or 384 arm rows as independent samples or call any successful patch an attacker-reachable exploit. A W-positive/O-negative pattern establishes relative sufficiency under these exact interventions. It does not show unique word storage, absence of information in O, or a security-property violation. Different W/O widths and natural edit magnitudes remain confounds even with matched-norm random controls.

## Operational bounds and independent review

Run each track/model in a separate CPU-only process, one model resident at a time, with **four Torch threads, 30-minute wall time, 4-GiB peak process RSS and 512-MiB new-output cap**. Before any candidate forward, the no-weight preflight enumerates every planned clean case and arm, reads WAV frame counts, derives maximum state and logit shapes from pinned model configs and fixed generation limits, and writes a worst-case byte ledger. It must fail closed if the sum of the following file bounds, **32 MiB for JSON/JSONL and metadata**, and **64 MiB contingency** exceeds 512 MiB. Bound `.npy` files by payload bytes plus 256 bytes per file for header overhead; include all inventory and audit files. Track B Wav2Vec2 retains at most one input array, **two clean state tensors and one complete clean CTC-logit tensor per clean model/mode input** (64 inputs), and **one complete CTC-logit tensor per arm** (768 arms). Track A has 96 clean inputs and 576 arms, with only its frozen post-block-11 clean state per input. Track B Whisper retains one mel array and **two clean state tensors per clean input** (32 inputs), plus clean and patched generated token IDs, complete decoded strings, and bounded scalar scores; **no full step-by-vocabulary score matrices**. The Track B upper bound for Wav2Vec2 is `64*(input_bytes+2*T*H*4+T*V*4)+768*(T*V*4)` plus per-file headers, using the maximum derived `T`, hidden width `H` and CTC vocabulary `V`; the analogous Track A formula uses 96, one state and 576. Whisper's bound is `32*(mel_bytes+2*1500*H*4)` plus the bounded IDs/string/score ledger. Save **no patched full-state sidecars**: each arm records its donor/recipient clean-state hashes, exact word/outside indices, seed, natural and realized L2 norms, and a SHA-256 hash of the constructed patched tensor. A separate auditor must reconstruct that tensor from the clean state sidecars and recipe, compare hashes and observed output IDs/logits, and account for every arm. Check actual new bytes, time and RSS before/after each forward and write; stop with an append-only failure row if a bound is reached. A partial run is never a completed matrix. Track A can run while Track B source/render/listening work continues. The host's prior thermal sleep and finite battery make the CPU-only cap substantive; no overnight GPU or remote instance is needed for this plan.

Before **either** candidate inference, request independent review of this design and its specific runner/auditor implementation, fake-model tests, complete-case enumerator, hash-bound no-weight preflight and control semantics; commit a reviewed freeze receipt first. Track B additionally requires the audited 32/32 listening GO. After each run, a separate saved-data auditor must rehash every WAV/state/logit/output file, independently reconstruct pair windows and all six edits, re-decode all saved complete outputs, account for every planned case and control, and reject missing/duplicate/partial records. Publish negative outcomes and QA failures as readily as positive ones. A later speech-assistant security claim would need a separate, attacker-reachable input and consequential action or disclosure test, with the audio-to-action pipeline traced and a specified harness.
