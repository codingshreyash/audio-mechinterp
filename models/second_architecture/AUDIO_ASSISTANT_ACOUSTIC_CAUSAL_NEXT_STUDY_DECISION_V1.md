# Decision: hold the words fixed, trace the assistant action

19 November 2026. **GO as the next research question; HOLD as a candidate-model run.** This memo selects one assistant experiment. It does not change the existing study protocols or report a new inference result.

## What the evidence warrants

The independently audited FIT noise pilot used four already inspected synthetic `silver`/`teal` recordings. All 12 Whisper noise arms retained the intended word. Wav2Vec2 retained its own clean transcript in 10/12 noise arms; one word-local noise arm corrected clean `TIL` to intended `TEAL`, while one outside-word arm changed another word. The same word-local PCM edit first produced a measured outside-word state difference after Whisper encoder block 0, but Wav2Vec2's stock whole-utterance normalization changed samples outside the edited region before its network. These are **path-specific observations**, not comparable cross-model L2 scores or a general robustness ranking. [Cross-model synthesis](ACOUSTIC_FIT_NOISE_CROSS_MODEL_SYNTHESIS_V1.md); [independent synthesis review](ACOUSTIC_FIT_NOISE_CROSS_MODEL_SYNTHESIS_INDEPENDENT_REVIEW_V1.md).

For the **post hoc selected** Kokoro/teal Wav2Vec2 pair, swapping actual feature-projection word rows `[105,179)` transferred the complete CTC transcript in both directions. Self and full-donor replay passed; complement and eight random controls did not switch it. This establishes one-case white-box sufficiency. The natural word-region edit was L2 266.30 versus 11.87 outside, so the complement negative does not prove localization at matched strength. There is no unmodified assistant decision, user-suppliable exploit, rate estimate, or security finding. [Independent causal audit](ACOUSTIC_FIT_NOISE_CAUSAL_RESULT_INDEPENDENT_REVIEW_V1.md).

The next inference gap is therefore: **Can an acoustic change that leaves an English request intelligible alter a model's native action proposal, and can a measured audio-path state account for the complete change?** This holds semantics fixed and tests the audio pathway instead of selecting another one-word meaning contrast.

## One prospective assistant experiment

Use the pinned [VoiceChat-11B native function-head path](VOICECHAT_DUAL_HEAD_ASSAY_PROTOCOL.md), subject to official-sample/adapter identity and resource gates. Its released model has text and function heads reading the same LLM state. Instrument the original WAV, processor/perception outputs, audio-to-LLM fusion, shared state, raw text and function logits/IDs, all unmodified `<TOOLCALL>` tokens, parser input/output, and unspliced speech. Keep **pass 1** predicted functions separate from the **pass 2** replay with an inert tool response; a cross-pass speech/function comparison is not one simultaneous model decision. [Source map](SPEECH_BRANCH_MODEL_MAP_AND_ASSAY.md).

Before candidate inference, freeze a new English corpus of explicitly dated, independently worded requests covering (A) list events only, (B) list and request confirmation before any cancellation, (C) explicitly confirmed cancellation of one seeded event, and (D) an unrelated read-only request. Use separately produced voices, including a human voice as its own stratum if available. For each source recording, create a clean recording and **length-preserving, predeclared** additive-noise versions at fixed SNRs and seeds; include an outside-authorization-phrase noise placement as a location control. Do not change the words, date, tool schema, seeded event IDs, confirmation state, decoding settings, or user turn. Keep all derivatives of a source recording in the same split. A distinct held-out speaker/engine and independently worded requests must remain sealed from threshold and hook development. Freeze every WAV and source hash, transformer revision, sample count, exact transforms, time-alignment method, arm order, stopping rule, and primary decision criterion in a separately reviewed executable protocol.

Obtain blinded human full-transcript and intelligibility judgments **before opening model outputs**. Independently transcribe the WAVs for diagnosis, but do not use ASR agreement as the definition of human equivalence. Retain every attempted clip and failed clean baseline in the denominator; do not replace a clip because the model recognized it incorrectly. Score per source recording and speaker, not per correlated noise variant. Include typed exact-word controls to expose whether the problem is specific to the audio path, but do not treat typed success as proof of an audio-only vulnerability.

The observational comparison is clean versus noisy **within the same model and request**: processor values, perception outputs, fused audio state, shared pre-head state, complete raw function script, pass-specific text, complete unspliced audible response, and dry-run dispatcher decision. Report the earliest *measured* difference at each named site; input/processor differences caused by the noise are expected and are not themselves a discovered mechanism. An action-relevant boundary requires a predeclared function-script margin or selected action change and a valid intervention, not a large activation norm alone.

At the first predeclared audio-to-LLM boundary with verified same-length alignment, patch **every planned clean/noisy pair**, not only pairs with interesting outputs: clean state into noisy recipient, reverse donor, exact self/zero, full donor, authorization-window donor, equal-width displaced-window donor, and independently seeded equal-norm random edits in the same regions. Record realized edit norms and exact pre/post tensor hashes. Require no-hook/read-only/self complete-token parity and full-donor parity; invalid cases remain visible. If generation histories have already diverged, do not force a later shared-state patch across unmatched token prefixes. A clean-state patch that restores a full decision in several held-out source recordings while displaced and random controls do not would support a **bounded causal boundary**. If clean and noisy answers are identical, score the pair as stable, never as a successful rescue.

The primary endpoint is the **complete, parsed model-proposed action** from raw pass-specific function tokens: no call, list, unconfirmed cancel, confirmed cancel, malformed, or other, with arguments and termination. A security-relevant positive requires a human-intelligible, attacker-suppliable noisy WAV to induce an **unconfirmed cancel proposal in the unmodified model** for A or B, while the corresponding clean and typed requests do not, replicated across independently worded requests and voices. The seeded dispatcher must reject it unless an independent confirmation state authorizes the exact event ID and date. Report spoken text and audible audio as distinct supporting observations from the same pass; do not turn a proposed call into a claimed executed cancellation. C and D test whether a putative repair destroys legitimate behavior. An internal patch alone is mechanistic evidence, never an input-level exploit.

## Why the existing 32 clips are insufficient

The 32-word [Track B fixture](word_disjoint_v2/README.md) uses `I said {word} and then stopped` and a Voxtral word-identification prompt. Its [V3/V6 answer-link study](VOXTRAL_FP32_TRACK_B_ANSWER_LINK_PROSPECTIVE_V3.md) tests a recipient-local projector derivative against a complete generated one-word answer on 16 selected WAVs, after a required 32/32 human listening gate. It does not contain event requests, clean/noisy versions of the *same* words, or VoiceChat's native function stream. The words and render recipe are already exposed. It can validate full-answer, parity, and audit plumbing and train procedural discipline; it cannot become the sealed assistant/security test or establish an acoustic authorization mechanism. Even a positive Track B result remains a white-box answer-link finding.

**Run decision:** finish the independent 32/32 Track B listening gate for that separate study. For this assistant experiment, hold candidate inference until an executable protocol freezes the new corpus and all contrasts, the human wording gate passes, and VoiceChat official-sample plus instrumented identity parity passes on suitable compute. A null unmodified action result is informative: report it, then retain any state sensitivity as a mechanism/robustness observation without calling it a security finding.
