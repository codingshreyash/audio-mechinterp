# Voxtral FP32 Track B answer-link V5: sequential alias scoring

**Prospective amendment; no model run.** This V5 replaces only the alias-batched scoring, batching diagnostics, scoring-work ledger, and admission/timing language of the [V3 design](VOXTRAL_FP32_TRACK_B_ANSWER_LINK_PROSPECTIVE_V3.md) as corrected by the [V4 erratum](VOXTRAL_FP32_TRACK_B_ANSWER_LINK_PROSPECTIVE_V4_ERRATUM.md). All 16 Track B contexts, 16 WAV hashes, six frozen candidate aliases per class, audio prompt, projector site/word rows, ±0.1 edit schedule, seven complete-generation arms, answer/switch criteria, 30-GiB MPS-driver cap, 2-GiB output cap, 12-GiB free-disk admission, AC/open-lid/power-log/clock checks, no-retry rule, and claim limits remain fixed. The no-weight estimate leaves almost no memory headroom for a six-alias FP32 backward pass; it is an estimate, not a measured out-of-memory result. This amendment chooses one alias per forward before any Track B inference.

## Exact sequential score and derivative

Keep the V3 six-surface alias construction and deduplicate identical token-ID sequences **before model weights load**. Freeze deterministic order within each class: lowercase, initial-capital, uppercase; no leading space then one leading ASCII space; retain the first occurrence of a duplicate. For each unique alias `a` of token length `L_a` **including EOS**, make a singleton teacher-forced forward from the common frozen prompt and audio: input IDs are prompt plus exactly `a[:-1]`, and `logits_to_keep=L_a` exposes only the prompt-last through EOS scoring rows. Sum the `L_a` conditional token log probabilities, including EOS, to obtain `q_a=log P(a|audio,prompt,edit)`. No right-padding, alias batch, or `logits_to_keep=0` is allowed. Require exactly one projector hook call with raw output `[T,3072]`, the expected per-clip `T` audio placeholders, identical prompt/processor hashes, in-range rows, and an exact prepatch source-state hash across all clean alias forwards and the singleton natural capture. Each edited forward applies the same specified edit to every selected row and preserves every other row exactly.

The **estimand is unchanged**: for class `c`, `L_c=logsumexp_{a∈A_c} q_a`, and `S=L_donor−L_recipient`. On clean input only, run one differentiable forward per unique alias with frozen weights and a detached FP32 projector leaf. Compute `g_a=∂q_a/∂H` for that alias, release its graph before the next alias, and save `q_a`, finite-gradient/norm checks, source hash, and the exact selected-row gradient or its losslessly reproducible sidecar. After all aliases, form `G_c=Σ_{a∈A_c} exp(q_a−L_c) g_a`, then `grad_S=G_donor−G_recipient` and `J=Σ_{r∈R} grad_S[r]·d`. Accumulate the logsumexp weights and gradient sum in FP32 or higher precision with a recorded dtype; do not average alias gradients or select the winning alias. Check each clean differentiable `q_a` against the corresponding no-grad **clean** `q_a` within `1e-4`, and keep V3's clean-gradient `S(0)` versus no-grad **zero-hook** `S(0)` within `1e-4`. The unpatched projector source hash must also match across both modes and all aliases. A parity failure invalidates that context's Jacobian comparison and stays in the 16-context denominator. The V3 first-context batched-versus-standalone diagnostic is deleted because no batch remains.

## Fixed workload and admission

Upper-bound **Track B core** work before deduplication: `16×7=112` complete generations; `16×6 scored arms×2 classes×6 aliases=1,152` no-grad singleton score forwards; `16×2 classes×6 aliases=192` clean differentiable score forwards/backwards. Thus the maximum is **1,456 core projector calls**. Capture each natural source state inside its unhooked clean generation. If an independently reviewed runner instead needs up to 16 separate source-capture forwards, its no-weight ledger and old-FIT resource pilot must explicitly include and time that call class before Track B; no unbudgeted capture is allowed. Record actual deduplicated alias counts and every planned/attempted/missing call; dedup changes the realized call count, not the 16-context denominator. At most two old-FIT clean/zero generations remain as plumbing controls. No batched-alias diagnostic forwards are reserved. This higher forward count supersedes V3's 336-call core estimate; V3's 240-second per-context and 3,840-second cumulative model-work ceilings remain hard caps, not runtime predictions.

The independently audited **32/32 Track B human-listening GO and its bound receipt must precede every model weight load under this V5 protocol**, including the old-FIT plumbing/resource pilot; no model-only QA exception exists. Source implementation and a no-weight preflight may be prepared beforehand. After QA and independent runner review, but before **any Track B model answer or score**, allow exactly one fixed old-FIT `silver` resource pilot using the V3 prompt/hook. The tokenizer-only preflight selects the longest of the frozen Track B alias token-ID sequences (including EOS; ties by lexicographic token-ID order), hash-binds it, and repeats that **same maximum-length sequence** in every timing score forward. The pilot runs exactly two clean/zero plumbing generations, 72 no-grad singleton score forwards, and 12 clean singleton backward forwards, with one additional source-capture forward only if the reviewed runner cannot capture inside a generation. These scores are timing/parity diagnostics only; they cannot select Track B words, aliases, alphas, thresholds, or a different model path. Preserve the pilot's exact source, shape, memory, elapsed-time, and host receipts.

Before the first Track B weight-dependent input, the frozen auditor must project the **maximum** per-context workload of 7 generations, 72 no-grad scores, 12 backwards, and zero separate source captures if they occur inside clean generation, otherwise one separate capture. Use the pilot's slowest observed time in each call class; include measured model load/setup, the pilot itself, and a 20% contingency. The projected per-context work must be **≤240 seconds** and the projected cumulative pilot-plus-16-context model work **≤3,840 seconds**; otherwise stop and publish feasibility under this version. The pilot's own model work is bounded by 240 seconds and its MPS peak by 30 GiB. Keep V3+V4's 2-GiB output, 12-GiB free disk, AC/open lid, ten-minute clean `pmset` admission, post-run transition check, signed UTC-minus-monotonic gap ≤5 seconds, and no-retry rules for pilot and Track B attempts. An invalid or interrupted pilot is retained and stops this version; do not adjust counts or caps after seeing Track B answers. A later resource redesign requires a new prospective version and independent review.

This amendment does not create a pair-excluded map or a reusable lens. A passing answer-link gate remains a per-recipient local-oracle result from internal projector interventions, with no time-localization or attacker-reachable security claim.
