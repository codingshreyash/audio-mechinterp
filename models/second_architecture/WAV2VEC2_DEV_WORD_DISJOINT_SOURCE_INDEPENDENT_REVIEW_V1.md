## Reproduced source checks

- The enumerator reads only `development` / `dev_listen` manifest rows, the lexicographically first development template. It finds **12 word pairs × two Piper/Kokoro engines = 24 pair/voice cells**, **48 WAVs**, 96 clean model/mode inputs, and **96 directed S/C cells × six arms = 576 patches**. Pair lengths and word slots match. The actual int16 PCM is equal before and after each pair's word slot and differs inside it. The common-stat C inputs are equal outside that slot. The plan correctly labels these already-inspected development words as exploratory.
- The exact NFKC/casefold/Unicode-token parser compares each clean **complete** transcript to its full `dev_listen` reference. The patch outcome retains every planned case and stores raw complete transcript, CTC argmax IDs, normalized tokens, strict eligibility and full donor/recipient relation; errors stay in the denominator. The tests include Unicode compatibility, punctuation, repeated/alternative words, omissions, extra digits and empty output.
- The hook is the first tensor returned after `wav2vec2.encoder.layers[11]`, consistent with the successful FIT hook. Clean captures require one hook and pinned `(1,T,768)` float32 geometry. The patch helper requires one hook, verifies that the live recipient state equals the saved clean state exactly, and replaces only the intended rows while holding the recipient input fixed. `W`, `O`, `self`, `full`, seeded `random_W` and seeded `random_O` are present in each directed cell. The random generator is NumPy PCG64 with one deterministic distinct seed per direction/region; its one draw spans the complete O complement in left-then-right order. Each random edit is matched to its corresponding natural region L2 before float32 rounding; actual realized norm is retained.
- Before any candidate forward, preflight binds pinned checkpoint/dependency/source hashes, all 48 WAV/PCM hashes, the plan, helper, runner and auditor, a full case/direction enumerator, and a worst-case byte ledger. My independent rerun returned **96 clean / 576 patch**, maximum 101,040 waveform frames and 315 CTC frames, and **259,676,160 bytes** total bound versus **536,870,912 bytes** allowed. The ledger includes clean input/state/logits, patched logits, NPY headers, 32 MiB metadata and 64 MiB contingency; it saves no full patched-state sidecars. The runner checks 30 minutes, 4 GiB process RSS and 512 MiB output, with forward headroom and an append-only failure row for a partial run.
- The separate auditor rehashes all referenced sidecars and rejects extras; reconstructs C inputs outside the slot; derives word windows independently from sample indices; reconstructs all six edits from clean states/seeds and compares patch tensor hashes and norms; re-decodes every saved complete CTC logit tensor; checks the full 674-row matrix, controls, output bytes and file population. It does not load model weights. `self` and `full` require exact complete logit equality to recipient and donor baselines. Four no-weight tests passed, as did the full hash-bound preflight. The audit reuses the pinned manifest/processor and runner's case loader to establish source identity, while independently implementing the patch construction and outcome checks.

## Interpretation limits

The model has not yet been run on these development cases. Clean ASR eligibility may be low; the planned denominator remains 96 directed mode cells regardless. A later positive W/O result would show relative sufficiency under internal state edits in one English CTC ASR checkpoint and two synthetic voices; it would not prove unique storage, transfer to independent human speech, attacker reachability, a speech-assistant action, or a security vulnerability. The S/C modes, reverse directions and two TTS voices are correlated and must not be counted as independent replications.
