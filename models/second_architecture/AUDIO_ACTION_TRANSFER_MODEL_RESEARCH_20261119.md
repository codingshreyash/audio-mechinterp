# Audio-language transfer model decision, 19 November 2026

## Decision

**Keep NVIDIA NemotronLabs VoiceChat 11B as the primary native-action model. Use the already working Qwen2.5-Omni-3B and Voxtral Mini 3B paths as smaller, complementary complete-answer models.** This is a model-selection recommendation, not a new model result or authorization to interpret unreviewed outputs. VoiceChat alone among the locally planned candidates has a released, separate function-output channel and an official two-pass tool example. Qwen permits same-checkpoint typed/audio comparison and has a measured local gradient path; Voxtral has an already exercised audio-to-complete-answer intervention and multilingual support. These are different questions, so one model should not stand in for all three. [VoiceChat card](https://huggingface.co/nvidia/NVIDIA-NemotronLabs-VoiceChat-11B), [Qwen card](https://huggingface.co/Qwen/Qwen2.5-Omni-3B), [Voxtral card](https://huggingface.co/mistralai/Voxtral-Mini-3B-2507/blob/3060fe34b35ba5d44202ce9ff3c097642914f8f3/README.md).

## Minimal prospective transfer experiment

1. **Use a complete endpoint first.** For VoiceChat, preserve the frozen V1/V2 same-word clean/noisy calendar study and score raw pass-1 function tokens, first raw function span, and independent inert dispatcher authorization. Record pass-1 text separately. For a quick Mac control, reuse Qwen or Voxtral with a fixed `LIST`, `ASK_CONFIRMATION`, `CANCEL` *text-response* task, report exact generated token sequence and EOS/censoring, and do not call its text a native tool action.
2. **Keep the sound the same while testing state causality.** First show stock/no-hook/read-only/self exact complete-token parity and full-donor complete-endpoint parity. Then donor-patch only predeclared human-marked decision-word rows versus equal-width displaced rows and equal-norm seeded random rows at the audio encoder/projector boundary. Capture raw waveform and preprocess features so model-internal changes can be located relative to the earlier Whisper/Wav2Vec2 padding and normalization mechanisms. A donor state patch is a white-box sufficiency test, not an attacker-supplied audio exploit.
3. **Only then test the input-level security claim.** Frozen clean/noisy WAVs must pass independent blinded wording/intelligibility review before model outputs are opened. A model-origin unconfirmed cancel proposal must repeat on all prescribed locked cases under unchanged prompt, tool schema, date and seed, while the inert dispatcher rejects it. Report every null, malformed call and censored output. A real-world exploit claim would need an actual deployed action path, not the local stub. These gates and the four-locked-source rule are already fixed in [VoiceChat V2](VOICECHAT_ACOUSTIC_ACTION_PROSPECTIVE_V2.md).

## Resource and QA gate

**No model launch is recommended from this memo alone.** The Mac reports 48 GiB physical memory; existing Qwen runs measured roughly 16–21 GiB MPS driver allocation under short tasks, but that is not a guaranteed peak for a new task. A fresh small one-sample resource pilot should record allocator, RSS, duration, model/code/processor hashes and all output tokens before any batch. VoiceChat's 44.4-GB file plus NeMo CUDA/Mamba stack calls for a separately measured H100-class pilot; the existing H100 instance is stopped and should remain so until the prior timing/QA and live-adapter gates are ready. Human timing and two-listener exports are still missing per [local status](../../STATUS.md). Each model should have its own frozen prompt, score, and output semantics; cross-model similarities should be measured rather than presumed.
