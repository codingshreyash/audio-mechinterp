## Root cause

The acoustic pilot calls the earlier `wav2vec2_fit_baseline_stage_capture_v1.model_forward`. That source's `capture_modules` labels `post_block0`, `post_block5`, and `post_block11` as `post_first`; its forward hook takes `result[0]` before validating `(1, frames, 768)`. Under the installed Transformers **5.20.2**, `Wav2Vec2EncoderLayer.forward` returns the hidden-state **tensor** directly (`modeling_wav2vec2.py`, line 609; current file SHA-256 `0c5027789d81a622f72f062eab1ee16566bb8dfb200cb6da0a9ffef06543b287`). Indexing that tensor selects batch item zero and removes the batch dimension, giving the observed `[286,768]`. The first forward reaches validation and fails before any case is saved. `Wav2Vec2FeatureProjection.forward` still returns `(hidden_states, norm_hidden_states)`, so its `post_first` capture remains appropriate.

The earlier successful FIT Wav2Vec2 baseline was frozen under Transformers **5.12.1** and modeling-source SHA-256 `c404982e3a063a5f68ee85809356c8a5ed29ad24c8441eea1d56346a57b5da0c` (`WAV2VEC2_FIT_BASELINE_PREFLIGHT_V1.json`; independent saved audit passed). The acoustic pilot's no-weight preflight instead recorded **5.20.2**. Its preflight hashed the installed module but did not test the return type at each hook site, so source identity alone did not catch this interface change. This does not show that model predictions changed between versions; the failure is in the measurement hook.

Add a fake-module regression that supplies a full batch tensor at a block hook and rejects batch-stripping; include exact hook count and full-state geometry checks.
