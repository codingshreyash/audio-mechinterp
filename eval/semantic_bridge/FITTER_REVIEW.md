# Independent review of the one-prompt terminal Jacobian fit

**Scope, 2026-11-18.** Read-only audit of [the saved checkpoint](artifacts/terminal_interview_piper.pt), [fit report](fit_interview_piper.json), [fitter](../../models/qwen_omni/fit_terminal_jacobian.py), and [fit-only readout runner](evaluate_fit_pilot.py). No model, MPS, development, or test run was made for this review. This is a mathematical and artifact consistency check, not a claim that the lens has decoded an audio concept.

## What derivative was computed

For each target coordinate `j`, the fitter places one cotangent at `target[batch_copy, final_prompt_position, j]` and saves the gradient at `source[batch_copy, final_prompt_position, :]`. Thus `J_layer[j, i] = ∂h_35(last)_j / ∂h_layer(last)_i`, for layers 0 and 17. Separate copies of the same prompt calculate eight rows per backward, and the retained graph is reused across batches. Matrix orientation in the readout, `J @ h`, matches this definition and the [upstream Jacobian Lens transport](../../reproductions/anthropic_jlens/jacobian-lens/jlens/lens.py).

The layer-0 hook returns a detached tensor with identical values and `requires_grad=True`. This cuts **only the graph before layer 0**. For a derivative *with respect to the layer-0 output*, the downstream Jacobian is unchanged: the returned value is the source variable through which later decoder blocks run. It saves the audio-encoder/early-decoder graph. It does **not** measure a derivative with respect to the waveform or an audio-encoder activation. The terminal-position derivative holds earlier source positions fixed, even though the target terminal state also depends on them through attention. A separate audio-source localization method would need a frame/placeholder position policy.

The existing [CPU tests](../../models/qwen_omni/test_terminal_jacobian.py) verify orientation, analytic matrix values, a short final batch, interruption/resume, and the value-preserving graph-start hook on a toy network. They do not test full-model finite differences or BF16 Jacobian accuracy. A small random-coordinate finite-difference/VJP spot check on the pinned model would strengthen this audit before treating the matrix as a precise local linearization.

## Readout path and limits

The runner captures the same terminal post-block source states for typed, Piper, and Kokoro inputs. Its raw baseline is `lm_head(final_norm(h_layer))`. Its uncentered Jacobian baseline is `lm_head(final_norm(J_layer @ h_layer))`. This is the same raw/transport/unembed structure as the upstream lens, with the pinned Thinker's final norm and head. The runner also rebuilds `lm_head(final_norm(h_35))` from the captured last-block state and compares it to the actual final next-token logits. The original 36 fit-only modality records have maximum absolute reconstruction difference **0.03125**, below the runner's 0.125 threshold. That check supports hook placement and final-head routing; it does not validate early-layer readout semantics. BF16 round-tripping and head computation can account for small differences, but no independent error budget was measured.

**Single-prompt intercept issue:** The matrix is a Jacobian around one anchor state, so the local first-order approximation to the final residual for another state is `h_35(anchor) + J @ (h_layer(other) - h_layer(anchor))`. Plain `J @ h_layer(other)` drops the affine intercept and is an upstream-style *uncentered transport*, not the exact local Taylor approximation. The current [runner](evaluate_fit_pilot.py) has added `local_affine_jacobian` and `anchor_constant` controls; these were added after inspecting the first uncentered pilot, so they are exploratory fit-only analyses. At the anchor input, the affine prediction should reproduce `h_35(anchor)` up to inference precision. Improvement over `anchor_constant` is necessary to show that the Jacobian carries input-specific information rather than only a useful anchor prior. A one-prompt local Jacobian still has no evidence of generalization to other voices, items, or positions.

In the **original** [uncentered fit-only score report](fit_pilot_scores.json), none of the 12 items in typed, Piper, or Kokoro had a bridge-label full-vocabulary rank ≤100 under either raw or uncentered Jacobian readout. The best displayed uncentered minimum rank was 119 for a typed item. This describes only the earlier two-method report; it says nothing about the newly added affine or semantic-vocabulary methods until their run completes. No selective bridge finding or causal claim follows from the available readout results.

## One causal patch control if a candidate becomes selective

Choose a candidate source-layer direction **from fit data only**, and freeze it before looking at held-out pairs. For two matched audio inputs that differ in one spoken concept, record terminal layer-17 states `h_A` and `h_B`. In a forward hook on input A, replace only its component along unit direction `d` with B's component: `h_A' = h_A + ((h_B - h_A) · d)d`. Continue the model from the patched state and measure the prespecified next-token label margin **and complete answer**, then reverse A/B. Compare with equal-norm orthogonal directions and a fit-label-shuffled direction; hold the same voice, prompt wrapper, and patch magnitude fixed. A direction is causally useful only if the targeted margin and answer move selectively in the predicted directions beyond those controls. A whole-state swap would be too broad to validate a particular direction, and a rank change alone would not establish answer control.
