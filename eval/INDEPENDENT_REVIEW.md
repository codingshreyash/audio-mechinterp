# Independent review of Whisper pilot and frozen audio extension

Date: 2026-11-17. Reviewer scope: read-only audit of `reproductions/audio_prior/`; no fit, evaluation, or source artifact was modified. This review distinguishes checks I independently recomputed from claims supported only by the producer's JSON and logs.

## Audit verdict

The [`SOURCE_EVAL_MANIFEST.md`](../reproductions/audio_prior/SOURCE_EVAL_MANIFEST.md) accurately labels this as a **local, partial reproduction of a preliminary Whisper Tiny pilot**, with a negative aligned-encoder result. I found no exact fit/evaluation leakage. The evidence establishes that the code and a generated-token rank readout work on this small ASR model. It does not establish audio localization, causal use, speaker generalization, or a security result.

### Limits that matter for interpretation

1. **Same voices and engine across split.** Fit and evaluation are disjoint by clip/text, but both use macOS `say` voices Samantha and Moira at the same rate. This is an utterance holdout, not a speaker, engine, microphone, or natural-speech holdout. The manifest already limits its claims accordingly.
2. **Generated-token target.** The evaluator first generates Whisper's output, then teacher-forces that output and ranks each generated token. This tests whether a readout tracks the model's own transcription trajectory. The final-logit self-check at rank 1 is tautological for greedy generation. WER/CER against references are independently computed but are not the rank target. A rank improvement cannot be read as better recognition of the actual speech.
3. **Model-derived alignment.** The encoder aligned window comes from Whisper token timestamps/cross-attention. It is useful for a diagnostic but cannot independently validate where the sound was encoded. The aligned and remote affine MRRs are nearly equal; the local negative result should be stated as failure of this particular readout, not absence of lexical information from the encoder.
4. **Only six independent evaluation clips.** The 50 scored token positions share six recordings, so token-level uncertainty would overstate precision. Future intervals and model comparisons should resample at the recording/template level.
5. **Comparator is an audit, not a test of novelty or significance.** Exact matches to several published counts are interesting despite different audio bytes, but the ten assertions were chosen after observing the local metrics and mostly read aggregates already produced by the same evaluator. The separate WER/CER recomputation above is a stronger independent check; raw rank recomputation would require saving per-token ranks or logits.

No evidence indicates hidden exact-clip leakage. The evaluator's fingerprint uses **audio bytes plus transcript**; by itself that would miss identical audio with altered reference text, so I also checked raw audio hashes separately. There was no such overlap here.

## Frozen specification for the first audio extension

This is a **task and metric specification**, frozen before recording the new evaluation stimuli or selecting audio-model readout layers. A concrete model/checkpoint, byte-level stimuli manifest, splits, and analysis code must be versioned before fitting candidate maps. Any later change gets a versioned amendment and an untouched held-out test. The tasks adapt the released [Anthropic Jacobian Lens evaluations](https://github.com/anthropics/jacobian-lens/tree/main/data/evaluations) at commit `581d398613e5602a5af361e1c34d3a92ea82ba8e` while adding information that text tokens alone cannot express. The released multihop/association item lists are taken exactly from that commit; their file hashes go into the new manifest before rendering.

### Task set and splits

| Task | Frozen construction | Ground truth and main question |
|---|---|---|
| Semantic bridge | Select 30 multihop and 30 association items from Anthropic's released JSON by sorting `SHA256(item.name)` and taking the first 30 of each. Render the exact prompt with two independently sourced TTS systems; keep matching typed prompts. | Released intermediate concepts. Does an audio path carry the same latent bridge as text, and at which stage does it become readable? |
| Acoustic intent | 20 minimal pairs with identical words but independently validated statement versus question prosody. Record each pair with two speakers and both TTS systems. Keep sentences semantically neutral; no tool access. | Majority label from three listeners blind to the intended label, plus measured pitch contour. Does the audio path preserve prosodic information after any transcript-like bottleneck? |
| Voice identity | 20 same-text pairs spoken by different voices, with 20 same-voice/different-text controls. Use speaker IDs only to construct same/different pairs; reserve speakers absent from fitting for test. | Pairwise same-speaker label. Does identity survive each audio stage independently of lexical content? |
| Channel invariance and nulls | For 20 semantic-bridge recordings, make clean/noisy/reverberant versions at fixed measured SNR and room-impulse settings. Add 20 silence, music, clicks, and non-speech clips of matched duration/loudness. | Intended transcript unchanged for channel variants; no lexical target for nulls. Do apparent concept readouts remain selective under realistic variation, or fire on unsupported audio? |

Split by **item/template and speaker**, never by individual rendering: semantic bridge 36 fit/12 development/12 locked test items; intent and voice pairs 12/4/4 by template; channel variations inherit the source item's split. All versions of a base waveform stay together. The two TTS systems must differ by provider/model family. Reserve at least 12 human-spoken clips across the locked-test tasks; if these are unavailable, report only synthetic-speech results. Record source engine/version, voice, language, raw waveform SHA-256, resampling version, exact transcript, external prosody label, and seed in the manifest. The pilot starts in English to avoid conflating new language coverage with new measurement; a later multilingual extension gets its own locked split.

### Readout scores, without assuming a word-token bottleneck

- **Semantic bridge at language-model residuals:** For an audio-language model with a text head, Anthropic's pass@1/5/10 metric at the final prompt position: per item, minimum full-vocabulary rank of each prespecified intermediate across all prespecified layers, then mean fraction over items. Freeze single-token surface rules before scoring and use them identically for audio and typed input **to the same checkpoint**. Report audio-minus-text paired difference by item and bootstrap confidence intervals over items. Compare Jacobian Lens, raw logit lens, and a layer-matched linear probe. A direct speech-to-speech model without a text head gets task-level output scores and stage-specific acoustic probes instead; do not invent a word-token rank or collapse an encoder frame into one without validating that map.
- **Encoder/projector acoustic information:** For lexical content, train a constrained linear or contrastive readout on fit items, tune only on development, and report locked-test pairwise forced-choice accuracy/AUROC for the prespecified concept versus matched distractor. For prosody, report question/statement AUROC and paired sign accuracy. For speaker, report same/different retrieval AUROC across distinct utterances and unseen test speakers. Estimate uncertainty by bootstrapping base items/speakers, not frames. Include a majority-class and simple acoustic-feature baseline (e.g., pitch statistics for prosody). A detectable signal is an observational result only.
- **Time and stage map:** Freeze a small set of normalized acoustic regions: pre-onset, the independently labeled word/prosody interval, post-interval, and silence; and structural stages that actually exist in each model (audio encoder, connector/projector, LM residual, speech decoder). Publish per-stage and per-region scores and false-positive rates. Align with independent human/forced boundaries or known synthetic timing, not the tested model's own attention or generated token timestamps. If a model lacks a stage, record `not applicable` rather than inventing an equivalent.
- **Channel/null behavior:** On the same semantic items, report clean-to-variant score change and consistency of the full task response. Report false positive concept/intent rates on non-speech clips. Do not interpret an activation as a concept simply because it is high in a colorful UI.

### Causal gate

Only after a readout passes locked-test selectivity, use matched A/B activation patching or a fitted direction edit at the prespecified stage and time window. Compare the **complete** generated text/speech/native action to the unedited output on repeated runs. Include self-patch, wrong-time, wrong-layer, unrelated and norm-matched random edits, reverse-direction patch, and collateral checks (ASR intelligibility and speech quality where relevant). For the bridge task, score whether the final answer changes to the predeclared counterfactual answer; for prosody, score the model's complete punctuation/response act; for speaker, score an appropriate speaker-dependent output or explicitly state that the task is observational. A changed rank or classifier score alone does not pass this gate.

No security claim follows from this battery alone. A later claim must identify the attacker-controlled waveform, protected property, expected authorization behavior, actual end-to-end action, and whether the failure is in the model or the tool runtime.
