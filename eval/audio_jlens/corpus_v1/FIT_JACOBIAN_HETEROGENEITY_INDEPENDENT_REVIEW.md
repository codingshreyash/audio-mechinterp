## Verified design and math

- `selected_cases` chooses exactly 48 `map_fit` FIT contexts. The shared corpus loader opens WAVs only for `fit_pool`; the assay neither loads development/test answer outputs nor sends those audio clips to the model. It does parse the common spec and manifest, which include non-FIT metadata, so a literal claim that no non-FIT metadata is read would overstate the isolation.
- `stage2_case(..., max_coordinates=RANK)` uses one retained graph, exactly 16 VJPs, a grad/no-grad terminal parity check, and frozen stage-1 row geometry. `accumulate_one_vjp` **sums**, rather than averages, source-row gradients within each of six bins, matching the derivative for a uniform edit. The CPU finite-difference test covers this distinction. Each local matrix has `[6,16,width]`.
- The local, frozen corpus-average, and 44-context leave-one-pair-out maps use the same saved donor-minus-recipient six-bin delta and α=.025. Pair exclusion removes all four related contexts; the 12 lexical pairs have equal context counts. The local map is an in-sample oracle diagnostic. The pair-excluded map still uses the basis fitted on all 48 FIT contexts, as the protocol correctly discloses.
- The `1,128` unordered similarity pairs and fixed pair/category/voice strata are complete and correctly counted. Full-terminal and rank-16-projected errors, projected cosine, captured-energy fraction, score MAE, and pair summaries use the planned cases without answer-based filtering. The V2 prediction is a **first-token prefix score**, not a complete-answer or security-effect result.
- The checkpoint is written after each context and resume checks metadata plus exact frozen case-prefix IDs. Smoke uses separate paths. The MPS memory helper records driver allocation after model load and every VJP and raises above 30 GiB; the per-process memory fraction is also set before model load.

## Pre-MPS blockers in this initial draft

1. **Artifact root of trust.** `load_fit_inputs()` compares lens, stage-1, and calibration bytes to hash fields in their mutable reports, but does not pin literal expected SHA-256 values for those inputs and reports. The `.pt` inputs are not git-tracked. A coordinated change to artifact and report could pass all present cross-checks. Pin the actual bytes before MPS: lens `fef84a20f437c37ca665e4026bb3645ccd558e549c7ffe2adff20e6a867ba12c`; stage-1 `8276aca0e24fcaa1397693e0353f9c7ee59190036f3516c0c13ebcbc6208b641`; FIT report `bd5b281dc8eb0e6b2653f496fe0e4901df9cab035b975415dde0c00a686b498e`; calibration raw `76085f0dab8f37b6052024b582ff34533cac3d1c579b27b39a631c536d9cd110`; calibration report `b130aa4af85a807671f537aaabbaddf922bc8f2632d8721c9188c2b6aa8e7bfa`.
2. **Wall-time guarantee.** The 20-minute check occurs between contexts. One 16-VJP context or the final analysis may exceed 20 minutes before the next check. Check the deadline between VJPs and before/during final analysis, or label the limit as a between-context stop rather than a strict invocation cap. Preserve the one-graph 16-VJP method.
