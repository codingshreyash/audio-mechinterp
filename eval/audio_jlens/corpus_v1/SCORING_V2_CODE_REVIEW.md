# Post-fit lexical scoring V2: independent code review

**Verdict:** No blocker before the fit-only MPS comparison. Reviewed commit `58edfd2`. I ran no Qwen inference and opened no development or locked-test answer file or WAV.

`SPEC_V1.json` remains SHA-bound and unchanged. The V2 generator takes exactly the same four lower/title, bare/leading-space strings already listed in `make_spec.py`; it retains their deterministic pinned-tokenizer encodings and appends EOS. I independently rebuilt `SCORING_V2.json` on CPU and obtained equal parsed content. The artifact has four unique variants for each of 96 words, 48 frozen pairs, disjoint paired first-token sets, and matching spec/generator/artifact hashes. The prior fit capability and V1 score hashes are explicitly recorded, making the post-fit adaptation visible.

The runner validates the frozen fit corpus, V2 policy, tokenizer, and V1 score result. It selects the same **48 map-fit contexts** (12 pairs × two voices × two directions, first fit template). Corpus preflight opens all 192 fit WAVs to verify hashes; model forwards use only the 48 selected clips. No development or locked-test audio or model answers are loaded.

The V1 and expanded V2 prefix scores use full-vocabulary-normalized alias log mass at the prompt-last position, with expected-minus-foil orientation. Complete-sequence scoring uses the previously tested causal extension: append all but the last candidate ID, score logits starting at `prompt_len−1`, and sum log probabilities for every answer token **and EOS**. `logsumexp` then combines the four unique complete sequences for each word class without length normalization; expected class minus foil class has the stated orientation. This is a later-decoder behavior score, not a substitute for a prompt-last Jacobian readout.

The runner pins model and Transformers revisions, sets the 30 GiB MPS per-process cap before loading, logs memory after load and each case, and SHA-binds final progress and memory logs. It refuses overwrite and has no resume path. With four variants per word, it plans **nine forwards per context** (one prompt-last plus eight teacher-forced sequences), or 432 forwards total; a midrun failure will leave sidecars that require a fresh output name or deliberate cleanup. Two CPU tests and `--validate-only` passed. Any resulting comparison is fit-informed and fit-only; promotion of V2 to a primary transport metric would need a new frozen protocol and untouched evaluation split.
