# Post-fit lexical scoring adaptation

**Status:** secondary scoring policy drafted after inspecting FIT-POOL outputs and before any Qwen development or locked-test answers. It does not change [SPEC_V1.json](SPEC_V1.json), the frozen V1 one-token score, the WAVs, prompts, splits, or the original fit results.

The fit capability run produced 180/192 strict correct word+EOS answers, but only 87/192 first tokens matched the frozen **single-token** aliases. Among the 48 planned map-fit contexts, 44 were strict correct and only 21 had a V1 alias first token. This is largely a tokenizer-surface issue: `Lion` was generated as `[43,290]` (`L` + `ion`), while the V1 alias list included only single-token forms of `lion`. The 12 incorrect full answers are separate behavior errors, including `deer`→`Dear`, `cyan`→`sand`, and `grove`→`growth`. Source: [fit capability result](fit_pool_capability_v1_results.json), SHA-256 `d0e185bcc778f2fc681a243b59417858ca91f4bb04fa3f715adaea64d2a3dd23`.

The original V1 score remains meaningful within its narrower definition: on the 48 map-fit contexts, expected-word **single-token** alias mass exceeded paired-foil mass **48/48**, including four cases whose complete answer was wrong. Median expected alias mass was 0.264, but 12/48 expected masses were below 0.01. Thus a positive paired log-odds does not mean the model will emit the word. Source: [V1 score result](fit_pool_single_token_score_v1_results.json), SHA-256 `34128f325b1e08818be0369fb91754cedda6331ac42c07439326cb1b09608c45`.

[SCORING_V2.json](SCORING_V2.json) enumerates the tokenizer's **deterministic encoding of the same four strings** that were already declared in [make_spec.py](make_spec.py): bare lower case, bare title case, and each with one leading space. It does not enumerate every possible segmentation, spelling, pronunciation, punctuation, or phrase. For each word, it stores deduplicated first-token IDs and unique complete token sequences followed by EOS. Each of the 48 paired words has disjoint V2 first-token sets. On saved fit generations, these sets contain the first token and full sequence of all **180/180 strict correct** outputs; this fit coverage does not guarantee development/test coverage.

Two **secondary** scores are specified before any V2 model evaluation:

1. **Expanded first-token prefix score:** for each answer pair, `logsumexp(logits[prefix IDs of expected word]) − logsumexp(logits[prefix IDs of foil])` at the prompt-last position. This can be compared to V1 under the same forward. A prefix such as `L` is not itself the word `Lion`; this score can track answer onset without demonstrating a complete answer.
2. **Complete-sequence score:** teacher-force each unique canonical answer-token sequence plus EOS and sum its token log probabilities. For each word class, combine sequence probabilities with `logsumexp` (no length normalization); subtract foil-class log probability. This is a different endpoint requiring later decoder states. The current rank-16 map targets a **prompt-last final residual**, which cannot by itself predict every continuation token or EOS. A complete-sequence score can assess behavior and full donor patches, but it must not be substituted into the map's first-token MAE gate without a new multi-position transport.

The [FIT-only comparison runner](fit_pool_scoring_v2.py) evaluates exactly the same 48 map-fit clips and saves V1, V2 prefix, and V2 complete-sequence scores for each without filtering. Development/test remain sealed. Freeze the runner and artifact before this comparison; any later choice to promote V2 to a primary transport endpoint requires a new versioned protocol and a fresh untouched test, not relabeling the existing V1 result.
