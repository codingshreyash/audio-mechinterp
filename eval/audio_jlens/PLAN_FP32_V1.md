# FP32 audio Jacobian validation after the BF16 fit diagnostic

**Frozen before development or locked-test Jacobian runs, 2026-11-18.** This is a separate precision track for the pinned Qwen2.5-Omni-3B Thinker. The original [BF16 plan](PLAN.md) and all its fit results remain intact. Its fit-only locality gate is unresolved: the late encoder meets the median-error reading but misses a mean-error reading, and BF16 gradient and inference kernels disagree on small changes. The [fit-only precision audit](PRECISION_DIAGNOSTIC_INDEPENDENT_REVIEW.md) shows that FP32 makes the connector derivative locally accurate; a later [microstep fit diagnostic](fit_fp32_microstep_v1_results.json) finds strong local agreement at encoder layer 31 on one Piper direction. These observations choose the FP32 track and its two primary sites. They are **not** development or test evidence.

- Primary source sites: the audio connector output and post-block encoder layer 31. Encoder layer 15 is a named *diagnostic* site; it cannot substitute for a failed primary site after results are seen. The same nominal spoken-word time interval selects each site's own rows. Record all row indices, full source shapes, and outside-word state differences. Check the exact donor/recipient tensor shapes and cached versus uncached prefill states.
- For a recipient audio clip and opposite-word donor, compare the log probabilities of **complete** canonical answers including the end-of-turn token: `S(H)=log P(donor answer + EOS | H)−log P(recipient answer + EOS | H)`. Derive a gradient at the unpatched recipient state and predict each actual FP32-rounded edit with `⟨∇S, Hα−H0⟩`. Measure the same score with a patch at the same site and rows, and separately generate with `do_sample=False`, `use_cache=True`, `max_new_tokens=16`, and the pinned tokenizer's `eos_token_id` as EOS and pad ID. An answer counts as complete only when generation actually ends on EOS within that limit and its decoded generated suffix, after outer whitespace trim and case folding, exactly equals the expected word. Use a no-grad unpatched intercept for no-grad patched scores; report the grad/no-grad intercept gap. Report per-row predicted contributions and their sum. Never count a changed score alone as an answer flip.

## Fixed interventions and comparisons

Use `α={0, 0.005, 0.01, 0.025, 0.05, 0.10, 1.0}` for each primary site and direction. The locality score uses only `α={0.005,0.01,0.025}`; `0.05,0.10` display the onset of curvature and `1.0` tests full donor replacement. Every case must record effective edit norm, predicted and measured score change, full greedy answer, EOS, and hook call count. Alpha zero must reproduce the same score and token IDs. No per-item alpha selection.

At each site, use these controls on all four fit routes and on **both patch directions** for the first phrasing of each category and voice in development/test: development `chosen` for `animal` and `weekday`, test `codeword` for `direction` and `number`, in Piper and Kokoro. This fixes eight directional control cases per split and site. Apply controls at `α=1.0`: self patch; equal-size off-word window; same-row norm-matched random edits with seeds 0, 1, 2; row-shuffled donor edit; and norm-matched off-word edit labeled as a synthetic control. To choose the off-word window, enumerate contiguous source-row windows with the same number of rows as the word window and exclude every overlapping candidate. Prefer a candidate whose rows lie entirely in an attention chunk **disjoint from all chunks touched by word rows**; if none exists, use the lowest-start nonoverlapping window. Within either preference, select the lowest row start. If no nonoverlapping candidate exists, record `ineligible_no_offword_window` and keep the case in the all-planned denominator. The natural off-word patch uses the donor-minus-recipient difference at those off-word rows. The scaled variant multiplies that difference to match the selected word-edit Frobenius norm; if its natural norm is zero, record `ineligible_zero_offword_delta`. For row shuffle, permute only the word-row donor-minus-recipient vectors with NumPy RNG seed 0, identical across reruns. Random controls draw an independent standard-normal tensor per seed at the correct word rows on CPU, normalize it to the word-edit Frobenius norm, then cast to FP32/MPS. Use no candidate resampling or per-case random search. For controls report source rows, natural/scaled edit norm, measured score change, complete answer and EOS. A control that changes the answer limits a word-local causal interpretation. Record effects outside the nominal word rows because attention spreads audio information.

Fit-only norm baseline: independently per primary site, use all four red/blue routes and only `α={0.005,0.01,0.025}`. For effective edit norm `n_i` and donor-oriented measured score change `z_i`, set `β=max(0,Σ n_i z_i / Σ n_i²)`. Predict `β n` on development and test. Record the coefficient, all fit rows, and input hashes in an immutable artifact **before** opening locked test. The other baseline is zero change. Do not calibrate on development or test.

## Order and decision gates

1. Reproduce the four clean complete fit answers in FP32; require EOS. Run the two primary sites in both directions and voices. Inspect fit numerics and controls. Define the site's numerical floor from three repeated alpha-zero contrasts per fit route as `max(1e-4, 5 × maximum absolute departure from that route's repeated-zero mean)`, taking the maximum over the four routes. Stop this FP32 route on a disconnected gradient, failed alpha zero, exceeded 30 GiB cap, fewer than four clean complete fit routes, fewer than four alpha-one donor-answer flips per primary site, or a primary site's fit locality sign agreement below 75% among determinate `α={.005,.01,.025}` effects. If no fit effects exceed the floor, stop as indeterminate. This is a fixed fit stop rule, not a discretionary visual judgment.
2. Freeze the norm coefficients and fit result hashes in an immutable artifact. Then run development once with the fixed code, alpha grid, scoring, and controls. Effects below the frozen site floor are indeterminate for sign, but remain in error metrics and all-planned counts. A primary site clears the locality gate only if, over clean-eligible directional cases and `α={.005,.01,.025}`, its sign matches at least 75% of determinate measured changes **and** its mean absolute error is at most **0.75 × each** of the zero-baseline and frozen norm-baseline mean absolute errors. If no cases are clean-eligible, no effects are determinate, or either comparator has zero mean absolute error, the site cannot pass. Also report median absolute error, median relative error, each case, and failures; neither median nor mean can be silently swapped after the run. Both primary sites must clear this gate to claim an audio-to-answer Jacobian transfer. Report alpha-one donor-answer flip rate separately with all-planned and clean-eligible denominators.
3. If both primary development gates clear, freeze code and outputs in a Git commit, then run the locked test **once**. Apply the identical gate separately at both sites; report category, phrasing and voice, all-planned and clean-eligible denominators, numerical floor exclusions, controls, and complete-answer outcomes. A passed local gate is evidence for a local causal predictor on these tasks, not an Anthropic-style corpus-fitted Jacobian Lens or a security vulnerability.
4. Only after locked-test transfer, consider a reusable corpus-fitted audio-to-terminal transport with more fit data and an anchor-constant baseline. No full-rank lens or security claim follows automatically from this scalar assay.

All deviations, errors, source hashes, and negative results must remain visible. No audio from the locked test may guide code, thresholds, site choice, or prompt changes.
